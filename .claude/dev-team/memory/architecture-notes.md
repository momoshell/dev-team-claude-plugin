- **2026-08-01** — **ADR-003 Amendment 1 (proposed): the completion token is an unguessable per-dispatch nonce**, delivered to the adapter via a mode-0600 file outside the task dir that the adapter reads and unlinks before spawning `claude`; never in the worker's env/argv/kickoff/role body/task dir. Parent re-derives completion from the ladder (fresh schema-valid return) on **every** wake regardless of which token released it — a forged wake buys one wasted loop iteration, never a false completion. Attention channel is orthogonal to the ladder, never completion evidence, **and best-effort by construction** (`signals/` file + ladder carry all guarantees). Rank-2 EXIT sentinel moves to parent-side state and is permanent (no process-exit event in cmux 0.64.20). Status: **ratified 2026-08-01** (1a planning, user-approved) with two riders. **Rider A:** S25b proved `wait-for` latches are consume-once — v2 §7.3's two-phase await loop collapses to a single repeating phase-1. **Rider B (correction):** the EXIT sentinel is unforgeable **by tool calls only** — a `Bash(npm test *)` subprocess reaches `~/.dev-team/state/` with the same uid (G13), so a forged `.exit` (or the new `.gate` counter) is possible; blast radius is bounded to one wasted parent loop because completion is re-derived from the ladder on every wake. Never describe the sentinel as unforgeable.

- **2026-08-01** — **S20 restart-durability (live, post-restart, `boot_id` confirmed a real cmux restart):** `wait-for` tokens are **durable across restart** (a pre-restart latched token released a waiter in 0.03 s afterward) — surprising, opposite of tmux-style in-memory behavior. A moved markdown doc-tab panel did **not** survive (cmux didn't offer to resume it), though the orchestrator's own agent-session pane *did* restore. *Design impact:* the durable token store **reinforces** the ADR-003 completion-nonce + ladder-re-derivation decisions (a stale prior-dispatch token can survive a restart and fire a spurious wake, so completion must never rest on a token alone); and it confirms recovery for dispatcher-mounted panels must be **file-based**, not GUI-session-restore-based (matches ADR-004 fallback + S21). Not a blocker.

- **2026-08-01** — **ADR-013 (ratified 2026-08-01, user-approved at 1a planning): the cmux contract freeze is structural, not advisory.** Roster `allow` lists are **enum-constrained capability tokens** (`returns_write`, `signals_append`, `worktree_write`, `validation_commands`), never permission-rule strings; expansion into rules is an **adapter responsibility** — 1b exposes `expandGrants(agent, tokens, ctx) -> string[]` with `agent` a parameter. Profiles carry no `deny` key, no `tools` key (hoisted to one top-level roster field), `permission_mode` enum-closed to `dontAsk`. **Exactly three profiles — `executor`, `validator`, `judgment` — generated by the rule *one profile per distinct grant-token set*** (`validator` exists because judgment can't run a build and executor could edit the artifact under test). The dispatch record is **parent-side**, has a closed eight-key `env`, and follows a three-state monotone lifecycle (`create` → `bind` → `terminate`, atomic tmp+rename). The completion nonce is structurally unrepresentable in any record. *Stated cost:* the only bespoke-`Bash(...)` channel moves from a human-authored roster to the agent-authored spec `validation_commands` (trust-boundary relocation, bounded by the `CMD_RE` whitelist + `Bash(<c> *)` wrapping). *Named consequences:* (1) fresh-worktree dependency prep is **dispatcher-side before spawn**, never a worker grant, never a reason to widen the token enum; (2) the pre-approved future escape hatch is a structured pattern-restricted prefix-list field, not a rule-string `extra_allow`. *Supersedes:* issue #2's inline roster/record JSON (superseding comment posted on #2). *Why:* hard rules 4/5/6 stop being test-defended config properties — the issue's own draft violated rule 6 three times before anyone edited it. Full decision record: `tasks/cmux-mode/1a-contracts-package.md` (v2.1).
- **2026-08-01** — **Return files are envelopes** (`scripts/cmux/return-envelope.schema.json`): workers write `{schema_version, dispatch_id, slice_id, attempt, role, produced_at, body}`; validation is two-step (envelope, then `body` against the record's `return` — schema for json, `required_sections`/`SECTION_HEADING_RE` for markdown), no `$ref` needed. For markdown the **parent** renders `returns/<stem>.md` after validation and mounts the doc tab on it — no grant covers that file (under the S25f `returns/**` fallback it relocates to `render/<stem>.md`). `coder-return.schema.json` and `handover-spec.schema.json` unmodified. *Why:* the ladder's freshness clause needs a `dispatch_id` inside the return, which `coder-return.schema.json` cannot carry and markdown returns (7 of 12 roles) cannot express. Ratified with 1a.
