## Base architecture decisions (ADR-001–011)

The eleven decisions below are the baseline cmux execution-mode architecture, ratified 2026-08-01 at slice-1a planning. Later amendments live as dated entries in the `## Entries` section above; each ADR below that has been amended carries an `*Amended by:*` pointer to those entries. ADRs are read in isolation — a contradiction between an amended base decision and a later entry elsewhere in this file is a failure mode these pointers guard against.

- **ADR-001 — Execution substrate: custom cmux adapter, not `cmux claude-teams`.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Drive cmux via its CLI/socket behind our own adapter layer. Option A (`cmux claude-teams`) rejected: tmux shim at `~/.cmuxterm/claude-teams-bin/tmux`, gated behind `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, Claude-only, partial tmux verb coverage — cannot carry a roster, a permission model, or a return contract. *Consequence:* the orchestrator composes dispatch records and invokes adapters, never hardcodes Claude Code assumptions into the dispatcher. *Why:* every architecture of the plugin before cmux was tied to the Agent-tool model; adapters un-tie it. Revisit if: claude-teams leaves experimental and grows multi-CLI support. Source: epic #15 design ledger (D1); v1 §4.1 option A rationale, v1 §6.

- **ADR-002 — Filesystem is the data plane; the cmux socket is control plane only.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Specs in as file paths on the launch line; returns as schema-validated files; `wait-for` = doorbell; `read-screen` = diagnostics only; `send` = single-line control text only. Forced by cmux's design (events redact bodies; no payload primitive; TUIs submit on every newline). *Consequence:* structured returns are the data plane's contract in both directions — the orchestrator branches on enums (status, verdict, severity), never on prose; screen-scraping is structurally impossible. *Why:* the asymmetry (agent uploads giant JSON, orchestrator reads one byte at a time from a pane) forced this shape; it turns out to be robust. Source: epic #15 design ledger (D2); v1 §4.2 rationale, v2 §4.5.

- **ADR-003 — Completion is signalled by a four-rank ladder; events trigger rescans, never endings.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. The doorbell is a hierarchy: (0) return-file watch inside `await` — stat + `return-lint` every 3–5 s, co-primary, filesystem-only; (1) `cmux events --name notification.requested` — workspace-scoped rescan trigger, native for Claude inside cmux; (2) adapter `trap … EXIT` writes `logs/<id>.exit` sentinel and signals `wait-for`; (3) Stop hook return-gate with ≤2 block cap and its own counter, writes the blocked return on exhaustion. *Consequence:* the orchestrator's join always unblocks — by a fresh valid return, by an explicit blocked return (written by the agent, the gate, or the adapter), or by a timeout naming the pane and its log; no branch ends in silence. Self-signal dropped (prompt-dependent, deny-beats-allow makes it unreliable). *Why:* (0+1) provide liveness without hooks or socket reach; (2) is the liveness backstop for crashes; (3) enforces the return contract but never owns the signal. Unbounded block loops burn sessions; an interactive TUI never exits by itself. Source: epic #15 design ledger (D3, amended in v2 after review); v2 §4.3 rank definitions, v2.1 §B-2 attribution model. *Amended by:* 2026-08-01 Am.1 (nonce + ladder re-derivation), 2026-08-02 poll-first await, 2026-08-02 '.exit never decides completion', 2026-08-05 be-11-01 errata (the rank-1 doorbell event is `agent.hook.Stop`, not `notification.requested` — live-verified against cmux 0.64.22; see docs/trd-cmux-execution-mode.md's Superseded-since-ratification table).

- **ADR-004 — Role-station panes: the return file is the doc tab.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Judgment roles return markdown, opened with `cmux markdown open` and relocated into the producer's pane with `move-surface --focus false`. One artifact serves three roles: contract return (schema-validated), live progress view (live-reloading on disk), approval surface (rendered doc in the pane). For executors the pane closes on return; for judgment roles the pane collapses to the rendered document — focus-don't-close is the Phase-2 default (collapse-on-close is polish, gated on spike S19). UUIDs only (no positional refs persisted); re-read before acting. Placeholder is lint-invalid by construction. *Consequence:* leads and reviewers see their work live while producing it; the orchestrator never drafts-in-pane; every file is written tmp+rename, never rm-then-recreate. Fallbacks: browser surface tab, then a split pane. *Why:* one artifact instead of three (return + viewer + approval) is cheap; live reload frees the lead from refresh loops. Source: epic #15 design ledger (D7, amended in v2 for UUIDs); v1 §4.4 mechanism, v2 §4.4 amendments, v2.1 §E close-step. *Amended by:* 2026-08-03 parent-render-on-validation, 2026-08-06 collapse-on-close default (S19 passed; verified-sibling precondition — this reverses "focus-don't-close is the Phase-2 default").

- **ADR-005 — Security posture: default socket mode, orchestrator-inside-cmux, allowlist-shaped worker profiles, scoped return grant.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. `cmuxOnly` stays (the only socket mode that makes sense); `allowAll` banned; `cmux identify` preflight enforces the precondition. Worker profiles are allowlist-shaped under `dontAsk` (deny beats allow; only non-prompting mode that cannot stall). One file grant: `Edit(//<abs task-dir>/returns/**)`. Workers denied `Bash(cmux *)` at the tool layer (outside the permission system). No Task tool. Never `--dangerously-skip-permissions` or `bypassPermissions`. For pane dispatches the profile's tool universe and allow/deny rules REPLACE the role's frontmatter wholesale — never merge (frontmatter expresses the Agent-tool model, profiles express the pane model). *Consequence (resolves the latent ADR-004/005 conflict):* the one file a read-only role may write is exactly the file ADR-004 renders — they're the same file. Addendum clause: `cmuxOnly` is containment, not immunity. The socket admits any descendant of the cmux app — which includes every subprocess a worker pane spawns. Third-party code executed by allowed commands (e.g. package scripts under `npm test`) is therefore inside the socket trust boundary, and the worker-level `Bash(cmux *)` deny does not mediate it. What the default mode does buy: the boundary shrinks from the entire user account to what is deliberately run inside cmux. Residual inside-risk is cross-pane typing, screen reading, and driving logged-in browser surfaces within cmux. Operational rule: do not keep high-privilege interactive sessions — SSH to production, sudo'd shells, authenticated admin browser surfaces — in the same cmux instance where worker panes execute untrusted build code. Task workspaces are ephemeral by design; privileged long-lived panes belong outside cmux or at minimum outside any cmux instance running dev-team workers. *Why:* Tier-2 and Tier-3 specs can dispatch untrusted role prompts; permission-based containment is the only available boundary (OS sandboxing deferred). Denying cmux at the tool layer assumes workers never signal — true because the gate and adapter signal instead. Source: epic #15 design ledger (D9, amended in v2 and again in v2.1); v1 §5.4 Roster, v2 §4.6 scoped grant, v2.1 §B-1 profile replacement. *Amended by:* 2026-08-01 D9 amendment (enumerated cmux allow-list, no deny wildcard) and 2026-08-01 Am.1 (uniform --tools, web-tool loss).

- **ADR-006 — `roster.json` is committed; `tasks/` is gitignored by a self-contained ignore file.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. `roster.json` is team configuration like `config.md` — committed. `.claude/dev-team/tasks/` is ephemeral dispatch working data — ignored via `tasks/.gitignore` (`*` + `!.gitignore`), not the repo root `.gitignore` (the plugin commits the sibling `memory/` tree). Task dirs are deleted at ship after memory distillation; `keep_task_artifacts: true` archives instead. Additive optional roster schema fields do not bump `version`. *Consequence:* the roster survives a git clone; task state does not. Every project gets the team-wide roster and may override it locally. *Why:* rosters express policy (who runs what, on which model); tasks express session state (what is happening now). Source: epic #15 design ledger (D2, D6); v1 §5.4 Roster, v1 §5.2 data layout. *Amended by:* 2026-08-01 Am.1 + 2026-08-02 siting rule/Rider D + 2026-08-04 stale-paths warning.

- **ADR-007 — Workflow mode stays on the Workflow tool's agent() dispatch; "never the Agent tool" is scoped to conversational dispatch.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. The Workflow tool's `agent()` primitive cannot be intercepted without rewriting the wave scheduler; workflow mode is the batch lane where visibility is not the point. Conversational dispatch (Tier-1/2/3 task roles) never uses the Agent tool when cmux mode is active. Workflow mode is carved out and remains Agent-tool only. *Consequence:* workflow teams keep their existing behavior; conversational tasks get visible panes. *Why:* workflow is a separate subsystem; intercepting it would require too much machinery for a non-core flow. Carve-out is stated in `references/cmux-dispatch.md` and `commands/team.md`. Source: epic #15 design ledger (D3); v1 §4.1, v1 §9. *Amended by:* 2026-08-03 slice-1d entry (workflow mode stays on the Workflow tool's agent()).

- **ADR-008 — cmux is an environment prerequisite, not a preference.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. `execution_mode: cmux` means preflight failure stops the task with precise remediation; no silent degradation to Agent-tool dispatch. Two values: `cmux` / `agent-tool` (default for anyone without cmux — macOS-only app). Onboard sets `execution_mode: cmux` on a working install; pre-existing projects default to `agent-tool` and must opt in. The plugin treats cmux like git (also a macOS/Linux-only prerequisite). *Consequence:* preflight failure is loud with remediation steps; users know when they are not in cmux mode. Phase 1 spike S8 audits the installed version and gates the entire phase. *Why:* silent fallback created debugging confusion (users think they got cmux when they got Agent-tool); loud failure is cleaner. Source: epic #15 design ledger (D14); v2 §3.5 binding constraint 6, v2 §5.5 preflight. Cross-file pointer: conventions.md's 2026-08-03 entry (execution_mode canonical values cmux|agent-tool, subagent a normalized legacy alias).

- **ADR-009 — Pane system prefixes are byte-stable per role.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Static role file + static per-profile addendum + static worker plugin; per-dispatch variance via env and kickoff only; wave launching (first pane of a role warms the prefix cache; same-role siblings launch after it begins). The model receives expanded absolute literals in the kickoff (spec path, return path, dispatch id) — the kickoff is per-dispatch and sits after the cached prefix. Env vars are for shell-side consumers (adapter, return-gate, gate-mode), which expand them; the model is not a shell consumer. *Consequence:* two dispatches differing only in ids/paths produce byte-identical prompt-file content; cache hit rates stay high; rejects per-dispatch generated `--settings`. *Why:* every dispatch re-computes the session prefix for the model; caching is essential under the July-2026 token budget. D15 made it load-bearing. Source: epic #15 design ledger (D15); v2 §5.9 cache discipline, v2.1 §B-3 kickoff delivery. *Amended by:* 2026-08-01 Am.1 (--append-system-prompt-file exists; single pre-composed role-prompt file per role with role_prompt_sha256) and 2026-08-01 S16 reversal.

- **ADR-010 — Machine-readable verdicts at both ends of the pipe.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Reviewer returns stay markdown for the human surface but carry a fenced `{verdict, findings[]}` block inside the Verdict section — present, parseable as JSON, `verdict` in the set {pass, changes-needed, inconclusive}, every `findings[].severity` in {critical, warning, suggestion}. Shape-validated only; finding quality is never linted. The gate branches on the severity enum (any critical → bounce/escalate; only suggestions → pass with notes; missing/unparseable → inconclusive → re-run scoped to the diff), never on prose interpretation. A majority-verdict rule runs over multiple reviewers' `verdict` values. *Consequence:* the orchestrator's control flow reads the block; prose remains for the human and the doc tab; reviewer quality judgments stay agent-side and are never linted. *Why:* prose is ambiguous (does "needs work" mean bounce or amend?); enums are actionable. The severity-to-ladder mapping is critical ↔ must-fix, warning ↔ should-fix, suggestion ↔ consider. Source: epic #15 design ledger (D17); v2.1 §H verdict-block definition, §R2-3 gate branching. *Amended by:* 2026-08-03 required_sections matching semantics and the still-open extractSection shadowing exposure noted 2026-08-04.

- **ADR-011 — One shared noise-glob definition applied at read points only.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. `scripts/noise-globs.json` holds a single definition of paths to filter (lockfiles, vendored, minified/generated, build output); `config.md` per-project override. Applied at reviewer bundle, cmux diff view, and handover-spec.md guidance — the three places humans read. Never at the git scope-compliance check (which stays explicitly unfiltered); never to a files_in_scope path (a dependency-bump task's only meaningful diff IS the lockfile). Every filtered bundle names what it excluded in the gate report, so the omission is visible. *Consequence:* reviewers see diffs that matter; the git check validates the full truth; filtered content is named, never hidden. Spec-lint WARNs on noise-glob matches in files_in_scope (to surfaced the intention). *Why:* filtering is a read-side convenience for humans; verification paths always see the unfiltered truth. A reviewer passing a diff it never saw is the failure mode the naming mitigates. Source: epic #15 design ledger (D16); v2.1 §G noise-filter definition, §12·10 filtering rules. *Amended by:* shipped at issue #9 (PR #33) with the spec-lint WARN later absorbed into #26.
