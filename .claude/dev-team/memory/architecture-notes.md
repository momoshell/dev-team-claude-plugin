- **2026-08-07** — **ADR-019 — The task-workspace browser is a singleton preview surface, dispatcher-created under a lock and dispatcher-driven at the gate; its page bytes are reduced before they exist as evidence, and they never gate a verdict.**

  **Status:** proposed · **Date:** 2026-08-07 · **Scope:** cmux execution mode, Phase 4b (issue #12, epic #15 D8) · **Supersedes:** nothing; refines TRD D8 (`docs/trd-cmux-execution-mode.md:565`) and discharges the `:252` `references/qa-gate.md` promise. **Number:** 019 is free — 014/015/016 are claimed by the parked deterministic-backbone epic #23 (`tasks/deterministic-backbone/architecture-package-v2.1.md`); 017 and 018 are ratified in this epic; v1's ADR-017–019 were absorbed into v2's 014–016, the same reasoning that freed 018; epic #39's sub-issues claim only ADR-007 (grep, confirmed firsthand).

  **Opt-in, off by default.** One config key, `cmux_preview_url`, read with the ADR-018 reader doctrine (fenced-block-stripped, one line or refuse-as-ambiguous, absent = today's behavior exactly). Scheme restricted to `http`/`https` by allowlist; userinfo (`@`) refused outright; hostless forms, out-of-range ports and malformed percent-escapes refused; refusals name the reason and the scheme, never the value. A preview is created only when the key is set **and** the spec's `domain` is exactly `frontend` **and** the role's isolation is `worktree` **and** the cached preflight's methods include `browser.open` — so backend-only tasks are structurally incapable of spawning one. An accepted consequence: a full-stack slice authored `backend` gets no preview.

  **`browser` enters `VERBS` as a single entry guarded by a frozen sub-verb allowlist** (`open goto wait errors screenshot` — no `eval`, `state`, `console`, `snapshot`, or interaction verbs), and **never enters `VERB_METHODS`**: that map is one-verb-to-one-method and cannot represent a five-method family, and the preview is non-load-bearing, so it must degrade loudly rather than hard-stop preflight on every dispatch including the ones that will never open a browser. Availability is read at the point of use from the already-cached `preflight.json` methods array, the way teardown reads `close_workspace_available`.

  **The created id comes from a tree diff, never from stdout.** `cmux browser open` prints `OK surface=surface:N pane=pane:N placement=split` — positional refs, which this repo may not persist and which renumber mid-session. Only `placement` is parsed, and only to be logged. `browser open` is chosen over `new-surface --type browser --url` because it is live-verified for an `http` URL with a UUID workspace, while the latter is unverified even for `file://`.

  **The singleton is a single-writer sidecar under a lock, with a mandatory pre-create authority scan and no adopt path.** The record lives at `<stateDir>/browser.json`, not in `workspace.json`: that file has one writer and five readers and is rewritten wholesale from `carried`, so a second writer there would be a lost-update race with `workspace --tier` and would force `workspaceCmd` to join the lock — a load-bearing change to a core verb for a cosmetic feature. Parallel `dispatchCmd` against one workspace is reachable today and `writeJsonAtomic` prevents torn writes, not lost updates, so the whole resolve→decide→create→verify→stamp runs inside `withRecordLock`, and **the lock spans the side effect, not the write** — locking only the stamp leaves both racers having created. Because `withRecordLock` steals any lock older than `LOCK_STALE_MS` (30 s) without checking holder liveness, and because `tree()` is otherwise unbounded, every spawn inside the critical section carries an explicit `timeoutMs` summing to a stated 19 s worst case, **and** a post-create idempotence re-scan detects a stolen-lock loser and abandons its own surface rather than stamping. Both halves ship: a budget cannot cover a misbehaving spawn timeout, and a detector cannot prevent the window.

  A pre-create fresh-tree authority scan is nonetheless mandatory, because `browser open --workspace` **reuses an existing browser pane rather than creating a second**, and two stacked browser surfaces are **both undrivable** (live-verified in both directions: `js_error`/`navigation_timeout` on `wait` and `errors list`, blank screenshot, while the identical single-surface flow in an equally unfocused workspace works). "Create because we have no record" is therefore a data-loss operation, not an idempotent one, and the singleton is an operational requirement, not hygiene.

  **There is no adopt outcome — this is deliberate.** The three outcomes are reuse (recorded surface corroborated against a fresh tree and a matching workspace id), create (zero free browser surfaces), and fail closed (any free browser surface with no valid record: skip, create nothing, log `preview_surface_ambiguous`, or `preview_topology_unverifiable` when a same-workspace record's pane id no longer resolves). Adopting a free browser surface would mean `browser-verify` issuing a `goto` against it — and if it were a `mountDocTab` rung-2 doc tab whose record went unreadable, or a pane that ADR-004's collapse-on-close reduced to a lone browser surface, that `goto` would **navigate a rendered return document away**. The cost of a wrong adopt is data loss; the cost of a wrong skip is one missing preview and a log line. Asymmetric costs settle it, and deleting the outcome also deletes the cmux-restart edge, the collapsed-doc-tab special case, and the unreadable-record case in one move — every residual in that family now degrades to a skip.

  Worker panes are excluded by UUID — the pane holding `initial_surface_id`, and every same-workspace dispatch record's resolvable `surface.pane_id` — **never by a surface title.** Titles were the first design and are live-falsified: `rename-tab` returns `not_found` on a browser surface, and a browser surface's `tree` title tracks the page hostname, i.e. it is navigation-controlled text. Selecting a topology target with page-controlled bytes is the boundary violation this ADR exists to prevent, so an available `http(s)`-vs-`file://` title heuristic is rejected on principle, not on capability.

  **The dispatcher is the only invoker at both ends.** `dispatchCmd` creates, in the cosmetic zone — a preview failure never fails a dispatch. A new orchestrator-invoked `dispatch.mjs browser-verify` verb collects evidence at the gate, documented in `references/qa-gate.md` beside `cmux diff` as an optional adjunct and deliberately kept out of the lifecycle-order line. No worker ever runs a `cmux browser` verb; `contract.mjs` and `CMUX_ALLOWS` are byte-identical; ADR-013's freeze holds. The issue's "driven by-ref by the validator" is reinterpreted: the dispatcher drives the surface by UUID and the *reduced* evidence reaches the validator's bundle as data — the validator itself has no cmux reach, so the reverted pane flip is not a dependency. Hand-typing the sequence was rejected for a stronger reason than convention: it pipes **unreduced page bytes into the orchestrator's own context** — the agent that composes the gate report and decides bounce-vs-pass — which is *closer* to control flow than the also-rejected Agent-tool validator. The `cmux diff` precedent transfers on the **permission half only** (orchestrator-invoked ≠ worker capability, no `CMUX_ALLOWS` entry); it does not transfer on output handling, because `cmux diff` renders to a GUI for human eyes while `errors list` lands in a model transcript. `browser-verify` joins `MUTATING_VERBS`, whose name misleads here: the set means "requires `execution_mode: cmux`", not "mutates a record".

  **Bounded spawns.** `cmux()` has no default spawn timeout. Every browser wrapper passes one explicitly, exceeding any cmux-side `--timeout-ms`, so a spawn kill (`spawn_error`) stays distinguishable from cmux's own bound (`js_error`, `navigation_timeout`). `browser-verify` states a total wall-clock budget (≤ 90 s): an unbounded verb at the gate stalls the orchestrator's interactive session, not a background job.

  **ADR-002 boundary, extended from screen frames to page bytes.** `browser errors list` output is task-controlled, prompt-injection-class text. `scripts/cmux/browser-evidence.mjs` reduces it in-process to `{clean, count, shape}` — a count and a closed three-value enum, never a message — and is import-firewalled from `ladder.mjs`/`triage.mjs`/`contract.mjs` by test in both directions, exactly as `triage.mjs` is. Unrecognized output fails toward *not clean*. Raw bytes never reach JSON, a log line, stderr, or disk. Wrappers log the error **code** only, shape-guarded to `^[a-z_]{1,32}$`, never the detail — a deliberate divergence from the house `err.message` pattern, because browser error details are page-influenced and `dispatch.mjs`'s stderr is an orchestrator-context ingress. Truncating or sanitizing the detail was considered and rejected: it bounds volume, not content. Likewise only the URL **origin** ever appears in JSON, a report line, or the sidecar — a dev URL can carry a token query param, and refusing to echo a value on the reject path while printing it on the accept path is the same leak.

  **Screenshot success is not evidence of a rendered page.** On a surface that never became ready, `screenshot` returns `OK` and writes a full-size white PNG; and a connection-refused navigation leaves the console **clean**, so `clean (0)` on a never-loaded page is reachable and reads exactly like success. `browser-verify` therefore reports `load_state_confirmed` — the `wait --load-state complete` result, the only non-vacuous liveness signal — alongside and never merged into the console reduction, and the gate report **suppresses any clean claim when it is false**. Report lines never say "verified" or "renders correctly": screenshot success means a file exists, nothing more. **None of this gates the verdict** — the gate branches on the parsed `{verdict, findings}` enum alone (D17); an unconfirmed load state and a dirty console are both evidence, and the verb exits 0. The orchestrator may exercise judgment after reading it; that is judgment, not a mechanical branch, and the distinction is stated in the doc and in the code because "fixing" it into a branch is the predictable regression.

  **Screenshots and the sidecar are deleted at teardown, not merely swept.** `archiveOrDelete` *renames* `stateDir` into `.archive` whenever any record's outcome ≠ `ok` — common on bounced tasks — so "swept for free" was false on the archive path and screenshots of an authenticated dev app would persist indefinitely, contradicting the exposure reasoning that put them in `stateDir` in the first place. `teardownCmd` performs exactly one feature-specific deletion, before archiving, tested on both branches.

  **`browser state save`/`state load` does not ship.** The same surface persists build→gate in one cmux instance, so the live session already carries auth; the verbs add value only across a cmux restart or a surface re-creation. Against that, state files are cookies and localStorage on disk in a `stateDir` reachable by a same-uid worker subprocess (G13) — precisely the residual ADR-005's addendum names, authenticated browser surfaces near worker panes. **The descope does not avoid that residual: PR 1 walks into it the moment a human logs into the preview.** What it declines is a *replayable on-disk artifact* that would let a file manufacture an authenticated surface with no human in the loop. Mitigation is documentary — `commands/onboard.md` and `config.md` state: log the preview into dev/staging accounts only, never production or admin credentials. *Re-entry condition:* an observed cmux restart **or surface re-creation** between build and gate that discarded an expensive login. At that point the design owes, per **ADR-003 Am.1 Rider E (confidentiality is bounded by lifetime, not achieved by location)**: the state file written immediately before `state load`, unlinked immediately after and on every abort path (the 1b nonce lifecycle verbatim), never logged, with an origin guard because `state save` throws `SecurityError` on `about:blank`. Mode-0600 and clever siting buy nothing against G13, and unlink-at-teardown is far too late — an earlier draft of this decision prescribed exactly that and was wrong.

  **`snapshot` is a named non-goal** — a large page-controlled blob with no reduction that is both non-vacuous and non-injecting.

  **Placement is cmux's default; no `move-surface` is issued.** No anchor-pane argument exists on 0.64.22, and moving the preview into the coder's pane would stack it as a tab and destroy the simultaneous visibility that is the point. Adjacency stays a human concern (the issue's own words); `--focus false` on create; the reported `placement` is logged for live acceptance.

  **The preview is invisible to the ladder by construction:** `reconcile`/`paneAlive` are record-driven and the preview is in no dispatch record; `closeCmd`'s collapse is pane-scoped and the preview has its own pane. No record-level invisibility mechanism was built — only regression tests pinning those non-interactions.

  **Distinguishing rule (why one thing is descoped and another pre-paid).** This ADR descopes `state save/load` for an unobserved need while shipping the gate half for an equally unobserved one. The rule: the byte-reduction boundary is judgment-dense and would be built **wrongly** under pressure later — a hand-typed sequence, at a gate, by the agent that then decides bounce-vs-pass. A credential-on-disk would be built **at all** only under pressure later. One is worth pre-paying; the other is not. Deferring the reduction boundary does not preserve the decision, it pre-decides it wrongly.

  **Frozen literals and platform facts (cmux 0.64.22, live-verified):** `--load-state complete` (`load` is invalid; accepted set is `interactive|complete`); `No browser errors` is the clean literal; error codes `js_error`, `navigation_timeout`, `not_found`, `invalid_params`, `invalid_state`, `not_supported`, plus `spawn_error` from a spawn kill; `rename-tab` is terminal-surfaces-only; `browser open` is fire-and-forget (~0.06 s) while `goto` self-bounds at ~15.5 s.

  *Why this ADR exists:* D8's ratified record was one line, and each of its three under-specified parts had a wrong-looking obvious answer — gate the family on one RPC method, let the validator drive the browser, save the session to disk. Each is recorded here with its rejection reason so a future slice does not re-derive them, and two mechanisms (a frozen tab title, a sanitized error detail) are recorded as *falsified* rather than quietly dropped.

- **2026-08-08** — **ADR-020 (proposed): external content is wrapped at ingress by a script, not by discipline — the envelope covers only author-authored text, never API-structural fields, and the strip+nonce mechanisms deliberately cover each other's failure mode.** Every Trello/GitHub fetch that folds untrusted text into a prompt pipes through `scripts/wrap-external.mjs --src <closed-enum: github-issue|github-pr|github-review-thread|trello-card>`. - **2026-08-08** — **ADR-021 (proposed): the QA gate has memory (no new persisted ledger), and a consolidation pass may only make the gate stricter, never looser.** Three parts. **(1) Gate memory / carry-forward** — reuses three existing carriers with zero new schema: an in-loop "Prior findings" block the orchestrator composes from the gate report it already holds; GitHub thread replies for `/dev-team:pr-review` respond mode (with a new rule: a disposition reply must be from the PR author — not any commenter — recognized by a closed 5-shape enum, never a "friendly-sounding" comment); and `conventions.md`/`qa-notes.md` when a disposition generalizes. The carry-forward table's closed disposition enum is `fixed`/`open`/`wont-fix (user)`/`disagreed (user)`/`deferred (issue #N)`. **Only the user may author a `(user)` disposition** — the orchestrator may author `deferred` but never fabricate user consent, and (after a real attack was found and closed) may never independently choose or lower the `prior severity` column either — it must reproduce the severity the finding actually carried, since that column is the second lever an unconstrained orchestrator could pull to bypass the same authorship bar. A `deferred` row on a critical is NOT a "don't re-raise" instruction — the reviewer should still report it if re-encountered; deferral is scheduling, not dismissal. **(2) Consolidation pass** — six ordered steps run after an adversarial panel returns, before acting: (0) freeze the verdict pass/fail arithmetic FIRST from the raw returns, exactly as the existing panel-majority rule defines it — nothing below may change this number, except that a step-3 upgrade INTO critical still flows through and can flip a frozen pass to a block (the invariant is **"stricter, never looser," not "never changes the arithmetic"** — the latter phrasing contradicts this repo's own pre-existing "a verdict:pass carrying a critical is a contradiction" rule); (1) normalize to `(member, severity, file, line, summary)`, marking a member with no parseable block `unstructured` — and an unstructured member's prose-described critical-class defect MUST BLOCK PENDING ESCALATION exactly as a structured critical would, never weakened to "may block"; (2) dedup — two findings merge only if EVERY pair in the resulting group was independently judged the same defect (a **clique** of the pairwise relation, not merely a connected component: A~B and B~C true with A≁C judged false does NOT merge all three, since that would be over-merging under certainty, contradicting the adjacent under-merging-is-safe rule); merge is content-preserving (every merged *finding's* summary retained, none discarded — phrased per-finding not per-member, since one member can raise two distinct findings at the same file:line); normalized `file` strips both the repo-root prefix and any `.claude/worktrees/<id>/` segment so an agent-tool-mode absolute path and a cmux-mode relative path compare equal; (3) re-categorize against the fixed severity table only — upgrades unrestricted, downgrading an existing critical forbidden; (4) drop only under one of three cited conditions, critical never droppable (escalate instead): contradicts a *quoted* (not just named) pre-dating memory entry; re-raises a `wont-fix`/`disagreed (user)` finding with a cited concrete artifact and no new evidence; or is factually false against the diff (must disprove the underlying defect, not merely an imprecise anchor/wording); (5) report a mandatory audit line (`consolidated N findings from M members (P of M supplied structured findings) -> K (X merged, Y dropped, Z re-categorized)`) whose absence is itself an escalation; (6) escalate in both directions — a frozen block survives even if every blocking finding was later dropped, and a step-3 upgrade into critical blocks even though the frozen count said pass. **(3) A gate report is written at `.claude/dev-team/tasks/issue-<N>/gate-report-r<k>.md`** whenever a gate bounces OR whenever a carry-forward row is critical (so an accepted-risk critical is persisted even on a clean pass) — plain markdown, human-readable, never parsed by anything; the moment something parses it, the rejected persisted-ledger design has been quietly rebuilt. *Why this needed 4 full adversarial-panel rounds (12 reviewer dispatches):* round 1 found a genuine critical-suppression bypass — the orchestrator could unilaterally author `deferred` on a real critical with zero constraint, and once in the carry-forward table it vanished from all future gate arithmetic, bypassing every safety mechanism the consolidation pass has (those only guard drops *within* consolidation, never suppression one step upstream via carry-forward); rounds 2–3 found and closed follow-on gaps in that same fix (the severity-column mislabeling lever, a fix-round that accidentally deleted the pre-existing PR-author authorship check, unhardened `deferred`/`open` handling in `pr-review.md`) plus the dedup over-merge contradiction above; two of three lenses independently proved that almost none of the new safety rules had test coverage (one did so empirically, by deleting rules from a scratch copy and confirming the full suite stayed green) — 24 test pins were added in response. Round 4 passed clean on all three lenses (suppression-safety / dedup-correctness / doctrine-coherence). *Known residual, not fixed, recorded as follow-up:* a user-accepted `deferred` critical that a reviewer keeps re-reporting per the not-a-don't-re-raise rule has no terminal handling — it will re-block and re-escalate every round, which can wedge the gate against the user's own deferral decision; the coverage-declaration's "distinguish looked-vs-never-looked" purpose (stated in ADR from A2) still has no consumer in the consolidation steps, only its "shared blind spot" half landed; the audit-line counting units don't reconcile under a clique that resolves as overlapping pairs rather than one group. Source: issue #13 items 2–3, `qa-13-a3`.

## Base architecture decisions (ADR-001–011)

The eleven decisions below are the baseline cmux execution-mode architecture, ratified 2026-08-01 at slice-1a planning. Later amendments live as dated entries in the `## Entries` section above; each ADR below that has been amended carries an `*Amended by:*` pointer to those entries. ADRs are read in isolation — a contradiction between an amended base decision and a later entry elsewhere in this file is a failure mode these pointers guard against.

- **ADR-001 — Execution substrate: custom cmux adapter, not `cmux claude-teams`.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Drive cmux via its CLI/socket behind our own adapter layer. Option A (`cmux claude-teams`) rejected: tmux shim at `~/.cmuxterm/claude-teams-bin/tmux`, gated behind `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, Claude-only, partial tmux verb coverage — cannot carry a roster, a permission model, or a return contract. *Consequence:* the orchestrator composes dispatch records and invokes adapters, never hardcodes Claude Code assumptions into the dispatcher. *Why:* every architecture of the plugin before cmux was tied to the Agent-tool model; adapters un-tie it. Revisit if: claude-teams leaves experimental and grows multi-CLI support. Source: epic #15 design ledger (D1); v1 §4.1 option A rationale, v1 §6.

- **ADR-002 — Filesystem is the data plane; the cmux socket is control plane only.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Specs in as file paths on the launch line; returns as schema-validated files; `wait-for` = doorbell; `read-screen` = diagnostics only; `send` = single-line control text only. Forced by cmux's design (events redact bodies; no payload primitive; TUIs submit on every newline). *Consequence:* structured returns are the data plane's contract in both directions — the orchestrator branches on enums (status, verdict, severity), never on prose; screen-scraping is structurally impossible. *Why:* the asymmetry (agent uploads giant JSON, orchestrator reads one byte at a time from a pane) forced this shape; it turns out to be robust. Source: epic #15 design ledger (D2); v1 §4.2 rationale, v2 §4.5.

- **ADR-003 — Completion is signalled by a four-rank ladder; events trigger rescans, never endings.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. The doorbell is a hierarchy: (0) return-file watch inside `await` — stat + `return-lint` every 3–5 s, co-primary, filesystem-only; (1) `cmux events --name notification.requested` — workspace-scoped rescan trigger, native for Claude inside cmux; (2) adapter `trap … EXIT` writes `logs/<id>.exit` sentinel and signals `wait-for`; (3) Stop hook return-gate with ≤2 block cap and its own counter, writes the blocked return on exhaustion. *Consequence:* the orchestrator's join always unblocks — by a fresh valid return, by an explicit blocked return (written by the agent, the gate, or the adapter), or by a timeout naming the pane and its log; no branch ends in silence. Self-signal dropped (prompt-dependent, deny-beats-allow makes it unreliable). *Why:* (0+1) provide liveness without hooks or socket reach; (2) is the liveness backstop for crashes; (3) enforces the return contract but never owns the signal. Unbounded block loops burn sessions; an interactive TUI never exits by itself. Source: epic #15 design ledger (D3, amended in v2 after review); v2 §4.3 rank definitions, v2.1 §B-2 attribution model. *Amended by:* 2026-08-01 Am.1 (nonce + ladder re-derivation), 2026-08-02 poll-first await, 2026-08-02 '.exit never decides completion', 2026-08-05 be-11-01 errata (the rank-1 doorbell event is `agent.hook.Stop`, not `notification.requested` — live-verified against cmux 0.64.22; see docs/trd-cmux-execution-mode.md's Superseded-since-ratification table).

- **ADR-004 — Role-station panes: the return file is the doc tab.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Judgment roles return markdown, opened with `cmux markdown open` and relocated into the producer's pane with `move-surface --focus false`. One artifact serves three roles: contract return (schema-validated), live progress view (live-reloading on disk), approval surface (rendered doc in the pane). For executors the pane closes on return; for judgment roles the pane collapses to the rendered document — focus-don't-close is the Phase-2 default (collapse-on-close is polish, gated on spike S19). UUIDs only (no positional refs persisted); re-read before acting. Placeholder is lint-invalid by construction. *Consequence:* leads and reviewers see their work live while producing it; the orchestrator never drafts-in-pane; every file is written tmp+rename, never rm-then-recreate. Fallbacks: browser surface tab, then a split pane. *Why:* one artifact instead of three (return + viewer + approval) is cheap; live reload frees the lead from refresh loops. Source: epic #15 design ledger (D7, amended in v2 for UUIDs); v1 §4.4 mechanism, v2 §4.4 amendments, v2.1 §E close-step. *Amended by:* 2026-08-03 parent-render-on-validation, 2026-08-06 collapse-on-close default (S19 passed; verified-sibling precondition — this reverses "focus-don't-close is the Phase-2 default").

- **ADR-005 — Security posture: default socket mode, orchestrator-inside-cmux, allowlist-shaped worker profiles, scoped return grant.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. `cmuxOnly` stays (the only socket mode that makes sense); `allowAll` banned; `cmux identify` preflight enforces the precondition. Worker profiles are allowlist-shaped under `dontAsk` (deny beats allow; only non-prompting mode that cannot stall). One file grant: `Edit(//<abs task-dir>/returns/**)`. Workers denied `Bash(cmux *)` at the tool layer (outside the permission system). No Task tool. Never `--dangerously-skip-permissions` or `bypassPermissions`. For pane dispatches the profile's tool universe and allow/deny rules REPLACE the role's frontmatter wholesale — never merge (frontmatter expresses the Agent-tool model, profiles express the pane model). *Consequence (resolves the latent ADR-004/005 conflict):* the one file a read-only role may write is exactly the file ADR-004 renders — they're the same file. Addendum clause: `cmuxOnly` is containment, not immunity. The socket admits any descendant of the cmux app — which includes every subprocess a worker pane spawns. Third-party code executed by allowed commands (e.g. package scripts under `npm test`) is therefore inside the socket trust boundary, and the worker-level `Bash(cmux *)` deny does not mediate it. What the default mode does buy: the boundary shrinks from the entire user account to what is deliberately run inside cmux. Residual inside-risk is cross-pane typing, screen reading, and driving logged-in browser surfaces within cmux. Operational rule: do not keep high-privilege interactive sessions — SSH to production, sudo'd shells, authenticated admin browser surfaces — in the same cmux instance where worker panes execute untrusted build code. Task workspaces are ephemeral by design; privileged long-lived panes belong outside cmux or at minimum outside any cmux instance running dev-team workers. *Why:* Tier-2 and Tier-3 specs can dispatch untrusted role prompts; permission-based containment is the only available boundary (OS sandboxing deferred). Denying cmux at the tool layer assumes workers never signal — true because the gate and adapter signal instead. Source: epic #15 design ledger (D9, amended in v2 and again in v2.1); v1 §5.4 Roster, v2 §4.6 scoped grant, v2.1 §B-1 profile replacement. *Amended by:* 2026-08-01 D9 amendment (enumerated cmux allow-list, no deny wildcard) and 2026-08-01 Am.1 (uniform --tools, web-tool loss).

- **ADR-006 — `roster.json` is committed; `tasks/` is gitignored by a self-contained ignore file.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. `roster.json` is team configuration like `config.md` — committed. `.claude/dev-team/tasks/` is ephemeral dispatch working data — ignored via `tasks/.gitignore` (`*` + `!.gitignore`), not the repo root `.gitignore` (the plugin commits the sibling `memory/` tree). Task dirs are deleted at ship after memory distillation; `keep_task_artifacts: true` archives instead. Additive optional roster schema fields do not bump `version`. *Consequence:* the roster survives a git clone; task state does not. Every project gets the team-wide roster and may override it locally. *Why:* rosters express policy (who runs what, on which model); tasks express session state (what is happening now). Source: epic #15 design ledger (D2, D6); v1 §5.4 Roster, v1 §5.2 data layout. *Amended by:* 2026-08-01 Am.1 + 2026-08-02 siting rule/Rider D + 2026-08-04 stale-paths warning.

- **ADR-007 — Workflow mode stays on the Workflow tool's agent() dispatch; "never the Agent tool" is scoped to conversational dispatch.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. The Workflow tool's `agent()` primitive cannot be intercepted without rewriting the wave scheduler; workflow mode is the batch lane where visibility is not the point. Conversational dispatch (Tier-1/2/3 task roles) never uses the Agent tool when cmux mode is active. Workflow mode is carved out and remains Agent-tool only. *Consequence:* workflow teams keep their existing behavior; conversational tasks get visible panes. *Why:* workflow is a separate subsystem; intercepting it would require too much machinery for a non-core flow. Carve-out is stated in `references/cmux-dispatch.md` and `commands/team.md`. Source: epic #15 design ledger (D3); v1 §4.1, v1 §9. *Amended by:* 2026-08-03 slice-1d entry (workflow mode stays on the Workflow tool's agent()).

- **ADR-008 — cmux is an environment prerequisite, not a preference.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. `execution_mode: cmux` means preflight failure stops the task with precise remediation; no silent degradation to Agent-tool dispatch. Two values: `cmux` / `agent-tool` (default for anyone without cmux — macOS-only app). Onboard sets `execution_mode: cmux` on a working install; pre-existing projects default to `agent-tool` and must opt in. The plugin treats cmux like git (also a macOS/Linux-only prerequisite). *Consequence:* preflight failure is loud with remediation steps; users know when they are not in cmux mode. Phase 1 spike S8 audits the installed version and gates the entire phase. *Why:* silent fallback created debugging confusion (users think they got cmux when they got Agent-tool); loud failure is cleaner. Source: epic #15 design ledger (D14); v2 §3.5 binding constraint 6, v2 §5.5 preflight. Cross-file pointer: conventions.md's 2026-08-03 entry (execution_mode canonical values cmux|agent-tool, subagent a normalized legacy alias).

- **ADR-009 — Pane system prefixes are byte-stable per role.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Static role file + static per-profile addendum + static worker plugin; per-dispatch variance via env and kickoff only; wave launching (first pane of a role warms the prefix cache; same-role siblings launch after it begins). The model receives expanded absolute literals in the kickoff (spec path, return path, dispatch id) — the kickoff is per-dispatch and sits after the cached prefix. Env vars are for shell-side consumers (adapter, return-gate, gate-mode), which expand them; the model is not a shell consumer. *Consequence:* two dispatches differing only in ids/paths produce byte-identical prompt-file content; cache hit rates stay high; rejects per-dispatch generated `--settings`. *Why:* every dispatch re-computes the session prefix for the model; caching is essential under the July-2026 token budget. D15 made it load-bearing. Source: epic #15 design ledger (D15); v2 §5.9 cache discipline, v2.1 §B-3 kickoff delivery. *Amended by:* 2026-08-01 Am.1 (--append-system-prompt-file exists; single pre-composed role-prompt file per role with role_prompt_sha256) and 2026-08-01 S16 reversal.

- **ADR-010 — Machine-readable verdicts at both ends of the pipe.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Reviewer returns stay markdown for the human surface but carry a fenced `{verdict, findings[]}` block inside the Verdict section — present, parseable as JSON, `verdict` in the set {pass, changes-needed, inconclusive}, every `findings[].severity` in {critical, warning, suggestion}. Shape-validated only; finding quality is never linted. The gate branches on the severity enum (any critical → bounce/escalate; only suggestions → pass with notes; missing/unparseable → inconclusive → re-run scoped to the diff), never on prose interpretation. A majority-verdict rule runs over multiple reviewers' `verdict` values. *Consequence:* the orchestrator's control flow reads the block; prose remains for the human and the doc tab; reviewer quality judgments stay agent-side and are never linted. *Why:* prose is ambiguous (does "needs work" mean bounce or amend?); enums are actionable. The severity-to-ladder mapping is critical ↔ must-fix, warning ↔ should-fix, suggestion ↔ consider. Source: epic #15 design ledger (D17); v2.1 §H verdict-block definition, §R2-3 gate branching. *Amended by:* 2026-08-03 required_sections matching semantics and the still-open extractSection shadowing exposure noted 2026-08-04.

- **ADR-023 — Roster-override persistence across `/clear` is declined; the existing two-layer precedence already covers the need.** accepted 2026-08-08, issue #30. `resolve.mjs`'s `loadRoster` already has two persistent layers below the ephemeral session override: `~/.claude/dev-team/roster.json` (personal, all-projects) and `<project>/.claude/dev-team/roster.json` (project-scoped, higher-precedence, committed by default — `.git/info/exclude`-able pre-first-commit for a personal copy). The hypothesized gap — a personal, project-scoped, uncommitted override an operator wants to survive `/clear` — is already expressible as a 3-line partial fragment in the project file (only the MERGED roster is schema-validated, so a layer file needn't carry `schema_version`/`tools`/`defaults`/`profiles`). Building a THIRD, session-tagged persisted layer was rejected: ranked below the project layer it would be silently defeated by team config; ranked above it (matching the session layer's current top rank) it becomes a top-precedence override with no `/clear` event to end it — a "why has my coder been running haiku for three weeks" footgun requiring a full writer/inspector/clearer lifecycle to be safe, none of which existed. *Consequence:* `commands/team.md`'s `roster` verb doc now points operators at the two existing files instead of offering a `--persist` flag; no new roster precedence layer, no new verb. *Why:* same family as the 2026-08-04 pane-dispatch-flip revert (needs real design, not a patch) and the "documented-then-broken control path" pattern (`execution_mode`, `keep_task_artifacts`, `noise_globs` — backend-notes.md) — a fourth knob whose entire risk surface is "operators forget it exists" belongs in that family, not shipped by default. - **ADR-026 — Instrumentation is never load-bearing; the emitter facade swallows every ledger/lock failure.** accepted 2026-08-11, epic #39/#41 (shipped as `scripts/factory/emit.mjs`; back-filled into this file 2026-08-12 — the number was claimed in code and specs but never recorded here, caught during #78's V2 verification). Every public method on the emitter from `openRun()` is wrapped so no throw escapes: a failure bumps a drop counter and writes AT MOST ONE stderr line per process. `ledger.mjs` deliberately throws when its own JSONL append fails (losing the raw record is fatal); this facade exists to swallow that and every other ledger/lock failure without ever changing a caller's outcome, exit code, or returned value. `openRun()` itself never throws — any failure standing up the run sidecar yields a fully-formed, fully-inert DEGRADED emitter with the same method surface. *Clause 1 (the citable one):* a ledger degradation can never invert a gate's exit code — gate facts source from the sidecar read that already succeeded, never from the possibly-degraded emitter. - **ADR-027 — Multi-process seq allocation is parent-owned, persisted-before-emission; monotone, not gapless.** accepted 2026-08-11, epic #39/#41 (`scripts/factory/emit.mjs`; back-filled 2026-08-12 with ADR-026). `ledger.mjs`'s own seq allocator seeds from `SELECT MAX(seq)` once per process per (adw_id, kind) — single-process-only, and below the Node floor `ensureDb()` returns null so every below-floor process restarts numbering at 1 (a deterministic 100% collision the instant two processes share an adw_id). `emit.mjs` is the first multi-process caller, so it never uses `ledger.mjs`'s allocator: every emission passes an EXPLICIT seq from a parent-allocated, sidecar-persisted range. The range-allocating critical section contains NO sqlite, NO JSONL, NO spawn — it reads the sidecar, bumps `next`/`reserved_through`, atomic-replaces, all before any ledger I/O. The reservation persists BEFORE any emission: a crash mid-batch leaves a GAP, never a DUPLICATE. seq is therefore monotone, not gapless. Source: epic #41, be-41-03..06; `scripts/factory/emit.mjs:21-40`.

- **ADR-028 — Substrate discipline is enforced by an orchestrator-side PreToolUse guard that denies only on positive evidence; every other outcome allows.** ratified 2026-08-12 (user-approved at the plan-approval gate), issue #78 (arch-lead package v1→v2, plan-reviewer 2 rounds; shipped as `hooks/dispatch-guard.mjs` + a `hooks/hooks.json` entry, deep-review 3-lens adversarial panel + mutation pass). `orchestration.md:42` binds the orchestrator to dispatch every `pane: true` role through `scripts/cmux/dispatch.mjs` in cmux mode, never the Agent tool — prose with no mechanical backstop, and it failed twice in five days (issue #76 ran end-to-end on Agent-tool subagents; the planning session for THIS issue then did the same, on current rules, a pure judgment failure). **The guard:** a PreToolUse hook (matcher `Agent` — the payload tool-name for a subagent dispatch, Phase-0 live-verified, NOT `Task`) that DENIES iff SIX conjuncts all hold — `tool_name==='Agent'`, no `agent_id`/`agent_type` present (main-thread only), `subagent_type` matches `/^dev-team:[A-Za-z0-9_-]{1,64}$/`, `resolveExecutionMode().mode==='cmux'`, the MERGED roster marks the role `pane===true`, AND `PANE_ROLES.includes(role)`. That last conjunction MIRRORS the dispatcher's own admission test (`dispatch.mjs`: admit iff `resolved.pane && PANE_ROLES.includes(role)`) exactly, so the two can never disagree — and it gates on the RESOLVED grant, never a hardcoded name list (the #27 gate-on-the-grant-not-the-name rule; a project roster override that flips a role is honored in both directions, and a `pane:true`-but-not-in-PANE_ROLES role stays dispatchable via agent-tool rather than being wedged behind both doors). **Fail-open on positive evidence only:** every error/uncertainty path — malformed stdin, unknown role, ambiguous/unknown `execution_mode`, invalid/unreadable roster, any throw, hook timeout — ALLOWS. This inverts the repo's usual fail-closed default deliberately: the guard is not a containment boundary (worker containment is ADR-005/012's `--allowedTools` surface, untouched); it is a doctrine backstop on the orchestrator's own session, and the costs are asymmetric — a wrong refusal-to-permit blocks EVERY subagent dispatch in the session for a cause the user cannot see, while a wrong allow is one visible, correctable agent-tool dispatch. **Never emits `permissionDecision:'allow'`** (a PreToolUse allow bypasses the user's own permission rules — a fail-open guard must say nothing, never grant; narrowed from the ratified `deny|allow` shape by the backend-lead, orchestrator-confirmed) and **never exits 2** (policy is exit-0 JSON only, so the platform's non-blocking semantics for other non-zero exits carry the fail-open guarantee for free). **ADR-008 reconciliation:** ADR-008 governs the dispatcher's PREFLIGHT, where the substrate is genuinely unavailable — loud stop, no silent degradation; ADR-028 governs a GUARD malfunction, where the substrate is fine — fail open. They compose rather than conflict because the two failures have opposite blast radii (refusal-to-act costs one clear error; refusal-to-permit costs every unrelated caller). **Carve-outs:** `Explore` scouts (no `dev-team:` prefix), `pane:false` roles (agent-tool is their correct substrate in cmux), non-`dev-team:` subagents, nested calls (carry `agent_id`/`agent_type`), worker sessions (`DEVTEAM_WORKER` early exit), and workflow mode — DOUBLY excluded per Phase 0: the Workflow tool arrives as tool-name `Workflow` (never matches) AND its inner `agent()` calls carry `agent_type: workflow-subagent` (nested carve-out). This cleared the ADR-007 stop condition — the guard ships as a real deny, not warn-only. **Kill switch is the config, not a new knob:** `/dev-team:team mode agent-tool` makes the substrate truthful; a dedicated disable key is rejected on ADR-023 grounds; `escalate` is rejected per ADR-008. **Consequences:** (a) silent inertness when `node` is unresolvable is accepted and DETECTABLE — a `node_unresolved` line in the decision log (`~/.dev-team/guard/dispatch-guard.jsonl`), plus a `systemMessage`; (b) an invalid-roster fail-open is a de facto SECOND kill switch (a schema-breaking roster edit disables the guard via `roster_error` while the dispatcher keeps working off `roster.snapshot.json`); (c) the decision log accumulates `cwd`+`session_id` for every dispatch across every repo on the machine, rotation deliberately unbuilt, 32MiB ceiling MARKED (`log_ceiling_reached`) not silent; (d) **restart discipline** — hooks load at SessionStart, so a session started before this version keeps the old guardless hook set; the guard only protects sessions started on or after the shipped version, and restart-after-plugin-update remains required. **The guard reads 3 of the roster's 4 layers** (session is a dispatcher-only `--config` sidecar the hook can't see) — a bounded residual that could diverge only via a hand-authored non-standard sidecar, not the supported `roster` verb (which writes agent/model only). Source: issue #78, arch-78 package v2, Phase-0 findings, be-78-01/02, doc-78-03.
