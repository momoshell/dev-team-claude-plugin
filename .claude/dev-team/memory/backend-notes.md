- **2026-08-01** — Validators: **throw on contract-author error, return violations on data error** (`scripts/cmux/contract.mjs` precedent). Throw when the *schema* is wrong — out-of-budget keyword, malformed keyword **value shape** (`required: 'name'`, `additionalProperties: 'no'`, `items: true`) — because that's a repo-author error no valid data can trigger; return `Violation[]` when the *instance* is wrong, because the caller is the dispatcher's hot path and needs to classify (`invalid_return`), not crash. *Why:* the deep review caught the value-shape half missing — name-only checks let `additionalProperties: 'no'` silently disable closed-set enforcement, the exact vacuous-validator failure. Shape-check keywords before recursing.
- **2026-08-01** — `Violation` shape is `{ path, keyword, message }` (`path` dotted/bracketed from `$`; `keyword` = the failed budget keyword or the distinct `schema_version_too_new`). *Why:* a test asserting only "non-empty violations" can't tell a right-reason rejection from a reject-everything validator — negatives must assert `path` + `keyword`, ideally exactly-one via deepEqual.
- **2026-08-01** — A slug that feeds a filesystem path **throws on empty/degenerate input**, never returns a fallback (`slugify` in `contract.mjs`). *Why:* an empty segment collapses a path (`~/.dev-team/tasks//x`) and silently re-targets writes; fail closed at derivation, not at the write.

- **2026-08-02** — `cmux send` does **not** auto-submit, even with a trailing `\n` — every kickoff is `send` then `send-key <surface> enter` (live-verified, spike S7; implemented in `cmuxctl.mjs` `sendLine`). *Why:* a missing `send-key` looks exactly like a hung worker.

- **2026-08-02** — `scripts/spec-lint.mjs` false-positives on absolute paths containing hyphenated directory names: its path-extraction regex chops `/Users/x/Development/dev-team-claude-plugin/tasks/...` into `team-claude-plugin/tasks/...` and FAILs it as missing, and a `path:line` citation followed by `)` also mis-parses. *Why:* triage lint FAILs against reality before bouncing a spec (verified every flagged path by hand at 1b planning); fixing the linter regex is an open backlog candidate.
- **2026-08-02** — Node **never dispatches a registered signal handler while the main thread is blocked in a synchronous call** (`spawnSync`, `Atomics.wait`, blocking `readSync`): libuv catches the signal on a self-pipe but the JS `process.on('SIGTERM')` body cannot run until the syscall returns and the stack unwinds. Consequence for a synchronous supervisor (the cmux adapter): its exit-evidence (sentinel + completion signal) MUST be written on the synchronous return path (call `finalizeSentinel(code)` first thing in the pane-hold, before the blocking `readSync`), never relying on the signal/`exit` handler to fire mid-spawn. A hard `SIGKILL` writes no sentinel — that is fine, the parent ladder re-derives (no `crashed` fast-path, falls to the `timeout_s` backstop, bounded not lost). Verified empirically, 3 repros (1c fix-1c-05 / SF3). *Why:* the issue's "trap … EXIT writes the sentinel" contract does not actually fire during the long blocking `spawnSync` where the adapter spends ~all its time.
- **2026-08-02** — The single blocked-return writer (`writeBlockedReturn`) enforces `return_path ⊂ task_dir` **inside itself**, failing CLOSED (throws), so every caller (gate + adapter) inherits the containment; a salvage path that runs *after* schema validation already failed needs its own inline copy of the check (tightening the schema `pattern` cannot help there). *Why:* a worker-rewritten `return_path` turned the guaranteed-return write into a confused-deputy write outside the permission scope — the `judgment`/`validator` profiles grant no worktree_write, so the permission layer is the only thing scoping those roles' writes (1c panel MF3).
- **2026-08-02** — Any reason/error string interpolated into a **markdown** body is sanitized (collapse `[\r\n]+`, strip a leading fence run) before use — a multi-line reason is the *default* (the absent-return case joins FAIL lines with `\n`), and a reason line beginning with ```` ``` ```` opens a fence that `stripFences` then uses to swallow the required `## <section>` headings, making the guaranteed-valid blocked envelope itself `invalid_return`. Single-token reasons (e.g. `violations[0].keyword`) are incidentally immune — make that immunity explicit with a comment + test, don't leave it load-bearing-by-accident. *Why:* 1c panel MF5.
- **2026-08-02** — An `invokedDirectly` guard comparing `process.argv[1]` to `fileURLToPath(import.meta.url)` must `realpathSync` **both sides**: the ESM loader realpaths `import.meta.url` while `argv[1]` stays literal, so under a symlinked path component (macOS `TMPDIR` is `/var → /private/var`) a literal compare is silently false and the CLI no-ops.
