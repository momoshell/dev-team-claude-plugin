# Conventions — dev-team-claude-plugin

Cross-cutting conventions and decisions. The orchestrator is the sole writer — leads only propose deltas. Mark superseded entries `deprecated` (`supersedes: <entry>`) rather than deleting them.

## Format

- **YYYY-MM-DD** — decision/convention. *Why:* reason. [deprecated — supersedes: <prior entry>]

## Entries

- **2026-08-01** — Every functional commit bumps the `version` field in `.claude-plugin/plugin.json` and the commit message ends with `; bump 0.<major>.<minor>`. *Why:* a directory-marketplace install caches the plugin at a version-pinned path (`~/.claude/plugins/cache/dev-team/dev-team/<version>/`) and `plugin update` no-ops while the version is unchanged — an unbumped version means the fix never reaches installed copies. Source: `.claude-plugin/plugin.json` + observed git history (e.g. commit `f7b6cef`).
- **2026-08-01** — No lint or typecheck tooling exists (no `tsconfig.json`, no eslint config) — the repo is plain JS (Node `--test`) + Markdown. *Why:* the plugin ships agent/command definitions as Markdown and a handful of `.mjs` scripts; there's no compiled/typed surface to check. Source: repo root listing.
- **2026-08-01** — Test suite (`node --test`) runs the full 87-test suite in under 1 second. *Why:* means `validate.fast` and `validate.full` are identical here — no separate slow/fast split is needed. Source: timed run at onboarding.
- **2026-08-01** — This repo is the dev-team plugin's own source; `/dev-team:onboard`/`next`/`ship` run here manage the plugin's own development. *Why:* affects how leads should read structural references — `agents/`, `commands/`, `references/` etc. are the plugin's *product*, not consumer app code.
- **2026-08-01** — When composing a `claude` CLI invocation programmatically, always place a bare `--` immediately before the prompt positional. *Why:* `--tools`/`--allowedTools`/`--disallowedTools`/`--add-dir` are variadic and greedily consume the following positional; the prompt is then silently never submitted (`SessionStart` fires, `UserPromptSubmit` never does, no error, indefinite idle). Live-verified on claude 2.1.220, 4 reproductions + fix confirmation (cmux spike, `tasks/cmux-mode/spike-findings.md` S7/S9).
- **2026-08-01** — `dontAsk` permission semantics, live-verified on claude 2.1.220 (spike addendum, transcript evidence): omission from `--allowedTools` **is** denial for any command outside the built-in read-only set (`ls cat echo grep pwd head tail find wc which diff stat du cd` + read-only `git` — those always run, in every mode); a precise argument-scoped allow (`Bash(cmux notify *)`) is honored while sibling verbs stay denied; scoped denies (`Bash(cmux ping*)`) enforce. Never pair a broad deny with a narrow allow — precedence is deny→allow and a deny cannot carry exceptions; prefer allow-only rules and rely on omission-denial. *Why:* fail-closed containment with zero deny-list maintenance; the natural deny+carve-out shape silently resolves to denied.
- **2026-08-01** — Never take permission verdicts from the Claude Code TUI screen: the collapsed "Ran N shell commands" line counts **denied attempts** as ran. Read the session transcript (`~/.claude/projects/<project-slug>/<session-id>.jsonl`, tool_use/tool_result pairs, `is_error` field) instead. *Why:* two spike tests were initially misread as "everything executed" when the transcript showed every call denied.
- **2026-08-01** — `--append-system-prompt-file` and `--system-prompt-file` exist on claude 2.1.220 but are absent from the main `--help` listing (referenced only inside `--bare`'s help text). Probe a flag's existence by passing a nonexistent file: a real flag errors "file not found" before any API call; a fake one errors "unknown option" (`--version`/`--help` short-circuit before flag validation and prove nothing). *Why:* S8 concluded the flags were missing from a `--help` grep; a free probe disproved it.
- **2026-08-01** — Claude Code permission-rule syntax, **live-confirmed on 2.1.220** (S22a passed both directions with `Edit(//abs/**)`; S22b showed a `Write(...)` rule is rejected on stderr with *"is not matched by file permission checks — only Edit(path) rules are. Use Edit(…) instead"*): file-path rules must be `Edit(...)`/`Read(...)` — `Write(...)`/`NotebookEdit(...)`/`MultiEdit(...)` path rules are accepted but never consulted, and `Edit` covers all file-editing tools; absolute paths need a **double** leading slash (`//abs/...`) — a single slash anchors at cwd. Grep a child `claude`'s stderr for `is not matched by file permission checks` to fail fast on a bad rule kind. *Why:* both errors fail silently as spurious denials; they invalidated the spike's original S9 test.
- **2026-08-01** — Never site an agent-writable directory under `.claude/`, `.git/`, `.vscode/`, `.idea/`, `.husky/`, or `.devcontainer/`. Live-verified: a `dontAsk` worker with an **exact-match** `Edit(//<repo>/.claude/dev-team/tasks/x/returns/**)` allow rule is **denied** — `permissions.allow` does not override protected-path denial. The boundary is asymmetric: an interactive/`auto` orchestrator session writes `.claude/dev-team/` fine, so the trap only bites the dispatched-worker path — exactly where return files live. *Why:* silently breaks every worker return with a message the worker will narrate rather than escalate (drove the ADR-006 task-dir relocation).
- **2026-08-01** — `--allowedTools` is an allow-*rule* list, not a capability list; `--tools` is what closes the available tool set, and `--tools` does not cover MCP tools (use `--strict-mcp-config` + `--disallowedTools "mcp__*"`). A profile claiming a role "cannot run commands" is wrong unless Bash is absent from `--tools` — with Bash present, the built-in read-only set still executes in every mode. *Why:* omission from `--allowedTools` denies *execution*, but the tool stays in the model's context and the read-only set still runs.
- **2026-08-01** — Any token that authorises a state transition must be an unguessable per-run nonce delivered out of band to the process that fires it, and must never reach the supervised process's argv, environment, or any directory it can read. Prefer a mode-0600 file the consumer reads and unlinks before the supervised process exists: on macOS `ps eww` reports a process's **exec-time** environment, so unsetting an inherited env var after exec does not retract it. *Why:* discovered closing a completion-token forgery hole in cmux mode.
- **2026-08-01** — Never auto-`git reset --hard` a checkout the user owns. Automatic destructive recovery is permitted only on a path proven to be an agent-created worktree (is a worktree, shares the expected `git-common-dir`, is not the primary checkout); anything else refuses and escalates. *Why:* an over-broad cleanliness post-condition plus an automatic reset is a data-loss bug waiting on one false positive.
- **2026-08-01** — This repo has no JSON-Schema validator and will not gain one. New schemas stay inside the fixed 15-keyword budget (`$schema title description type required properties additionalProperties items enum const pattern minimum maximum minItems uniqueItems`; non-empty string = `pattern: "\S"`, bounded length = pattern quantifier — `minLength`/`maxLength` out of budget) so the hand-rolled validator in `scripts/cmux/contract.mjs` stays small and reviewable; enforcement is a **positive allow-list walk** in `test/schema.test.mjs`, and every new schema must be added to that file's **hardcoded list** (it is a list, not a glob — an unlisted schema is checked by nothing). *Why:* README advertises dependency-free; `ajv` would need node_modules, a lockfile and CI changes.
- **2026-08-01** — `//` is permission-rule syntax, not filesystem-path syntax. Inside `--allowedTools` an absolute path needs a double leading slash; a *filesystem* path field in a record/env var must be single-slash absolute (POSIX leaves `//foo` implementation-defined). Two distinct patterns, never unified. *Why:* conflating them in a schema silently blesses paths some platform may resolve differently (caught reconciling issue #2 vs the v2 design record).
- **2026-08-01** — Prefer structural impossibility to a test assertion, and a whitelist to a blacklist. Encode a rule so violating it yields an *invalid document* (closed enum, absent property, `additionalProperties: false`); keep the test only as a meta-check that the constraint hasn't been widened. Where a constraint must be enumerated, enumerate what is **allowed**. *Why:* 1a's plan review found two stale blacklists (a shell-metachar refusal list missing `(`/`)`/quotes; a conditional-keyword list missing four banned keywords) and zero stale whitelists.
- **2026-08-02** — CLI-dependent tests use a repo-local fake-binary fixture behind a `<TOOL>_BIN` env indirection: `test/fixtures/fake-cmux.mjs` logs every invocation as one JSON line to `$FAKE_CMUX_LOG`, persists mutable topology to `$FAKE_CMUX_STATE`, and varies **only by env switches** — no test-specific conditionals inside the fixture; where it answers "what does the real system say", the answer is a frozen live capture (see qa-notes 2026-08-02). *Why:* first instance of the pattern here (1b dispatcher); keeps the suite offline and <5s while every cmux interaction stays assertable.
- **2026-08-02** — Concurrency-unsafe check-then-act on files is a defect class the panel found four times in one slice: use `writeFileSync(tmp)` + `linkSync(tmp, dest)` (EEXIST = loser) for exclusive creates, a `'wx'`-created lock file `{pid, started_at}` verified-before-unlink for RMW transitions, and treat a corrupt lock as stale, never a wedge. `existsSync`-then-`rename` is always a TOCTOU (rename clobbers unconditionally). *Why:* 1b's record lifecycle (writeRecord/terminateRecord/worktrees.json) shipped all three shapes before review.
- **2026-08-02** — A worker's self-reported terminal status (`blocked`/`insufficient` in the return body) is decided at the outcome-mapping layer, **never** inferred from the process exit sentinel. The `.exit` sentinel never fails a valid return (frozen U-4), and a gate-exhausted turn writes a blocked return with `.exit=0` — so an exit-keyed check both breaks U-4 and misses that case. Key on `envelope.body.status`, in a row ahead of `completed→ok`. *Why:* a PRE-1C-VERIFY refusal / CLI-missing / gate-exhausted dispatch was laundering `{status:"blocked"}` into outcome `ok`, advancing the orchestrator on work that never ran (1c panel MF1). Adding the dedicated `blocked` outcome bumped `dispatch-record.schema.json` schema_version 1→2 per its own evolution rule (outcome-enum additions bump).
- **2026-08-02** — A snapshot/inventory verifier must assert **completeness against a closed manifest** (every expected destination was seen), not only reject bad entries found on disk — a rejection-only walk is bypassable by deletion. *Why:* a worker `rm`-ing the turn-blocking gate from its snapshot passed a rejection-only walk with the gate silently absent (1c panel MF4).
- **2026-08-02** — Cross-trust artifacts (per-worker plugin snapshots) are keyed **per dispatch** (`<stateDir>/worker-plugin/<dispatch_id>/`), never shared per task: a shared snapshot lets a long-lived writer role mutate the hooks a concurrent read-only role executes on its next hook fire. Nest under the task stateDir so wholesale teardown still sweeps it. *Why:* shared `worker-plugin/` was a cross-dispatch code-execution vector (1c panel R1 / contract #9).
- **2026-08-02** — "Never logs the secret" and "exactly-once side effect" acceptance criteria are **vacuous unless proven by mutation**: pair each with a test that fails when the guard is removed or the secret is injected (assert against `NONCE_PREFIX` on *every* failure path, not just the happy one; count the actual side-effect invocations, don't just assert a well-formed value). *Why:* three 1c must/should-fixes (MF7 nonce-log, SF3 exactly-once, SF5 realpath) were 652/652-green holes a reviewer's one-line injection/guard-removal defeated. Extends the positives-first rule to guard-removal mutation testing.
- **2026-08-02** — A raw control character (e.g. a literal `NUL`) written as a string-literal separator makes the source file "binary" to BSD grep/`rg`/diff and many editors — they silently match nothing. Always use the escape (`'\0'`, `'\x00'`) so the source stays ASCII while the runtime string is identical; at the gate, a `grep` that unexpectedly returns *nothing* for a symbol you know exists is the tell — confirm with `tr -cd '\0' | wc -c` / a Python NUL scan. *Why:* a coder shipped two literal NUL join-separators in `adapter-claude.mjs`; tests passed (node tolerates it) but every grep-based gate check came back empty and nearly masked a real inspection.
- **2026-08-03** — `execution_mode` canonical values are `cmux` | `agent-tool`; `subagent` is a legacy alias normalized to `agent-tool` on read, and an absent key means `agent-tool`. Enforced by frozen exports in `scripts/cmux/dispatch.mjs` (`EXECUTION_MODES`, `EXECUTION_MODE_ALIASES`, `DEFAULT_EXECUTION_MODE`) + a deepEqual drift guard; exactly two values can ever leave `readExecutionMode`, and no document may present `subagent` as the value to set. *Why:* the frozen 1a preflight remediation (`cmuxctl.mjs` verb_missing) already instructed operators to set `agent-tool` while the 1b reader threw on it — a documented-then-broken control path. One canonical spelling per mode; the throw quotes the raw configured spelling. Supersedes: the 1b-era `subagent | cmux` pair (dispatch.mjs + README).
- **2026-08-03** — **A structural check whose "already done" state is unobservable will be re-done.** Any idempotent mount/create loop must resolve current state from the authority (a fresh tree/listing) before acting, and its absent-vs-ambiguous outcomes must be distinguishable so consumers can fail closed; a guard that relies on "this branch is unreachable today" becomes a duplicate-side-effect bug the moment the gate that made it unreachable opens. *Why:* `statusCmd`'s doc-tab re-mount loop was a documented structural no-op under the Phase-1 `PANE_ROLES` gate; flipping six roles at #6 turned it into "mount another panel on every status call" until guarded.
