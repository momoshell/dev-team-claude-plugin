# Conventions — dev-team-claude-plugin

Cross-cutting conventions and decisions. The orchestrator is the sole writer — leads only propose deltas. Mark superseded entries `deprecated` (`supersedes: <entry>`) rather than deleting them.

## Format

- **YYYY-MM-DD** — decision/convention. *Why:* reason. [deprecated — supersedes: <prior entry>]

## Entries

- **2026-08-01** — Every functional commit bumps the `version` field in `.claude-plugin/plugin.json` and the commit message ends with `; bump 0.<major>.<minor>`. *Why:* a directory-marketplace install caches the plugin at a version-pinned path (`~/.claude/plugins/cache/dev-team/dev-team/<version>/`) and `plugin update` no-ops while the version is unchanged — an unbumped version means the fix never reaches installed copies. Source: `.claude-plugin/plugin.json` + observed git history (e.g. commit `f7b6cef`).
- **2026-08-01** — No lint or typecheck tooling exists (no `tsconfig.json`, no eslint config) — the repo is plain JS (Node `--test`) + Markdown. *Why:* the plugin ships agent/command definitions as Markdown and a handful of `.mjs` scripts; there's no compiled/typed surface to check. Source: repo root listing.
- **2026-08-01** — Test suite (`node --test`) runs the full 87-test suite in under 1 second. *Why:* means `validate.fast` and `validate.full` are identical here — no separate slow/fast split is needed. Source: timed run at onboarding.
- **2026-08-01** — This repo is the dev-team plugin's own source; `/dev-team:onboard`/`next`/`ship` run here manage the plugin's own development. *Why:* affects how leads should read structural references — `agents/`, `commands/`, `references/` etc. are the plugin's *product*, not consumer app code.
- **2026-08-01** — When composing a `claude` CLI invocation programmatically, always place a bare `--` immediately before the prompt positional. *Why:* `--tools`/`--allowedTools`/`--disallowedTools`/`--add-dir` are variadic and greedily consume the following positional; the prompt is then silently never submitted (`SessionStart` fires, `UserPromptSubmit` never does, no error, indefinite idle). Live-verified on claude 2.1.220, 4 reproductions + fix confirmation (cmux spike, `tasks/cmux-mode/spike-findings.md` S7/S9).
- **2026-08-01** — `dontAsk` permission semantics, live-verified on claude 2.1.220 (spike addendum, transcript evidence): omission from `--allowedTools` **is** denial for any command outside the built-in read-only set (`ls cat echo grep pwd head tail find wc which diff stat du cd` + read-only `git` — those always run, in every mode); a precise argument-scoped allow (`Bash(cmux notify *)`) is honored while sibling verbs stay denied; scoped denies (`Bash(cmux ping*)`) enforce. Never pair a broad deny with a narrow allow — precedence is deny→allow and a deny cannot carry exceptions; prefer allow-only rules and rely on omission-denial. *Why:* fail-closed containment with zero deny-list maintenance; the natural deny+carve-out shape silently resolves to denied.
- **2026-08-01** — Never take permission verdicts from the Claude Code TUI screen: the collapsed "Ran N shell commands" line counts **denied attempts** as ran. Read the session transcript (`~/.claude/projects/<project-slug>/<session-id>.jsonl`, tool_use/tool_result pairs, `is_error` field) instead. *Why:* two spike tests were initially misread as "everything executed" when the transcript showed every call denied.
- **2026-08-01** — `--append-system-prompt-file` and `--system-prompt-file` exist on claude 2.1.220 but are absent from the main `--help` listing (referenced only inside `--bare`'s help text). Probe a flag's existence by passing a nonexistent file: a real flag errors "file not found" before any API call; a fake one errors "unknown option" (`--version`/`--help` short-circuit before flag validation and prove nothing). *Why:* S8 concluded the flags were missing from a `--help` grep; a free probe disproved it.
- **2026-08-01** — Claude Code permission-rule syntax, **live-confirmed on 2.1.220** (S22a passed both directions with `Edit(//abs/**)`; S22b showed a `Write(...)` rule is rejected on stderr with *"is not matched by file permission checks — only Edit(path) rules are. Use Edit(…) instead"*): file-path rules must be `Edit(...)`/`Read(...)` — `Write(...)`/`NotebookEdit(...)`/`MultiEdit(...)` path rules are accepted but never consulted, and `Edit` covers all file-editing tools; absolute paths need a **double** leading slash (`//abs/...`) — a single slash anchors at cwd. Grep a child `claude`'s stderr for `is not matched by file permission checks` to fail fast on a bad rule kind. *Why:* both errors fail silently as spurious denials; they invalidated the spike's original S9 test.
- **2026-08-01** — Never site an agent-writable directory under `.claude/`, `.git/`, `.vscode/`, `.idea/`, `.husky/`, or `.devcontainer/`. Live-verified: a `dontAsk` worker with an **exact-match** `Edit(//<repo>/.claude/dev-team/tasks/x/returns/**)` allow rule is **denied** — `permissions.allow` does not override protected-path denial. The boundary is asymmetric: an interactive/`auto` orchestrator session writes `.claude/dev-team/` fine, so the trap only bites the dispatched-worker path — exactly where return files live. *Why:* silently breaks every worker return with a message the worker will narrate rather than escalate (drove the ADR-006 task-dir relocation).
- **2026-08-01** — `--allowedTools` is an allow-*rule* list, not a capability list; `--tools` is what closes the available tool set, and `--tools` does not cover MCP tools (use `--strict-mcp-config` + `--disallowedTools "mcp__*"`). A profile claiming a role "cannot run commands" is wrong unless Bash is absent from `--tools` — with Bash present, the built-in read-only set still executes in every mode. *Why:* omission from `--allowedTools` denies *execution*, but the tool stays in the model's context and the read-only set still runs.
- **2026-08-01** — Any token that authorises a state transition must be an unguessable per-run nonce delivered out of band to the process that fires it, and must never reach the supervised process's argv, environment, or any directory it can read. Prefer a mode-0600 file the consumer reads and unlinks before the supervised process exists: on macOS `ps eww` reports a process's **exec-time** environment, so unsetting an inherited env var after exec does not retract it. *Why:* discovered closing a completion-token forgery hole in cmux mode.
- **2026-08-01** — Never auto-`git reset --hard` a checkout the user owns. Automatic destructive recovery is permitted only on a path proven to be an agent-created worktree (is a worktree, shares the expected `git-common-dir`, is not the primary checkout); anything else refuses and escalates. *Why:* an over-broad cleanliness post-condition plus an automatic reset is a data-loss bug waiting on one false positive.
- **2026-08-01** — This repo has no JSON-Schema validator and will not gain one. New schemas stay inside the fixed 15-keyword budget (`$schema title description type required properties additionalProperties items enum const pattern minimum maximum minItems uniqueItems`; non-empty string = `pattern: "\S"`, bounded length = pattern quantifier — `minLength`/`maxLength` out of budget) so the hand-rolled validator in `scripts/cmux/contract.mjs` stays small and reviewable; enforcement is a **positive allow-list walk** in `test/schema.test.mjs`, and every new schema must be added to that file's **hardcoded list** (it is a list, not a glob — an unlisted schema is checked by nothing). *Why:* README advertises dependency-free; `ajv` would need node_modules, a lockfile and CI changes.
- **2026-08-01** — `//` is permission-rule syntax, not filesystem-path syntax. Inside `--allowedTools` an absolute path needs a double leading slash; a *filesystem* path field in a record/env var must be single-slash absolute (POSIX leaves `//foo` implementation-defined). Two distinct patterns, never unified. *Why:* conflating them in a schema silently blesses paths some platform may resolve differently (caught reconciling issue #2 vs the v2 design record).
- **2026-08-01** — Prefer structural impossibility to a test assertion, and a whitelist to a blacklist. Encode a rule so violating it yields an *invalid document* (closed enum, absent property, `additionalProperties: false`); keep the test only as a meta-check that the constraint hasn't been widened. Where a constraint must be enumerated, enumerate what is **allowed**. *Why:* 1a's plan review found two stale blacklists (a shell-metachar refusal list missing `(`/`)`/quotes; a conditional-keyword list missing four banned keywords) and zero stale whitelists.
- **2026-08-02** — CLI-dependent tests use a repo-local fake-binary fixture behind a `<TOOL>_BIN` env indirection: `test/fixtures/fake-cmux.mjs` logs every invocation as one JSON line to `$FAKE_CMUX_LOG`, persists mutable topology to `$FAKE_CMUX_STATE`, and varies **only by env switches** — no test-specific conditionals inside the fixture; where it answers "what does the real system say", the answer is a frozen live capture (see qa-notes 2026-08-02). *Why:* first instance of the pattern here (1b dispatcher); keeps the suite offline and <5s while every cmux interaction stays assertable.
- **2026-08-02** — Concurrency-unsafe check-then-act on files is a defect class the panel found four times in one slice: use `writeFileSync(tmp)` + `linkSync(tmp, dest)` (EEXIST = loser) for exclusive creates, a `'wx'`-created lock file `{pid, started_at}` verified-before-unlink for RMW transitions, and treat a corrupt lock as stale, never a wedge. `existsSync`-then-`rename` is always a TOCTOU (rename clobbers unconditionally). *Why:* 1b's record lifecycle (writeRecord/terminateRecord/worktrees.json) shipped all three shapes before review.
- **2026-08-02** — A worker's self-reported terminal status (`blocked`/`insufficient` in the return body) is decided at the outcome-mapping layer, **never** inferred from the process exit sentinel. The `.exit` sentinel never fails a valid return (frozen U-4), and a gate-exhausted turn writes a blocked return with `.exit=0` — so an exit-keyed check both breaks U-4 and misses that case. Key on `envelope.body.status`, in a row ahead of `completed→ok`. *Why:* a PRE-1C-VERIFY refusal / CLI-missing / gate-exhausted dispatch was laundering `{status:"blocked"}` into outcome `ok`, advancing the orchestrator on work that never ran (1c panel MF1). Adding the dedicated `blocked` outcome bumped `dispatch-record.schema.json` schema_version 1→2 per its own evolution rule (outcome-enum additions bump).
- **2026-08-02** — A snapshot/inventory verifier must assert **completeness against a closed manifest** (every expected destination was seen), not only reject bad entries found on disk — a rejection-only walk is bypassable by deletion. *Why:* a worker `rm`-ing the turn-blocking gate from its snapshot passed a rejection-only walk with the gate silently absent (1c panel MF4).
- **2026-08-02** — Cross-trust artifacts (per-worker plugin snapshots) are keyed **per dispatch** (`<stateDir>/worker-plugin/<dispatch_id>/`), never shared per task: a shared snapshot lets a long-lived writer role mutate the hooks a concurrent read-only role executes on its next hook fire. Nest under the task stateDir so wholesale teardown still sweeps it. *Why:* shared `worker-plugin/` was a cross-dispatch code-execution vector (1c panel R1 / contract #9).
- **2026-08-02** — "Never logs the secret" and "exactly-once side effect" acceptance criteria are **vacuous unless proven by mutation**: pair each with a test that fails when the guard is removed or the secret is injected (assert against `NONCE_PREFIX` on *every* failure path, not just the happy one; count the actual side-effect invocations, don't just assert a well-formed value). *Why:* three 1c must/should-fixes (MF7 nonce-log, SF3 exactly-once, SF5 realpath) were 652/652-green holes a reviewer's one-line injection/guard-removal defeated. Extends the positives-first rule to guard-removal mutation testing.
- **2026-08-02** — A raw control character (e.g. a literal `NUL`) written as a string-literal separator makes the source file "binary" to BSD grep/`rg`/diff and many editors — they silently match nothing. Always use the escape (`'\0'`, `'\x00'`) so the source stays ASCII while the runtime string is identical; at the gate, a `grep` that unexpectedly returns *nothing* for a symbol you know exists is the tell — confirm with `tr -cd '\0' | wc -c` / a Python NUL scan. *Why:* a coder shipped two literal NUL join-separators in `adapter-claude.mjs`; tests passed (node tolerates it) but every grep-based gate check came back empty and nearly masked a real inspection.
- **2026-08-03** — `execution_mode` canonical values are `cmux` | `agent-tool`; `subagent` is a legacy alias normalized to `agent-tool` on read, and an absent key means `agent-tool`. Enforced by frozen exports in `scripts/cmux/dispatch.mjs` (`EXECUTION_MODES`, `EXECUTION_MODE_ALIASES`, `DEFAULT_EXECUTION_MODE`) + a deepEqual drift guard; exactly two values can ever leave `readExecutionMode`, and no document may present `subagent` as the value to set. *Why:* the frozen 1a preflight remediation (`cmuxctl.mjs` verb_missing) already instructed operators to set `agent-tool` while the 1b reader threw on it — a documented-then-broken control path. One canonical spelling per mode; the throw quotes the raw configured spelling. Supersedes: the 1b-era `subagent | cmux` pair (dispatch.mjs + README).
- **2026-08-04** — **`cmux diff [<patch-file>|-] [--source unstaged|staged|branch|last-turn] [--workspace] [--surface]` is the orchestrator's human patch view** — invoked from the interactive session, never by a worker, so it needs no `CMUX_ALLOWS` entry (that constant stays the frozen two-element list in `contract.mjs`; widening it is a permission change, not a convenience). Documented in `references/qa-gate.md`, #8. *Why:* verified live against the installed binary's `--help`; recording it prevents a future slice from "adding the diff verb to the allow list."
- **2026-08-04** — **A counter's unit is whatever event its hook actually fires on — design against the SHIPPED hook inventory, not a ratified-but-unbuilt one.** Issue #8 specified `max_turns` gate enforcement assuming a per-tool-call hook existed, because ADR-012 named a "PostToolUse attestation" hook in its closed inventory — but that hook was scheduled for a later slice and never built (`DEVTEAM_SIGNAL_LOG` is a frozen env key with no writer). Read `scripts/cmux/worker-plugin/hooks/hooks.json` itself before designing enforcement on "the hooks we have." *Why:* the plan survived to review because an ADR's planned inventory was read as its current state.
- **2026-08-04** — **No worker-plugin hook may force-stop (`continue:false` or equivalent) while the gate mode file reads `observe`.** Observe means a human has interjected mid-dispatch (`gate-mode.sh`, sticky once set); `return-gate.sh` already honors it with an unconditional early exit — no block, no slot claim. Any new enforcement mechanism must preserve this: count and log in observe mode, never act. *Why:* a mechanism that force-stops in observe mode force-stops the human's own conversation — the exact failure `gate-mode.sh` exists to prevent. (Moot for `max_turns` itself — see architecture-notes.md ADR-017, no such mechanism was built — but binding for whatever hook comes next.)
- **2026-08-05** — **A shell command documented in `references/*.md` for the orchestrator to run must be portable to bash, zsh, and POSIX `sh` — never assume bash.** This repo's interactive shell is zsh; a documented snippet using bash-only syntax (arrays, `read -a`, process substitution `<(...)`) silently fails or hard-errors when the orchestrator actually runs it, even though the snippet reads fine and any structural test of the surrounding prose stays green (tests can't execute embedded shell). Prefer POSIX-portable pipelines (e.g. `... | tr '\n' '\0' | xargs -0 -r ...`) over array-based composition; if bash-only syntax is unavoidable, say so explicitly and wrap it in `bash -c`. *Why:* issue #9's qa-gate.md noise-filtering commands shipped a bash-only fix that broke under zsh/sh on the first deep-review pass — caught only by live-running the snippet in all three shells (qa-notes.md 2026-08-05).
- **2026-08-03** — **A structural check whose "already done" state is unobservable will be re-done.** Any idempotent mount/create loop must resolve current state from the authority (a fresh tree/listing) before acting, and its absent-vs-ambiguous outcomes must be distinguishable so consumers can fail closed; a guard that relies on "this branch is unreachable today" becomes a duplicate-side-effect bug the moment the gate that made it unreachable opens. *Why:* `statusCmd`'s doc-tab re-mount loop was a documented structural no-op under the Phase-1 `PANE_ROLES` gate; flipping six roles at #6 turned it into "mount another panel on every status call" until guarded.
- **2026-08-01** — Dispatch only via `scripts/cmux/dispatch.mjs`, never in orchestration.md prose. The dispatcher owns the verb sequence (workspace creation, pane launch, kickoff send, doc-tab mount, await logic, close), token generation, worktree lifecycle, and error recovery — mechanical and deterministic work that belongs in a tested script, not narrative. Judgment (when to re-dispatch, how long to wait for a stalled pane, whether to ask the user) stays in the orchestrator's prose and interactive decisions. *Why:* the plugin already splits mechanical concerns (spec-lint, task-cost scripts) from judgment prose; dispatch is mechanical and failure-prone, and testability against a fake cmux without the model is essential. Source: epic #15 comment 6, v2 §4.1 and §5.8; recorded 2026-08-05, issue #10.
- **2026-08-01** — Control plane and data plane are separate channels: the filesystem carries structured returns (JSON/markdown), specs as file paths, and completion signals as files; the cmux socket carries diagnostics only (read-screen output is never a decision input), and control text only (send carries single-line commands, never payloads). Structured data that drives control flow (status, verdict, severity) is validated and acted on from files; prose diagnostics inform the human operator but never the orchestrator's branch logic. Any verdict that drives control flow is structured data with a fixed enum, validated mechanically; quality judgments stay agent-side and are never linted. *Why:* cmux's socket is message-scoped with redacted bodies and no payload primitive; the filesystem is the only channel that can carry contracts. Source: epic #15 comment 3, v1 ADR-002, and comment 8, v2.1 §R6; recorded 2026-08-05, issue #10.
- **2026-08-01** — The adapter contract is two verbs and a side effect: `capabilities` (orchestrator calls it at preflight; adapter reports model/flag support), and `run <record.json>` (orchestrator sends the dispatched role's spec/model/profile; adapter execs the agent inside the pane and never returns until the agent exits). The side effect is mandatory: on any exit (success, crash, timeout) the adapter writes the return file (`tmp+rename` for atomicity) and signals `cmux wait-for -S <token>` from a `trap … EXIT`, so the orchestrator is never left without a return. The return is the truth; the signal is the event. *Why:* determinism requires one script entry point; a return-on-exit invariant means crash recovery is file-based, never token-based. Source: epic #15 comment 6, v2 §5.3; recorded 2026-08-05, issue #10.
- **2026-08-01** — CLI-dependent subsystems (cmux, claude, npm) use a `<TOOL>_BIN` environment variable as a mockability seam: `dispatch.mjs` reads `$CMUX_BIN` (default `cmux`), the adapter reads `$CLAUDE_BIN` (default `claude`), and test fixtures wire them to fake binaries (`test/fixtures/fake-cmux.mjs` logs invocations; a mock claude script checks argv). This generalizes the existing `<TOOL>_BIN` test fixture convention (see 2026-08-02 entry about fake-binary fixtures); in cmux mode every integration point between the orchestrator and a real tool must be seamed this way. *Why:* tests run offline with full visibility into every tool call, zero model cost, and no flaky timeouts. Source: epic #15 comment 6, v2 §8; recorded 2026-08-05, issue #10.
- **2026-08-01** — Single source of truth for role prompts: every role body lives in exactly one `agents/<role>.md` file, never forked or duplicated. Substrate addenda (platform-specific instructions like "write your return to `$DEVTEAM_RETURN_PATH`") live under `scripts/`, never copied into `agents/`, so they are never auto-discovered as subagent roles. A pane dispatch reads the same role file, strips the frontmatter, appends the static substrate-specific addendum via `--append-system-prompt-file`, and sends to the agent. Agent-tool dispatch reads the same file, frontmatter intact. No file is edited to fit one substrate or the other. *Why:* two copies of a prompt drift independently and invalidate both; substrate addenda under scripts/ is the clean boundary. Source: epic #15 comment 6, v2 §4.6; recorded 2026-08-05, issue #10.
- **2026-08-01** — One reference file per subsystem: `references/cmux-dispatch.md` contains all cmux-mode mechanics and verb reference, read once per dispatch cycle; no cmux protocol lives in the core orchestration.md (kept lean at ≤69 lines), no verb tables elsewhere. A future adapter (codex, opencode, pi) gets one new reference file; the plugin never accumulates a second cmux reference or a second adapter reference. Judgment code (when to escalate, when to retry) can go in prose; mechanical reference material belongs in a frozen, indexed file. *Why:* discoverable, versionable, auditable as a single unit for every phase of work. Source: epic #15 comment 6, v2 §5.1; recorded 2026-08-05, issue #10.
- **2026-08-01** — Persist UUIDs, never positional refs, and re-read before acting: dispatch records store cmux surface/pane/workspace UUIDs as hexadecimal in the record file; code never stores positional refs like `surface:9` (which renumber when surfaces reorder). Before any topology operation (send, close, move-surface, read-screen), query `cmux tree --json --id-format uuids` and resolve the UUID to its current identity, no-op loudly if the UUID is gone. On ambiguity (multiple surfaces match), abort rather than guess. *Why:* positional refs are layout-dependent and silently break when cmux reorders; UUID-first + re-read means concurrent dispatches never close each other's panes. Source: epic #15 comment 6, v2 §4.4; recorded 2026-08-05, issue #10.
- **2026-08-01** — UI-backing files (return markdown for doc tabs, placeholder files for the worker to complete, rendered artifacts) are overwritten in place via `tmp+rename` (write to a temp file, atomically link it into place) or edited in place, never deleted and recreated. `existsSync`-then-`rename` is always a TOCTOU race; deletion + recreation later than cmux's ~500ms retry window bricks the rendered panel permanently. This differs from the existing TOCTOU rule (line 28, 2026-08-02 entry) in purpose: that rule guards *shared mutable state* (worktrees.json lock); this guards *visible UI artifacts* that cmux is monitoring for live-reload. *Why:* atomic writes and visible-file stability are prerequisites for a rendered doc tab. Source: epic #15 comment 6, v2 §4.4; recorded 2026-08-05, issue #10.
- **2026-08-01** — Worker profiles are allowlist-shaped under the `dontAsk` permission mode: a profile lists exactly what tools the role can call (`--tools Read,Edit,Write,Glob,Grep,Bash`) and exactly which operations are allowed (`--allowedTools "Edit(//…/returns/**)" "Bash(git diff *)"…`); there is no blanket deny list. Deny takes precedence over allow, so an allowlist-only shape fails closed by omission — any tool call not explicitly allowed is denied at the tool layer. Read-only roles (judgment, reviewer) can write exactly one file (their return) via a scoped grant; executors can write their worktree and their return. This enforces both capability (only what is listed works) and security (no privilege escalation via a blanket deny that can't carve out exceptions). The allowlist approach is embodied in architecture-notes.md's treatment of the dontAsk mode and the profile replacement rule. *Why:* the alternative (denylist + carve-out) is impossible because deny beats allow in Claude Code; allowlist-only needs no maintenance. Source: epic #15 comment 6, v2 §4.6; recorded 2026-08-05, issue #10.
- **2026-08-01** — Hooks own their loop bounds and never rely on `stop_hook_active`. The worker plugin's Stop hook runs at most N times (default 2; roster-overridable, hard ceiling 3) before the adapter writes a blocked return itself and allows the turn to end; the hook owns a persistent counter (`gate/<dispatch-id>.attempts`) and must never assume it will be called again. `stop_hook_active` is documented as broken (unbounded loop risk with 100+ iterations observed); the hook reads it only as an *additional* early exit, never as the signal source. A returned `{"continue": false}` from the hook has no effect because the turn is already ending (hook fires at Stop, after the model has already finished responding). *Why:* enforcing a return contract (schema validation) belongs in the hook; enforcing a word budget belongs in a counter the orchestrator owns. Hooks cannot change the agent's runtime behavior. Source: epic #15 comment 6, v2 §5.6; recorded 2026-08-05, issue #10.
- **2026-08-01** — Environment prerequisites fail loudly with precise remediation, never a silent substrate swap. When `execution_mode: cmux`, the dispatcher's preflight check runs `cmux ping`, `cmux identify`, and `cmux capabilities`; any failure prints a one-line remediation message (e.g. "cmux is required. Install: brew tap manaflow-ai/cmux && brew install --cask cmux") and stops the task with exit code indicating the failure class (binary missing, not running, wrong version, verb missing). The orchestrator never falls back to Agent-tool dispatch. This treats cmux like a hard dependency (git, npm) not a preference. Judgment stays in the user's onboard setup, not in the dispatcher. *Why:* silent degradation hides platform gaps and makes testing impossible; users who want cmux mode expect cmux. Source: epic #15 comment 6, v2 §5.5, and v2.1 ADR-008; recorded 2026-08-05, issue #10.
- **2026-08-01** — Pane system prefixes (system prompt, appended role body, worker-plugin hooks) are byte-stable per role: static role file path, static per-profile substrate addendum path, static worker-plugin directory. All per-dispatch variance (task paths, dispatch id, spec path, return path, timeout, attention tokens) is delivered as expanded absolute literals in the first user message (kickoff), never in env vars or the system prefix. Environment variables (`DEVTEAM_ROLE`, `DEVTEAM_RETURN_PATH`, etc.) serve shell-side consumers (the adapter, return-gate.sh) which expand them; the model is not a shell-side consumer and receives literals. This enables prompt-caching: the model caches the system prefix after the first pane of each role, and siblings of that role (same role, same profile) hit the cache. *Why:* cache efficiency scales dispatch volume; per-dispatch generation invalidates the cache every time. Source: epic #15 comment 6, v2 §5.9, amended by v2.1 §K:217; recorded 2026-08-05, issue #10.
- **2026-08-01** — Enforcement models don't merge. A role's permission rules are authored for one substrate (Agent-tool: role's frontmatter `permissionMode`, `tools`, `disallowedTools`; pane: profile from roster, allowlist-shaped `tools` and `allow`, `dontAsk` mode). For pane dispatch the profile's rules *replace* the frontmatter entirely — they are not merged. Merging a denylist (Agent-tool's mode) with an allowlist (pane's mode) silently produces a configuration where nothing works: the deny rules kill tool calls, the allow rules try to carve out exceptions, and deny takes precedence. *Why:* the two models are incompatible by design. One agent, two substrates equals two rule sets, one per substrate. Source: epic #15 comment 8, v2.1 §K:213; recorded 2026-08-05, issue #10.
- **2026-08-01** — A doorbell that cannot name the sleeper only wakes; it never decides. When multiple dispatches are running in one workspace, a `notification.requested` event (the doorbell) is workspace-scoped and wakes the join call, but the orchestrator cannot attribute the event to one pane — only to the whole workspace. The event triggers an idempotent rescan (re-stat and re-validate every outstanding return file); the actual resolution decision (completed / crashed / attention / timeout) is made by comparing the file state (fresh valid return file, EXIT sentinel, stale state, timeout elapsed). A workspace-scoped event cannot be a return-completion signal; it is only a "wake up and check" signal. *Why:* attributing a workspace event to one pane requires additional information the socket does not carry (cmux's event redacts the source); completion must be per-dispatch attributable from authoritative files. Source: epic #15 comment 8, v2.1 §K:214; recorded 2026-08-05, issue #10. **Amended 2026-08-06 (#11):** the *completion* half stands unchanged and reinforced — resolution is always re-derived from files, never from an event. But the premise "cmux's event redacts the source" was specific to `notification.requested`; the turn-end event `agent.hook.Stop` DOES carry a top-level UUID `surface_id` (live-verified 0.64.22), so the advisory *attention* signal (a pane quiet past `quietS` after its turn ended, no fresh return) IS per-surface attributable by exact match — a named doorbell still only triggers a rescan/flag, never a completion, but it can now name which sleeper.
- **2026-08-01** — Filters apply to what an agent reads, never to what a check verifies. Noise globs (lockfiles, minified/generated code, vendored libs) are applied when the agent reads the bundle (QA-gate report), cmux diff view, and handover guidance (spec-lint warns on matches); they are never applied to the git scope-compliance check, which always sees the unfiltered list. A spec that intentionally modifies a lockfile names it in `files_in_scope`; that path overrides the noise filter so it appears in both the bundle and the gate report. Verification paths (is the coder's diff in scope? did the coder edit outside its spec?) must always see the truth; filtering is a read-side convenience for human consumption. *Why:* filtered-away signal breaks the gate's scope check — if a reviewer never sees a lockfile diff, it cannot audit whether the coder respected scope. Filtered content is always named in the gate report so the omission is visible. Source: epic #15 comment 8, v2.1 §K:215; recorded 2026-08-05, issue #10.
- **2026-08-05** — A design record committed long after the fact ships as an *as-designed* document plus a supersession table — never as a retro-edited design doc. Assemble it verbatim from the dated sources under an explicit precedence chain (later amendment > base package; a rider that names itself governing > the section it rides on), banner it with its decision date, and append a table mapping each passage the implementation has since overtaken to the decision that overtook it and the memory entry recording that decision. *Why:* silently "correcting" the old design to match what shipped destroys the audit trail the record exists to create, while committing it unqualified ships a document that contradicts the code — issue #10 assembled a TRD from four epic-#15 comments whose data layout, completion token, profile set, turn-budget, and await-lock-contention decisions had all been superseded (the last one caught only at QA-gate review, not at drafting) before the document was ever written. Source: issue #10 planning + QA-gate finding.
- **2026-08-06** — Every cmuxctl wrapper that targets a workspace or surface takes the id explicitly and refuses (throws, before any spawn) without it; the `$CMUX_WORKSPACE_ID`/`$CMUX_SURFACE_ID` env defaults are never relied on. `dispatch.mjs` runs in the *orchestrator's own* pane, so a defaulted call silently decorates the orchestrator's workspace instead of the task's — a cosmetic-looking failure that points at the wrong place. The one deliberate exception is orchestrator-side user attention (`notify`/`trigger-flash` at the four blocking moments), where the caller's own surface *is* the correct target and the calls are hand-typed, never routed through `dispatch.mjs`. *Why:* generalises `setPhase`'s existing explicit-`--workspace` rule to `set-progress`/`clear-progress`/`workspace-action`; the default is a wrong-target trap, not a convenience. Source: issue #11 (`be-11-01`/`be-11-02`).
- **2026-08-06** — Cosmetic and diagnostic cmux verbs enter the frozen `VERBS` allowlist but never `VERB_METHODS`: a `VERB_METHODS` entry is a preflight hard-stop, and no colour pill, progress bar, log line, or screen read is worth halting every dispatch on an older cmux that lacks it. Such a verb is recorded unverifiable-by-capabilities and its wrapper degrades loudly on its own failure (the `setStatus` shape) instead. Only verbs the dispatch lifecycle genuinely depends on are capability-gated. *Why:* companion to the "never gate on a guessed method name" rule (that one is about *unknown* dotted-method mappings; this is about *known-but-non-load-bearing* verbs). The reason for the exclusion is stated at the `VERB_METHODS` definition site so it reads as a decision, not an omission. Source: issue #11 (`be-11-01`).
- **2026-08-06** — cmux's diagnostic verb family (`top`, `read-screen`) emits no UUIDs and accepts no `--id-format` — `top --format tsv` is headerless with 7 positional columns and its `id`/`parent_id` are positional refs (`surface:1`), never UUIDs. Anything joining diagnostic output to a UUID-keyed dispatch record needs a `tree --id-format uuids` cross-reference per call; price that before designing on it (it's why stall-attention attributes off the `agent.hook.Stop` event's UUID `surface_id`, never off `top`). *Why:* a parser that assumed a header row shipped twice with two different invented column sets in the fixtures, green — the real shape has to be a frozen live capture. Source: issue #11 (`be-11-01`/`be-11-03`), live-verified cmux 0.64.22.
- **2026-08-06** — An environment ingress crossing into a worker process is gated by a declared-key allowlist as the PRIMARY control; a reserved-name denylist is a non-overridable backstop only, never the primary gate, and is stated in-code and in the user docs as deliberately incomplete. A user env file reaching a pane sets env for the pane shell → adapter (node) → agent, so it can redirect binary seams (`CMUX_BIN`/`CLAUDE_BIN`), inject code (`NODE_OPTIONS`/`BASH_ENV`/`ZDOTDIR`), relocate config (`HOME`), or MITM traffic (`*_PROXY`/`*_CA_*`) — a denylist can never enumerate all of it (four vectors surfaced across one review). Reserved matching is case-insensitive where the consumer normalises case (npm reads `npm_config_*` case-insensitively — an uppercase `NPM_CONFIG_SCRIPT_SHELL` past a case-sensitive backstop was a proven RCE). *Why:* completeness is impossible for the denylist, so the allowlist must carry the weight and the human declaring keys must know it's a security decision. Source: ADR-018, issue #11 (`be-11-05`).
- **2026-08-06** — When we parse a file that a *different* tool will also parse and apply (an env file cmux re-reads by path), we parse to PREDICT what that tool will apply, not to consume: any construct whose downstream semantics we haven't verified is refused outright — quotes (incl. backtick), continuations, `export`, non-printable/non-ASCII bytes, duplicate keys — never repaired, never skipped-per-line, and the *whole file* refuses on one bad line. A printable-ASCII-plus-tab whitelist for keys and values is the enforcement; the file is read once so the recorded hash attests to exactly the validated bytes; the path is passed through, never re-composed into `ps`-visible `--env KEY=VALUE` argv. Refusal messages name the 1-based line number only, never the content or value (same secrets-hygiene class as never logging a nonce). *Why:* a divergence between our parse and the consuming tool's parse is a silent bypass of whatever gate our parse implements; a guard that "helpfully" unquotes would bless a key it believes it rejected. Source: ADR-018, issue #11 (`be-11-05`).
- **2026-08-07** — **A cmux verb family whose sub-verbs are argv tokens enters `VERBS` as ONE entry, is guarded by its own frozen sub-verb allowlist one level down, and never enters `VERB_METHODS`.** `VERB_METHODS` is a one-verb→one-RPC-method map, so a family (`browser` → five sub-verbs, dotted names `browser.navigate`/`browser.wait`/`browser.errors.list`/`browser.screenshot`/`browser.open_split` in the live capture — **not** `browser.open`/`browser.goto`/`browser.wait_for`/`browser.errors`, which this entry originally guessed and which the 2026-08-07 correction entry below caught) cannot be represented in it without gating five capabilities on one name — the exclusion is structural, not merely the non-load-bearing-verb policy. A single `VERBS` entry would otherwise unlock the whole family including `eval` and `state`, so the wrapper module asserts membership in a frozen `<FAMILY>_SUBVERBS` array and throws before any spawn, mirroring `runVerb`'s own check. [deprecated clause, 2026-08-07 fix-round: this entry originally added "availability is read at the point of use from the cached `preflight.json` methods array" — no such read shipped; the capability check was removed entirely (see the correction entry below), and the only remaining safety net is `browserOpen` returning `null` on failure.] *Why:* extends the 2026-08-06 cosmetics rule from a policy argument to a structural one, and closes the over-widening the single entry would otherwise create. Source: ADR-019, issue #12 (`be-12-01`).
- **2026-08-07** — **A created object's id is recovered by tree diff even when cmux prints one — printing an id is not a reason to skip `recoverNewId`.** `cmux browser open` is the one creation verb that prints its result (`OK surface=surface:6 pane=pane:5 placement=split`), and the printed ids are **positional refs**, which this repo may never persist and which were observed renumbering mid-session. Parse such a line only for non-identifying tokens (`placement`), log them, and discard. A fixture modelling such a verb must print the positional form verbatim, so an implementation that parses the id instead of diffing produces a non-UUID and fails. *Why:* the 2026-08-02 "all created-object id recovery goes through a tree diff" rule was justified by "no verb prints its id"; one now does, and the rule survives for a different reason (UUID-only persistence) that a future reader would otherwise not reconstruct. Source: ADR-019, issue #12 (`be-12-01`).
- **2026-08-07** — **Every family of task-controlled bytes gets its own import-firewalled reducer module, and the "raw bytes never leak" claim is proven by a seeded-marker mutation test, never by inspection.** `triage.mjs` established the shape for screen frames; `browser-evidence.mjs` repeats it for browser console output. Rules: the reducer imports nothing from the repo and is imported by no decision module (`ladder`/`triage`/`contract`), asserted by a source-text test **in both directions**; exactly one wrapper returns the raw bytes and a test asserts it has exactly one call site (a JSDoc is a comment, not a control); the reduction is a count plus a closed enum, never a message; an unrecognized shape fails toward the *unsafe* reading; and a test seeds a unique marker into the hostile fixture and asserts it appears in neither the produced JSON, nor stderr, nor any file under `stateDir`/`taskDir`. **Sibling rule:** for an error family whose *detail* is influenced by the untrusted side, log the **code** only, shape-guarded to a closed pattern, and note the deliberate divergence from the house `err.message` pattern at the definition site — truncating or sanitizing the detail is not a substitute, because it bounds volume, not content. *Why:* "never logs the untrusted bytes" is vacuous unless removing the reducer fails a test (2026-08-02 mutation rule), and the second instance of a pattern is where it becomes a convention rather than a one-off. Source: ADR-019, issue #12 (`be-12-03`).
- **2026-08-07** — **A create verb that silently *reuses* an existing target needs a pre-create authority scan, and a critical section that spans a spawn needs a stated spawn budget under the lock's own stale threshold.** `cmux browser open --workspace` stacks into an existing pane (`placement=reuse` — live-observed landing even in a terminal-only worker pane, 2026-08-07 §7.4 pass) [the "stacked surfaces are both undrivable" observation that originally justified this was falsified on build 102 — both members drive fine there; the rule stands on the stacking itself: a wrong adopt's `goto` navigates a rendered document away, and a stacked preview hides what it stacked onto], so "create because we have no record" is a data-loss operation, not an idempotent one — verify a creation verb's collision behavior live before treating a duplicate as merely cosmetic. Where the guard is a lock: `withRecordLock` **steals** any lock older than `LOCK_STALE_MS` without checking holder liveness, and `cmux()` passes `opts.timeoutMs` straight to `spawnSync` where it is undefined by default — so every spawn inside the section carries an explicit bound, the worst-case sum is stated as an invariant comment at the lock site, and a post-side-effect idempotence re-scan detects the stolen-lock loser so it abandons rather than commits. Ship the budget **and** the detector: a budget cannot cover a misbehaving spawn timeout, and a detector cannot prevent the window. Prefer failing closed to adopting an unrecorded object whose misidentification would destroy data. *Why:* the lock alone read as sufficient until the stale-steal semantics and the unbounded `tree()` were traced together. Source: ADR-019, issue #12 (`be-12-02`).
- **2026-08-07** — **A probe that verifies a CLI verb's *success* does not verify the RPC method name a design decides to gate on — capture `capabilities --json` itself before writing a capability check, never infer the dotted name from the verb's own spelling.** `browser.open` was written into both ADR-019 and a `conventions.md` entry as a live-verified capability name; the live probe that grounded #12's design ran `cmux browser open …` successfully many times but never separately ran `cmux capabilities --json`, so "the verb works" was silently read as "the RPC method exists under this name." It doesn't — 0.64.22 has no bare `browser.open` (only `browser.navigate`/`browser.wait`/`browser.errors.list`/`browser.screenshot`/`browser.open_split`, etc.), and the check would have permanently, silently disabled the shipped feature. Caught by two of three adversarial-panel reviewers, then confirmed live. This is the third instance of the same failure shape in this epic — `new-surface`'s guessed method at #6 (2026-08-02 entry), `top --format tsv`'s invented header row at #11 (2026-08-06 entry) — each time a design trusted an *assumption about the mechanism* behind an observed success rather than observing the mechanism directly. *Why:* three instances make this a pattern worth naming on its own, not just re-deriving the existing "never gate on a guessed method name" rule each time: a live probe's checklist must include capturing the *introspection* surface (`capabilities`, `--help`, schema dumps) as a **separate line item** from exercising the *behavior* surface, because a design will use the latter to infer facts about the former unless the probe already answered it. Source: ADR-019 correction, issue #12 (post-panel fix-round).
- **2026-08-07** — **A frozen live capture must record the full producing invocation (the exact argv), not only the output bytes — and the live-acceptance pass must drive the SHIPPED wrappers, never hand-typed equivalents.** be-12-01's wrappers shipped emitting `browser <sub> <surface>` while real cmux 0.64.22 parses `browser <surface> <sub>`; every output literal in the fixture WAS a genuine live capture (`No browser errors`, error codes, positional-ref `open` line), but the *grammar that produced them* was transcribed from the design doc, so the fake accepted the implementation's wrong argv order and 555 green tests contained five dead wrappers — the 2026-08-02 fixture-tautology rule recurring one level up (fourth instance of the assumed-mechanism family: #6 method name, #11 tsv header, #12 `browser.open`, now argv grammar). Two rules: (1) a fixture's frozen capture is the pair (argv, output) — checking in the output alone re-opens the tautology; (2) §7.4-style live passes run `node -e` through the shipped wrapper functions end to end (open→goto→wait→errors→screenshot→reduce), because hand-typing the verbs validates the platform, not the code. The same pass also caught `close-workspace` growing a required `--workspace` flag and `close-surface` refusing browser surfaces outright (`browser <id> tab close` is the working form) — platform drift between the scout's build and ship's build is real; the live pass is the only gate that sees it. Source: issue #12 (`be-12-03` fix-round 2), live-pass-findings.md.
