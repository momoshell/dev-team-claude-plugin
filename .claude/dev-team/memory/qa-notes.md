- **2026-08-01** — Contract files (`handover-spec.schema.json`, `coder-return.schema.json`) are the highest-value place to add tests when they change — `schema.test.mjs` already asserts their shape. *Why:* these are the spec contract between leads and coders; a silent break there breaks every downstream handoff, not just one task.
- **2026-08-01** — Every negative-case suite needs its **positive fixtures asserted first**: a validator that rejects everything passes 100% of a negatives-only suite. Assert the valid fixtures return zero violations before any mutation, build each negative as `structuredClone(base)` + ONE mutation, and assert the violation's `path`+`keyword` (exactly-one via deepEqual where the mutation is single). *Why:* the hand-rolled cmux validator makes every downstream "validates against the schema" claim vacuous if it under-checks; presence of a negative test is not coverage — the 1a deep review's only Must-fix in contract.mjs was exactly an under-check no negatives caught.
- **2026-08-01** — Contract files under deep-review-by-default now include `scripts/cmux/*.schema.json`, `roster.default.json` and `scripts/cmux/contract.mjs` (added to `config.md` review_defaults) alongside the two root schemas. The cmux schemas are policed by the **positive keyword-budget allow-list** in `test/schema.test.mjs` (not `COND_KEYS`), and constant↔schema agreement is pinned by drift guards in `test/cmux-contract.test.mjs`. *Extends the 2026-08-01 "contract files are the highest-value place to add tests" entry.*
- **2026-08-02** — **For a conjunctive predicate, a row matrix is not coverage — name the degenerate implementations the suite must fail.** When a classifier's output is `A ∧ B ∧ C`, one-factor-per-row fixtures leave every term unexercised (an implementation checking only `A` passes the whole matrix). Required shape: one positive asserted first; one negative per term with the *other* terms held true; and an **independence sweep** — a cross-product of every input the predicate must ignore × every evidence state, asserting the output as an equation with a **hand-written oracle that shares no code with the implementation**. Ship the two degenerates (permissive: `completed ⟺ existsSync(path)`; reject-everything) as a named comment block in the test file so the reviewer's vacuity lens is runnable by inspection. *Why:* the 1b ladder's 9-row recovery matrix could not distinguish the real `fresh ∧ envelope-valid ∧ identity-matching` from an existsSync check — same failure family as 1a's validator, one level up. *Extends the 2026-08-01 positives-first entry from validators to classifiers.*
- **2026-08-02** — **A "zero side effects on refusal" assertion is vacuous unless the positive is asserted first** — an unwired harness (empty invocation log because nothing ever ran) satisfies every such assertion. Pair each with "the happy path produces exactly one logged invocation, argv asserted", placed first in the file; assert refusal messages against the **exported constant** (re-typed literals also re-type the typo) with a source-text drift guard, and byte-pin each message once independently. Every new refusal added in review rounds needs its paired positive too.
- **2026-08-02** — **A pure-core design relocates its risk to the collector seam — test the seam with the real filesystem, in the unit the core compares in.** Making the ladder a pure function of `(records, fsState, tree, now)` made the matrix cheap to test and left `collectFsState` untested by construction; a seconds-vs-milliseconds (or `lstat`-vs-`stat`) bug there makes every pure-core freshness test pass while the live system treats all evidence as fresh. At least one test writes real temp files, sets sub-second mtimes via `utimesSync`, runs the production collector, and asserts equality in `mtimeMs`.
- **2026-08-03** — **Mutation-testing runs alone in the shared working tree — never concurrently with reviewers or coders.** The 1d gate launched `test-engineer` (applies/reverts mutations) in parallel with `code-reviewer-deep` (reads the same files); a reviewer can read a transient mutation and report a false finding, so any reviewer finding matching a known mutation had to be re-verified against the final tree. Sequence them, or give the mutation runner a worktree. Companion hazard: **reverting a mutation on uncommitted work must restore from a saved backup, never `git checkout --`** — HEAD lacks the uncommitted change, so checkout strips the change under test along with the mutation (near-loss on 1d's hooks.json; recovered from the pre-mutation read). Save a byte copy before the first mutation; end with `git status --porcelain` + full suite to prove restoration.
- **2026-08-03** — **Parallel coders sharing one working tree must not run the full suite mid-wave** — a neighbor's half-finished edit flakes it (e.g. a test asserting content of a file another coder is mid-edit). Per-coder validation stays scoped to that spec's files; the orchestrator runs the full suite once, inline, after the wave lands (and again at ship). Worked cleanly across 1d's 4-coder wave. *Extends the qa-gate "deterministic validation runs inline" rule to the multi-coder case.*
- **2026-08-02** — **A fake that mirrors the implementation's assumption makes the gate tautological — freeze live captures into fixtures.** `fake-cmux`'s capabilities response copied the code's own `VERBS`, so the preflight verb gate could never fail a test while being wrong about reality (live methods are RPC dotted names; every real run would have hard-stopped). Rule: when a fixture answers a "what does the real system say" question, its answer is a **frozen capture of the real system's output** (checked in beside the fixture), and divergences the specs pin (no auto-submit, no `--json` on markdown, error convention) get explicit fake-rejects-wrong-usage behavior so a drifting caller fails loudly. *Why:* 559 green tests contained a 100%-reproducible first-live-run failure — caught only by re-scouting live during review.
- **2026-08-03** — **Slices touching the cmux contract-freeze set (`scripts/cmux/*.mjs`, `roster.default.json`, `contract.mjs`, `scripts/cmux/*.schema.json`) route to a 3-reviewer adversarial panel, not merely deep review** — lenses that partition well: permission-boundary / cmux-surface-discipline / contract-coherence — with blocking-class overrides that beat majority (grant widening, focus verbs, rm-then-recreate, throw-in-never-throw path, degenerate heading match, capabilities-fixture regeneration). **Wave order: test-engineer first and ALONE, then the panel in parallel on the frozen tree** (refines the 2026-08-03 mutation-isolation rule into an ordering; reviewers also see the final tree incl. new tests). *Why:* extends the 1b precedent; at #6 the sequenced test-engineer killed two mutations the coder's suite missed before any reviewer read the code.
- **2026-08-03** — **A case-folded prefix matcher needs two specific negatives or it is unverified: an anchored-prefix case (`### Draft Handover Spec` must NOT satisfy `Handover Spec` — kills `includes()`) and a locale-independence case (subprocess-forced `LC_ALL=tr_TR.UTF-8`, `## İSTANBUL` vs `istanbul` — kills `toLocaleLowerCase()`, which is byte-identical to `toLowerCase` under the default test locale).** *Why:* every other case in a full-looking matrix passes both degenerates; same vacuity family as the 1a validator entries.
- **2026-08-03** — **Cross-file coherence tests (roster ↔ agent-definition headings) use a locally written matcher sharing no code with production, and do NOT fence-strip the definition while the return body always is** — the asymmetry is deliberate (a fence in a definition marks a template to emit; in a return body it marks an example to discount) and needs a comment. A guard importing the predicate it guards proves only self-consistency. *Why:* plan-reviewer's entire output template lives inside a fence; the import-checkSections version was unsatisfiable for a correct roster (caught by the coder's insufficiency bounce at #6).
- **2026-08-03** — **Live-GUI acceptance follows a transcript-first evidence protocol** (CLI outputs, session JSONL, on-disk artifacts; screenshots corroborating-only — sole exception: rendered-markdown live-reload, which has no non-visual signal). - **2026-08-04** — **D17 verdict blocks are now the operative gate rule (`references/qa-gate.md` rewritten, #8): the gate branches on the parsed `{verdict, findings}` enum, never on reviewer prose.** `critical`→Must-fix (blocks, even under a `verdict:"pass"`) · `warning`→Should-fix (task summary) · `suggestion`→Consider (pass with notes). Missing/unparseable block or `verdict:"inconclusive"` → re-run scoped to the diff, bounded at 2 (reuses `orchestration.md`'s amend→rebuild bound), then escalate. Adversarial panel pass = a **count** of members whose `verdict` field is literally `pass` (3→2), not a judgment call. *Why:* the lint (`return-lint.mjs`) had shipped enforcing this while the doctrine doc still told the orchestrator to read a free-text verdict line — full detail lives in `qa-gate.md` itself, this entry is the pointer.
- **2026-08-04** — **An opt-in flag needs an A/B test on the SAME fixture, flipping only the flag** — exhaustive coverage of the enabled path doesn't prove the disabled path is inert if every disabled-path test also happens to lack the flag for unrelated reasons. Shape: assert the violation fires as shipped (flag true), then flip only `record.return.verdict_block` on the identical record/body and assert the violation disappears. *Why:* `verdictBlockViolations`'s early-return-on-`false` had ~10 positive/negative tests on the enabled path and zero tests naming the opt-out itself; same "incidental coverage isn't coverage" family as the 2026-08-02 conjunctive-predicate entry.

- **2026-08-05** — **A "fixed" shell-command doc edit needs live verification under every shell the doc claims to support, not just the one that originally broke.** Issue #9's deep-review gate took 2 amend cycles: round 1 fixed an unquoted `$EXCLUDES` (silent no-op under zsh) with a `read -r -d '' -a` bash array — plausible-looking, unit tests still green (they don't execute shell prose) — but the array syntax itself is bash-only and hard-broke under zsh (`read: bad option: -a`, exit 128) and POSIX `sh` (no process substitution, exit 2), i.e. it failed under the exact shell the doc's own prose named as "this environment's shell." Caught only because the reviewer re-ran the fixed snippet empirically in bash+zsh+sh rather than trusting the coder's self-report or the passing test suite (structural tests assert the prose exists/is-consistent, never that embedded shell snippets execute). Round 2's fix (`tr '\n' '\0' | xargs -0`, no arrays, no process substitution) was verified the same way and held. *Why:* generalizes the "mutation-check don't eyeball" doctrine to a *second* dimension — a doc-embedded command needs execution-verified portability across its claimed shells, since structural/prose tests cannot see a shell-syntax bug at all.
- **2026-08-05** — **A deny-list for filtering untrusted strings into a shell context is a hole, not a fix — even after the "obvious" characters are added.** Same gate: round 1's mitigation for hand-appended `config.md noise_globs:` entries was "single-quote each entry, skip any containing whitespace, `$`, backtick, or `;`" — the deny-list omitted the *only* character that actually breaks single-quoting (`'` itself; `dist/**';id;'` breaks out and executes `id`), while the denied characters were all already inert inside correct single quotes. Round 2 replaced it with an allow-list (`[A-Za-z0-9._/*-]+`, reject anything not fully matching) plus, independently, restructuring the composition itself (`xargs -0`, NUL-delimited) so injection is structurally impossible regardless of the allow-list. *Why:* extends the 2026-08-01 "prefer a whitelist to a blacklist" convention (`conventions.md`) to shell-composition specifically — a reviewer must check what a deny-list *admits*, not just what it lists.
