## 1. Problem / goal

Make ADR-024's ledger-as-mirror real for the paths that already exist, so one shop-floor run reads back as a trail: phases in order, agent sessions with a deduped cost split, gate results verbatim, boundary evidence, and liveness. Constraint the issue states and I keep: **no behavior change to any instrumented path.**

The issue's framing understates three things, all confirmed: the usage mechanism it names does not exist (`agent_end` carries no token keys), the tool-event mechanism it names cannot see denials (`PostToolUse` fires only on success), and the producer it assumes (stream-json / a worker hook) is unavailable in a cmux pane. The corrected design is **one parent-side emitter reading raw records the worker already writes** — which is what ADR-024 actually asked for.

## 5. Architecture

### 5.1 Two new modules, one seam

```
scripts/factory/emit.mjs        (new) the only thing call sites touch: never-throwing facade
                                 + run sidecar (adw_id, phase cursor, seq counters, gate attempts,
                                   billed accumulator, per-dispatch resolution) + run-scoped lock
                                 + CLI main (gate / stats verbs)
scripts/factory/transcript.mjs  (new) import-firewalled reducer: resolveTranscript() + usage
                                   (dedupe by message.id, last-wins) + tool_call extraction
```

Direction is the sanctioned one (`cmux → factory`); `ledger.mjs` imports cleanly on Node 20 by design. **`ledger.mjs` is not edited by #41.**

### 5.2 Keystone 1 — instrumentation is never load-bearing

`emit.mjs` is a **never-throwing** facade: every emission is wrapped, failures increment a counter and emit at most one stderr line per process. `ledger.mjs` deliberately throws when its JSONL append fails ("losing the raw record is fatal to the caller") — the emitter **swallows that**, because ADR-024 already says dispatch can never die from a missing mirror. Proven by mutation (inject a throwing handle; assert every dispatch outcome, exit code, and JSON key is unchanged), never by inspection.

### 5.2b The counters must be *readable*, or acceptance is vacuous

A never-throw facade that silently drops rows passes "phases in order, one row per dispatch" on a run that lost half its emissions. So the drop counters are a **named surface**, not process-local trivia:

- The facade keeps `{emitted, dropped, lock_giveups, resolution_ambiguous, resolution_missing, payload_keys_dropped}`.
- Every mutation flushes them into the sidecar's `stats` object (same write that persists `seq`, so it costs no extra I/O), and `teardownCmd` copies the terminal snapshot into `endSession`'s emission path as its own `log`-typed event (`level:'warn'` iff any drop counter is non-zero).
- `emit.mjs stats [--json]` reads the sidecar and prints them; **run-level acceptance (§10) requires all drop counters at zero**, and the live pass must show that verb's output.

Rationale: `ledger.stats()` already carries `mirror_errors`/`dropped_payload_keys` for the *handle*'s own failures (`ledger.mjs:1154-1157`, `:1164-1166`). #41's failures happen *before* the handle — in the lock, the resolver, and the facade's own catch — so they need their own counters and their own reader.

### 5.3 Keystone 2 — the run sidecar (`<stateDir>/ledger/run.json`)

Every `dispatch.mjs` verb is a separate short-lived process, so run identity, phase position, sequence numbers and gate attempts cannot live in memory — and per ADR-024 they must not be read back out of the mirror. They live in one parent-side raw record, created link-exclusive, mutated under a run-scoped lock (`writeFileSync(tmp)`+`linkSync`, `'wx'` lock, corrupt lock = stale — conventions.md 2026-08-02):

```
{ adw_id, repo_slug, task_slug, db_path, jsonl_path, created_at,
  phase: {name, seq, phase_id, started_at},
  seq: {event: {next, reserved_through}, phase: {next, reserved_through}},
  gate_attempts: {"<gate_name>": n},
  heartbeats: {"<claude_session_id>": iso},
  billed: {input, output, cache_write, cache_read},
  stats: {emitted, dropped, lock_giveups, resolution_ambiguous, resolution_missing, payload_keys_dropped},
  dispatches: {"<dispatch_id>": {claude_session_id, transcript_path|null,
                                 session_started: bool, sighted_at|null}} }
```

**Lock scope — reserve, release, then write (v1 had this wrong).** v1 said "one ledger handle per emit batch, opened and closed inside the lock." That is over-broad: it puts SQLite open + N inserts inside a critical section, and makes `closeCmd`'s N-row back-fill N lock acquisitions. Correct shape:

1. **Inside** the critical section (no ledger, no SQLite, no spawn): read the sidecar, allocate a **range** of `seq` (default 64, one range per kind per verb), advance `reserved_through`, atomically write (tmp + `linkSync`), release.
2. **Outside** the lock: open the handle, emit every row with an **explicit `seq`** drawn from the reserved range, close.
3. Unused reservations are simply never used. **`seq` is monotone, not gapless** — an invariant stated at the allocation site *and* in ADR-027, because nothing reads `seq` as a dense index: `listEvents` pages by `id` (`ledger.mjs:1131`) and `dumpTable` orders by natural key (`:1148`). A future reader must not "fix" the gaps.

**Failure semantics at the exact point OD-7 exists to protect.** The allocation is persisted **before** any emission. So a crash mid-batch leaves a **gap** (harmless, per above); it can never leave a **duplicate**, which is the one outcome `INSERT OR IGNORE` swallows silently. The reverse order (emit, then persist) would re-hand the same `seq` to the next process and lose rows exactly as v1's own OD-7 argument describes.

**Lock waiting is bounded, always.** Acquisition retries a fixed budget (e.g. 20 × 50 ms ≈ 1 s), then **gives up**: increments `stats.lock_giveups`, drops that emission, and emits **at most one** stderr line per process. Never an unbounded wait — an instrumentation lock that can block a dispatch verb *is* instrumentation becoming load-bearing (§5.2). A lock file older than a stated stale threshold is broken and stolen, per the house rule; the sidecar RMW is short enough that no spawn ever occurs under it (contrast the budgeted spawn-under-lock case, conventions.md 2026-08-07).

The sidecar also gives `recordGateResult` a real `attempt` (its `UNIQUE(adw_id, gate_name, attempt)` + `INSERT OR IGNORE` silently drops collisions), makes phase transitions idempotent (`dispatch` fires `building` on *every* dispatch), and carries `db_path` — `defaultDbPath()` is CLI-only, library callers must pass it.

### 5.4 Session identity and transcript resolution (B4, incremental)

- **`dispatchCmd`**: `claude_session_id = record.dispatch_id`, known before the pane exists. Emits `recordEvent{agent_start,{role,model,dispatch_id}}` immediately, and records `dispatches[dispatch_id] = {claude_session_id, transcript_path:null, session_started:false}` in the sidecar.
- **`awaitCmd` poll loop** (already ticking every `AWAIT_TICK_MS_DEFAULT = 4000` ms, `dispatch.mjs:1788`/`:2015`, overridable via `deps.tickMs`): on each tick, for each unresolved dispatch, call `resolveTranscript`. **First sighting wins and is pinned in the sidecar** — never re-resolved, so a transcript later forked, rotated, or duplicated cannot move the answer. On first sighting: `ensureAgentSession()` → `startAgentSession({adw_id, dispatch_id, role, model, claude_session_id, transcript_path, started_at: record.bound_at ?? record.created_at})`, flip `session_started`, then emit the heartbeat (ordering matters: `heartbeat` is an `UPDATE … WHERE adw_id AND claude_session_id`, §3.12, so the row must exist first).
- **`closeCmd`**: `ensureAgentSession()` again as an idempotent fallback (a dispatch that was never awaited, or whose transcript appeared only at the end, still gets its row with `transcript_path` resolved-or-`null`), then the usage/`tool_call`/envelope back-fill.

Why this beats close-time resolution (v1): it removes the close-time ambiguity window entirely, survives rotation, makes OD-3's heartbeat target reachable at all (§3.12), and lets the reducer read incrementally later — the liveness Fork A's "hybrid hook" was reaching for, with **zero new hook files**.

**Trust framing, honestly stated.** A parent-derived id is *not* the same as a trustworthy transcript. A same-uid, Bash-capable worker can append fabricated assistant-shaped lines to its own transcript file, whose path it can derive under B4 exactly as under B1/B2. What the exactly-one-match rule buys is that ambiguity degrades to **denial** (no row, one counted log line), never to a forged row silently replacing a real one. Adequate here, and stated in the ADR rather than overclaimed — borrowing the posture the neighbouring module already publishes about itself: **this is a cost ledger, never an audit trail** (`task-cost-log.mjs:66-67`).

### 5.6 Abnormal exit, finalizers, and stale open rows (new)

ADR-027 claims to extend ADR-024's finalizer rule, so #41 owes an answer here rather than an omission.

- **Who installs the finalizer.** `installFinalizer` is opt-in and never installed at import (`ledger.mjs:1174`, `:1202`). #41's emitters are short-lived, single-batch processes, so the facade installs it **only** in the one verb with a genuinely long-lived process and an open session: **`awaitCmd`** (which can sit for up to `AWAIT_CAP_MAX_S = 600`s and is the realistic `SIGINT` target — a human pressing Ctrl-C on a waiting dispatcher). It is **not** installed in `workspace`/`dispatch`/`phase`/`close`/`teardown`/`status`, whose lifetimes are milliseconds and whose interruption leaves nothing a finalizer could improve. The finalizer sets `process.exitCode = 128+signum` and re-raises (`:1314-1317`) — so it **does** change `awaitCmd`'s exit code on a signal. That is pre-existing `ledger.mjs` behavior on a path that was already terminating abnormally, and it must be called out in be-41-04's spec and asserted (an interrupted `await` still exits 130 on SIGINT, not 0) so it is not mistaken for the "no behavior change" violation.
- **Stale open `agent_sessions` rows.** A timeout, a crashed pane, or an orchestrator-abandoned dispatch that never reaches `closeCmd` leaves `ended_at = null` forever; no finalizer covers this, because `installFinalizerImpl` reconciles **sessions and processes**, not agent sessions (`:1274-1313`). #41's answer: **`teardownCmd` is the reconciler.** It reads the sidecar's `dispatches` map, and for every entry with `session_started && !ended`, emits `endAgentSession` with whatever the reducer can compute (or the ten required numeric fields as explicit `null` when the transcript was never sighted). A run that never reaches `teardown` at all keeps its stale row — **named as an accepted limitation**, visible because `ledger sessions` shows the parent session's own terminal status.
- **`SESSION_STATUSES.'fail'` is unreachable from #41's mapping, deliberately.** `endSession` maps ok→`'ok'`, refused→`'aborted'`, so `'fail'` is never produced by a normal teardown. That is **intentional and stated**: `'fail'` is reserved for the finalizer's abnormal-termination path (`ledger.mjs:1295` emits exactly `status:'fail'`), which is the only writer that can honestly claim the run died rather than ended. A teardown that mapped some outcome to `'fail'` would make the two indistinguishable and destroy the one signal the finalizer exists to produce.

### 5.7 Interface contracts (identical text goes in producer and consumer specs)

**C1 — GateResultTuple.** `gates.mjs buildReport` (`:502-508`) yields `{task, slice, checks[{item,ok,hard_fail,note}], hard_fail, violations[{item,hard_fail,note}]}`. The caller supplies the four missing keys:
- `adw_id` ← sidecar; `phase_id` ← sidecar (`null` when degraded — explicit `null`, never omitted)
- `gate_name` = `` `${report.slice}/chain-check` `` (must include the slice, or two slices' gates collide and one is silently dropped)
- `attempt` = 1-based per-`gate_name` counter from `sidecar.gate_attempts`, incremented inside the critical section
- `ok` = `report.checks.every(c => c.ok)` (`hard_fail` stays recoverable inside the verbatim `checks`)
- `checks` / `violations` pass through **verbatim, never re-shaped** (ledger comment + ADR-024).

**C2 — AgentUsage** (from `transcript.mjs`, per #40 spec §E, after dedupe by `message.id` last-wins): `billed_input_tokens=Σinput_tokens`, `billed_output_tokens=Σoutput_tokens`, `billed_cache_write_tokens=Σcache_creation_input_tokens`, `billed_cache_read_tokens=Σcache_read_input_tokens`, `raw_read_tokens=Σ(input+cache_creation)`, `raw_written_tokens=Σoutput_tokens`; `context_tokens` = last surviving message's `input+cache_read+cache_creation`; `context_window = null` (U-4). **Pinned assumption:** a worker session never spawns subagents, so **no `<session-id>/subagents/*.jsonl` walk is required for completeness** — `DISALLOWED_TOOLS` (`contract.mjs:12`, frozen) excludes `Task`/`Agent`/`mcp__*` and is always applied (`record.mjs:572,651`). **Re-entry condition:** if any role ever gains `Task`, these numbers silently undercount — so the assumption ships as a test (a `contract.mjs` drift guard referenced from `transcript.mjs`'s header), not a comment.

**C3 — TranscriptResolution:** `resolveTranscript({record, projectsDir}) -> {claude_session_id, transcript_path} | null`. Under B4 this is `findTranscript(projectsDir, record.dispatch_id)`'s scan (`task-cost-log.mjs:109-129`) with its refusal posture converted from throw to `null`: 0 matches → `null` + `stats.resolution_missing++` (expected on early ticks, so **not** logged per tick); >1 matches → `null` + `stats.resolution_ambiguous++` + one log line, **never a guess**. Never derive the project-dir dash-encoding (that module's header rule). Called once per unresolved dispatch per tick; the result is pinned on first success (§5.4).

**C4 — no shared `warnings` reader.** `ladder.reconcile().warnings` is `string[]`. `gates.mjs`'s `buildReport` has **no `warnings` key at all** (`:502-508`) — its only warnings-adjacent code folds `lintResult.warnings` into a *count inside a note string* (`:421-428`) — while the `{check, detail, severity}` object shape lives in `dispatch.mjs:1392-1393` (spec-lint warnings). So there are **three** unrelated shapes with the word "warning" in this codebase and #41 mirrors each through its own mapping function; **never one generic `warnings` mirror.**

**C5 — SignalLogEntry (new).** `relaySignals().recorded` is **not** a validated stream (§3.6): schema-invalid parsed objects are pushed into it, and the level clamp (`ladder.mjs:719`) and message cap (`:741`) apply only to `relay`. Every `recorded` entry therefore passes through this mapping before becoming a `log` event, inside the never-throw facade:
1. `typeof entry?.message !== 'string'` → **drop** and count. (Do **not** `.slice()` a non-string: inside a never-throw facade that becomes a silently swallowed `TypeError` that eats the whole batch.)
2. `level` = `SIGNAL_LEVELS.includes(entry.level) ? entry.level : 'progress'` — mirroring `ladder.mjs:719` exactly, one shared constant, never a second enum.
3. `message` = control-characters stripped, then capped at `SIGNAL_LIMITS.message_max_chars` (200) — the **same constant** `:741` uses, applied on the `recorded` path too. Strip **and** cap: sanitization bounds content, capping bounds volume, and each is a distinct surface (conventions.md 2026-08-08).
4. Nothing else from the entry is forwarded (`PAYLOAD_KEYS.log` is `['level','message']`).
5. **The relay side effect is never performed.** Asserted by counting `notify` invocations in the fake-cmux log (must be zero), not by intent.

## 9. Risks

1. **Silent row loss** (colliding `seq`, colliding `gate_name/attempt`, a duplicate `agent_sessions` insert) — mitigated by OD-7/OD-8/§5.4; each needs a test that proves the **second** write survives, not just the first.
2. **Instrumentation becoming load-bearing** — the one failure that breaks the issue's core constraint. Three concrete vectors: a throwing handle (§5.2), an **unbounded lock wait** (§5.3), and `awaitCmd`'s finalizer exit code (§5.6). Each gets its own assertion.
3. **`buildArgv` is the highest-blast-radius edit in the package.** An unsupported or mis-placed flag breaks *every* dispatch, not one row. Mitigations: U-1 as a real behavioral probe, placement before all variadic flags, and (if U-2 says preflight persists `supports`) a preflight hard stop with remediation rather than a runtime surprise.
4. **Silent drops passing acceptance** — mitigated by §5.2b's readable counters and the §10 zero-drop criterion.
5. **Accidentally shipping the unbuilt relay** (OD-9) — a zero-`notify` fake-cmux-log assertion.
6. **Worker-influenced bytes reaching an LLM-read channel** — signal `message` and tool names are the ingress points; C5's strip-and-cap plus the reducer firewall.
7. **Lane coverage: the mirror sees cmux runs only.** An `agent-tool`-mode run (the default for anyone without cmux) and a workflow run produce **zero rows**. Accepted for #41 and recorded in ADR-026 clause 6 — but **flagged for #59**: if #59 retires hand-written run prose unconditionally, a non-cmux run leaves **no record on either surface**. #59 needs either an execution-mode-conditional retirement or a kept prose fallback. Documentation/scope, no new code in #41.
8. **#59 inherits this shape.** `adw_id` granularity (§10 D1) is the decision hardest to reverse once rows exist.

## 10. Acceptance criteria (run level) + the two decisions needed from the user

**Run-level acceptance:** one real cmux shop-floor task, end to end, then `ledger sessions` / `phases <adw_id>` / `tail <adw_id>` / `procs <adw_id>` plus `emit.mjs stats` show: phases in order with no duplicate `building`; **one** `agent_sessions` row per dispatch with a **deduped** cost split and a non-null `transcript_path` for every sighted transcript; every gate with its verbatim `checks`/`violations`; tool calls back-filled per dispatch; signals as `log` rows (capped, level-clamped); reconcile rows as boundary evidence; heartbeats advancing while `await` runs; **and every drop counter at zero**. Plus: **the same run with the ledger forced to fail produces an unchanged dispatch outcome, exit code, and JSON surface.** Per #12's precedent the live pass must drive the **shipped** code paths (`node -e` through the real verbs), never hand-typed equivalents.

- **D1 — run identity.** Recommend **one `adw_id` per (repo, task) run**, minted into `<stateDir>/ledger/run.json` and retired at teardown; re-running a torn-down task starts a new run. The alternative (per-session/per-dispatch) fragments a multi-session task across rows. **Read this together with OD-7:** one `adw_id` per run is *precisely why* parallel dispatches contend for a single `seq` space and need §5.3's reservation machinery — a per-dispatch `adw_id` would have made OD-7 nearly moot at the cost of a fragmented trail. You are choosing "one coherent run trail + a locked counter" over "no counter + a fragmented trail." **Needs user confirmation.**
- **D2 — "live pids" (U-5).** Recommend **amending the acceptance criterion to "live liveness"** (agent-session heartbeats, now genuinely emittable thanks to B4) and deferring `processes` rows; the alternative costs an `adapter-claude.mjs` write path plus a path derivation the closed `env` contract does not cleanly support. `ledger kill` stays unusable for panes until then. **Needs user confirmation.**

## Proposed memory deltas

> **ADR-026 — The ledger has exactly one writer class: parent-side processes. Worker facts enter by parent-side reads of raw records; the worker's Claude session id IS its `dispatch_id`; token spend lands on `agent_sessions`, never as an `agent_end` payload; and the mirror covers cmux-mode runs only.**
> **Status:** proposed · **Date:** 2026-08-09 · **Scope:** epic #39 SF-2 (issue #41), ledger producers · **Supersedes:** nothing; extends ADR-024 · **Number:** 026 free (grep across `scripts/`, `tasks/`, `.claude/`, `test/`, `docs/` + every #39 sub-issue body).
> (1) **Instrumentation is never load-bearing:** the emitter is a never-throwing facade — no ledger failure, and no *waiting* for a ledger lock, may change any dispatch outcome, exit code, or JSON surface; `ledger.mjs`'s deliberate JSONL-append throw is swallowed, counted, and logged once (ADR-024: dispatch can never die from a missing mirror). The counters are a **readable surface** (`emit.mjs stats`, plus a terminal snapshot event at teardown), because a silent-drop facade otherwise passes acceptance on a run that lost half its rows.
> (2) **No ledger writer ever runs inside a worker's process tree** — a worker-side hook writing the mirror would hand a `dontAsk`, Bash-capable agent a write path into parent-side trace state and would demand Node ≥ 24 inside the pane. A future worker-side hook that writes **raw records** into the reserved-but-unconsumed `DEVTEAM_SIGNAL_LOG`/`DEVTEAM_TASK_DIR` plumbing, for the parent to read and validate, stays **permitted** under this clause — the signals channel is already exactly that shape.
> (3) **Session identity is the dispatch's own parent-minted id:** `claude_session_id = record.dispatch_id`, passed to the worker as `--session-id` from `buildArgv` (`record.mjs:639-679`, the only argv source). `dispatch_id` is already a `randomUUID()` v4 (`record.mjs:155`) pinned to a strict UUID pattern (`dispatch-record.schema.json:10`), unique per dispatch and never reused, so this needs **no new record field and no `schema_version` bump** — the alternative (a second minted UUID carried in the record) was blocked because `flags` is a closed two-boolean object (`:22-30`), not a pass-through array. A worker-written `transcript_path` is **never** consumed; resolution is an exactly-one-match scan keyed by that id (`task-cost-log.mjs:109-129`), refusing on 0 or >1. **Honest framing:** this makes the *identifier* parent-authored, not the transcript trustworthy — a same-uid worker can append fabricated lines to its own transcript, and the exactly-one-match rule degrades that to **denial** (no row), never to a forged row silently replacing a real one. **This is a cost ledger, never an audit trail** (`task-cost-log.mjs:66-67`).
> (4) **Usage lands via `startAgentSession`/`endAgentSession`, deduped by `message.id` (last occurrence wins) before summing** — per #40 spec §E and `task-cost-log.mjs:139-159`. This **corrects issue #41's own text** ("per-turn usage → `agent_end` payloads"): `PAYLOAD_KEYS.agent_end` carries no token keys, and `--output-format stream-json` is print-mode-only while panes run interactive, so the transcript JSONL is the only usage surface in cmux mode. Completeness rests on a **test-pinned** assumption: no worker session spawns subagents, because `DISALLOWED_TOOLS` (`contract.mjs:12`, frozen) excludes `Task`/`Agent`/`mcp__*` and is always applied (`record.mjs:572,651`) — if a role ever gains `Task`, usage silently undercounts. Reproducing `task-cost.mjs`'s raw-sum overcount (#56) is the named forbidden outcome; `task-cost.mjs` is not touched here, and #56's fix should be re-scoped to converge all readers on `scripts/factory/transcript.mjs`.
> (5) **In #41, tool events are transcript-derived and back-filled**, not hook-emitted: `PostToolUse` fires only after a tool *succeeds*, so it can never see a denial, and the PostToolUse hook ADR-012's inventory named was never built. A denied call is `ok:false` here — `PAYLOAD_KEYS` untouched — because **deferring a field in a mirror is cheap** (the transcript retains the detail and can be replayed later), whereas deferring an authority field is not. This clause is scoped to #41 and is **not** a standing ban on hook-sourced tool events; clause 2 governs that.
> (6) **Lane scope: the mirror covers cmux-mode runs only.** #41's entire emission map lives in `scripts/cmux/dispatch.mjs` verbs, so the `agent-tool` lane (a first-class configured mode and the **default** without cmux — preflight failure is a hard stop, never a silent fallback: `references/cmux-dispatch.md:33`, ADR-008) and the workflow lane have **no producer** and yield zero rows. `team-build.workflow.mjs` stays unaware of cmux/ledger — pinned by `test/cmux-contract.test.mjs:604,637`, *not* by ADR-007 (which carves workflow out of cmux **interception** and does not prohibit emission); the operative reasons are that test pin plus the absence of any code-side trigger. **Note for #59:** retiring hand-written run prose unconditionally would leave a non-cmux run with no record on either surface — #59 needs an execution-mode-conditional retirement or a kept prose fallback.
> *Consequence:* five raw records feed the mirror (transcript JSONL, signals JSONL, return envelope, dispatch record, gate report); `ledger.mjs`, `team-build.workflow.mjs`, and `gates.mjs` are all unedited; `record.mjs` gains exactly one argv flag pair.

> **ADR-027 — Run identity and event ordering are parent-side facts in a run sidecar; `seq` is caller-allocated, monotone-not-gapless, and persisted before it is used; no emitter ever reads the mirror to decide what to emit.**
> **Status:** proposed · **Date:** 2026-08-09 · **Scope:** epic #39 SF-2 (issue #41), ledger ordering + run identity; #59 inherits · **Supersedes:** nothing; extends ADR-024's finalizer rule.
> Each dispatcher verb is a separate short-lived process, so `<stateDir>/ledger/run.json` (link-exclusive create, `'wx'`-locked RMW, corrupt lock = stale) owns `adw_id`, the phase cursor, the **event/phase `seq` counters**, per-gate `attempt` counters, heartbeat cadence, the billed accumulator, the per-dispatch resolution map, and the drop counters; the db path travels with it (`defaultDbPath()` is CLI-only). **Every emission passes `seq` explicitly.**
> **Why (lead with the deterministic case):** `nextSeq` seeds from `SELECT MAX(seq)` once per process (`ledger.mjs:624-643`), and **below the Node floor `max` is always 0 — so every below-floor process restarts numbering at 1 and collides with certainty, not by luck.** Above the floor, two concurrent verbs collide as a race. Either way `UNIQUE(adw_id, seq)` + `INSERT OR IGNORE` drops the loser from the mirror **and** from any later `replayJsonl`. Same shape for `UNIQUE(adw_id, gate_name, attempt)`: `gate_name` must include the slice or two slices' gate results silently collapse into one.
> **Lock discipline:** the critical section reserves a **range** of `seq` (read, bump, atomic tmp+`linkSync` write, release) and contains **no SQLite, no JSONL, no spawn**; all ledger writes happen outside it, keyed by `(adw_id, seq)`. So `closeCmd`'s N-row back-fill costs **one** lock acquisition, not N. The reservation is persisted **before** any emission, so a crash mid-batch leaves a **gap**, never a duplicate — and **`seq` is monotone, not gapless**, which is safe because nothing reads it densely (`listEvents` pages by `id`, `:1131`; `dumpTable` orders by natural key, `:1148`). A future reader must not "repair" the gaps. Lock acquisition is **bounded** (fixed retry budget, then a counted give-up and at most one stderr line) — an unbounded wait would make instrumentation load-bearing.
> **Extends ADR-024's finalizer rule** ("the finalizer sources state from an in-process registry, never from the mirror") from the finalizer to *every* emitter: a sidecar is an in-process registry that survives process death. `installFinalizer` (`ledger.mjs:1174`) is installed **only** by the one long-lived verb with an open session (`awaitCmd`), and its `exitCode = 128+signum` re-raise is asserted rather than discovered. `SESSION_STATUSES`'s `'fail'` is **deliberately unreachable** from normal teardown (ok→`'ok'`, refused→`'aborted'`): `'fail'` is reserved for the finalizer's abnormal-termination path, the only writer that can honestly claim the run died. Stale open `agent_sessions` rows (timeout, crash, abandoned dispatch) are reconciled by `teardownCmd` from the sidecar's dispatch map; a run that never reaches teardown keeps its stale row, an accepted and stated limitation.
> Heartbeats stay in-place columns at a caller-driven ~15s, emitted only from `awaitCmd`'s poll loop (`AWAIT_TICK_MS_DEFAULT = 4000`, `dispatch.mjs:1788`) — no timer — and their meaning is "last observed alive by a parent poll," never a death signal. They are only possible at all because ADR-026 clause 3 makes `claude_session_id` known at dispatch time: `heartbeat` UPDATEs `WHERE adw_id = ? AND claude_session_id = ?` (`ledger.mjs:956`).
> *Consequence:* #59 inherits `adw_id` granularity = one run per (repo, task), retired at teardown — and inherits the coupling that this choice is what makes a locked counter necessary.

**→ `.claude/dev-team/memory/conventions.md`** (candidates, only if #41 ships as designed)

- **A latent single-process assumption becomes a defect the moment a second caller exists — and db-derived sequence allocation is the canonical instance. Lead with the deterministic case, not the race.** `nextSeq`'s `MAX(seq)`-per-process seeding was correct for #40's single CLI and silently loses rows under #41's multi-process emitters — *with certainty* below the Node floor, where the max is always 0, and *probabilistically* above it. Fix caller-side (explicit parent-allocated seq, **range-reserved** inside a tiny lock and **persisted before use**, with all store I/O outside the lock), not by widening the store: the store's uniqueness constraint was right, the allocator's scope was wrong. Corollary: a caller-allocated sequence is **monotone, not gapless** — state that at the allocation site and prove nothing reads it densely, or a later reader "fixes" the gaps and reintroduces the collision.
- **Before consuming a returned collection as validated, read what the producer actually pushes into it — a name like `recorded` is not a contract.** `ladder.relaySignals` returns `{relay, recorded, dropped}`; schema-**invalid** entries land in **both** `recorded` and `dropped` (`ladder.mjs:711-717`), and the level clamp (`:719`) and message cap (`:741`) are applied only on the `relay` path. A consumer that treats `recorded` as the validated stream inherits unvalidated, unbounded, worker-authored bytes — and inside a never-throw facade, calling `.slice()` on a non-string `message` becomes a silently swallowed `TypeError` that drops the whole batch. Re-derive the guard on your own path (type check → clamp → strip → cap, reusing the producer's own constants) and **assert the side-effecting sibling stays unwired** (zero `notify` calls in the fake-cmux log), don't just intend it.
- **Reuse an existing, already-validated identifier before minting a new one — a schema's closed shape is a design signal, not an obstacle to route around.** #41's session capture began as "mint a UUID, carry it in the dispatch record" (a `schema_version` bump on a frozen, security-audited contract, plus a contract-freeze review) and collapsed to a one-line `buildArgv` edit once someone checked that `dispatch_id` was **already** a parent-minted, pattern-validated, never-reused v4 UUID with the exact properties the new field would have had. The tell was that the intended carrier (`flags`) turned out to be a closed two-boolean object with `additionalProperties:false` — i.e. the contract had already said "no arbitrary pass-through here." When a design needs a new field on a frozen contract, first enumerate the fields that contract already guarantees.
- **Deferring a field in a *mirror* is cheap; deferring one in an *authority* is not.** Because every mirror row traces to a raw record that still exists, a distinction you cannot yet make safely (denied-vs-failed tool calls, pending a `PermissionDenied`-under-`dontAsk` probe; `transcript_path` on a column with no back-fill writer) can be replayed in later. Prefer the narrow row now over widening a closed contract on an unverified platform mechanism.
- **A never-throw facade owes a read surface for what it swallowed, or its acceptance criteria are unfalsifiable.** "Phases in order, one row per dispatch" passes on a run that dropped half its emissions unless the drop counters (lock give-ups, ambiguous resolutions, swallowed throws, dropped payload keys) are persisted somewhere a human reads **after** the run — a stats verb and a terminal snapshot event — and unless run-level acceptance requires them to be zero.
