# Lean provider retry and turn usage

## Minimal implementation
- Change only `crew/lean.mjs` and the lean bridge tests in `crew/start.test.mjs` (a focused new lean test file is also fine). Leave the listed old paths, `crew/headless.mjs` behavior, and the suite stage untouched.
- In `runSeat`, keep the issued id, prompt, return path and effective definition unchanged across provider attempts. Scope recording state (`header`, `relayed`, `recordError`, guarded append) to each attempt. Preserve the initial `<id>.jsonl` name and exclusive creation; use deterministic distinct retry filenames such as `<id>.retry-1.jsonl`. Each call to existing `runAcpSeat` already creates a new client/session and tears it down before returning; do not resume/reuse the failed session.
- Import `acpProviderFailureKind`, `acpTextReset`, `providerRetryDecision`, and `PROVIDER_RETRY_TOTAL_WAIT_MS` from `./headless.mjs`. The shared decision consumes `PROVIDER_RETRY_MAX`, backoff, reset settle and total-wait policy; do not duplicate their values or classifier. Use `const kind = acpProviderFailureKind(turn?.refusal?.errorKind)` when routing a refusal. Recompute the reset from the current refusal message, never from a previous attempt. As in the old policy, an unreadable/absent rate-limit reset is declined rather than guessed.
- Add injectable `now` (epoch milliseconds, default Date.now) and async-capable `sleep(ms)` dependencies. Consult the shared decision with attempts spent and cumulative wait for this logical seat turn. Await its wait before retrying; consume one attempt per replacement. Account for actual elapsed wait (at least the intended wait), and refuse a replacement if an oversleep crosses the total bound. Auth/unknown refusals, missing stop reasons, thrown turns and recording errors still fail immediately with the existing error cause and no envelope read. Recording errors take precedence over provider routing.
- Append `{type: 'turn', stopReason, usage, refusal}` exactly once for every returned turn, outside the refusal-only branch, with existing null normalization. Keep the serialization fragment `usage: turn?.usage ?? null`. The runtime append must participate in the trusted relayed copy (or be included separately in the expected disk bytes); the intactness comparison must still reject rewritten/deleted recordings. Only the accepted attempt's trusted recording proves skills; failed attempts cannot lend it proof.
