# Lean lanes in the visualizer

## Findings / boundaries
- The sessions route reads only `feed.listRuns`; compose a second read-only source there, not in the ledger (`visualizer/server/server.mjs:632-653`, `visualizer/server/feed.mjs:6-10`). Leave ledger-feed, shapeRun, ledger schema and all crew code unchanged.
- Old journal selection requires ledger/run.json and reads the root journal (`visualizer/server/journal-source.mjs:36-67`). Add an early, positively identified lean branch; leave the existing fallback/verification rules intact for old runs.
- Actual lean rows have event/lane/stage but usually NO timestamps; review emits a nonterminal `verdict` and success ends in `pr`, not a final verdict (`crew/loop.mjs:83-99`, `crew/loop.mjs:234-241`, `crew/loop.mjs:275-280`). Never invent time, heartbeat, tokens, settlement or PR merge state.
- `showLane` prefers live, otherwise the newest sibling `<lane>.archive-*`, and orders seat turns numerically (`crew/show.mjs:125-135`, `crew/show.mjs:178-182`). Contrary to the brief's attribution, this checkout's showLane does not search the separate archive root. Disk inspection confirmed archived lean lanes at `~/.crew-journal-archive/dt-<lane>/<lane>/task/lean.json`; support that layout too, without importing show/lean/loop into the server.
- Current detail/probes assume old returns/events and timestamped trajectories (`visualizer/web/src/App.svelte:77-86`, `visualizer/web/src/lib/RunDetail.svelte:62-77`). Keep that path intact and branch only on a new `source: 'lean'` discriminator.

## Minimal implementation
1. Add `visualizer/server/lean-source.mjs`, Node built-ins only. Discover safe lane names below crewRoot/dt-<lane>, requiring a parsed task/lean.json whose id matches the lane and a valid crew.json members object. Resolve live first, then newest sibling archive, then the same forms below the separate archive root; deduplicate by lane. Default archive root: `join(dirname(crewRoot), '.crew-journal-archive')`; allow injection for isolated tests. Resolve paths from the discovered directory, NEVER the spec's old cwd/taskDir. Fence realpaths (including session files) and reject traversal; failed/malformed reads carry errors/reasons, not fabricated success.
2. Give list rows `source:'lean'`, `adw_id:'lean:<lane>'`, `goal:<lane>`, `repo_slug:'dt-<lane>'`, `latest_stage`, `status`, `reason`, `running`, `phases`, `seats`, and a `pending` map for unmeasured values. Preserve recorded stage order/repetitions; latest_stage is the last recorded nonempty stage. A final verdict copies status/reason verbatim; a final pr with recorded PR data means done (not merged). An earlier reviewed verdict must not settle a later open stage. Without terminal evidence status is running in the journal/open-record sense only, never proof of a live process. Empty/unreadable journals are unknown with reasons. Unrecorded timestamps/durations/usage/runtime/configuration remain null with reasons; do not date rows using mtime, synthesize stage times or count tokens from text.
3. In server.mjs merge these rows with the existing filtered feed result, retaining every ledger row/value/order and metadata. Apply mode/status/since/until filters to lean rows too (unknown dates do not satisfy time bounds); a missing/degraded ledger must not suppress lean rows. Keep the existing ship resolver on ledger runs; lean ship state is unmeasured with a reason unless explicitly recorded, never guessed from a branch. No changes to createLedgerFeed's public contract.
4. In createJournalSource, route positively identified lean requests to the same lean resolver/reader before the old path. Require matching synthetic identity when supplied, read task/journal.jsonl (not the decoy root journal), preserve original fields plus existing index/line_number/channel metadata and malformed-line accounting. Keep absent plan/acceptance metadata honest. A mismatched lean identity must not fall through to an unverified old-path journal.
5. Add GET/HEAD `/api/seat-sessions?repo_slug=...&task_slug=...&adw_id=lean:<lane>&role=...` to ROUTE_PARAMS and server dispatch, using that same resolved lane. Response: `{role, sessions:[{file,raw}], absent}` plus optional source/error metadata; file is lane-relative (e.g. task/lean/planner/<lane>.planner.2.jsonl), raw is the unchanged recording text. Validate role against safe crew members. Read only the requested role, ordered by numeric turn; include normal, repair and retry recordings. Missing/empty roles/files have explicit absence/read-error reasons. No client-supplied file path, process execution or lane writes; wrong identity/unsafe role must not expose another recording.
6. Add getSeatSessions to api.js and a small LeanRunDetail.svelte plus pure lean.js view helper. App.svelte selects it only for lean rows and skips old returns probes for those rows. Show lane, journal stages/checks/verdict in recorded order without requiring timestamps, recorded seats and a role selector that loads raw sessions as escaped text. Subscribe to journalPulse; guard stale async responses on lane/role changes. Display read errors and null-with-reason fields. Do not route lean rows through old trajectories, returns or ledger events. Old RunDetail.svelte stays untouched.
7. Add lean-only status/activity handling in fleet.js (do not reinterpret ledger rows): display stopped/done/reviewed/unknown reasons and distinguish an open journal from measured liveness. TaskList.svelte may add lean-only labels/reasons for missing phase/time/usage/setup; keep its ledger rendering unchanged. No fabricated heartbeat to light the Live now tab.
