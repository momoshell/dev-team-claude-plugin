lists journal rows with no times, and the only waterfall (`PhaseGantt.svelte`, laid out by `timeline.js`

`visualizer/server/lean-source.mjs` `summarize` builds `run.phases` from the journal's stage-start/stage-end
rows with `started_at`/`ended_at` taken from each row's `at`.

Show a waterfall of the lean run's stages in `LeanRunDetail`: one bar per phase, offset and width from its
recorded times, labelled with the seat that answered it. Reuse `layoutTimeline` (or the parts of `PhaseGantt`
that fit) rather than writing a second layout. Invariant: a time nobody recorded is shown absent with its
reason, never as a zero, never at the origin, never stretched to now.

### gate-red-for-the-right-reason.md

description: A baseline-red check must fail because the behaviour is missing, never because the gate throws
metadata:

---

Before returning a plan, run the gate on the unchanged tree and read every FAIL reason. Each must name the missing behaviour. A gate that throws (a wrong call signature, a missing required argument) prints FAIL for every id and still passes the baseline check, then blocks the builder for good. Exercise the real module through its public entry points and pass every required argument.


### fixtures-from-recorded-input.md

---
name: fixtures-from-recorded-input
description: Fixtures for anything that classifies seat or tool input must use the recorded shape, not the textbook one
metadata:
  type: feedback
---

Seats rarely issue a bare command. Claude seats prefix commands with cd <tree>; and chain an edit with a test run, so the exit status is the last command's. A detector tested only on bare commands misses nearly every real case. Base fixtures on recorded commands from session files, and test a chained case.


### nudges-fail-open.md

---
name: nudges-fail-open
description: A steer, hint or reminder fails open: act only on a certain match
metadata:
  type: feedback
---

When the change nudges a seat (refuse-and-redirect, a hint, a reminder) rather than enforcing a boundary, write the acceptance as: act on a certain match, do nothing when unsure. A false positive blocks or misleads a legitimate call and is a defect. A miss in an uncommon shell form is accepted. Name the measured common forms that must be caught.


### mutations-must-bind.md

---
name: mutations-must-bind
description: Each acceptance check needs a kill-mutation its own fixture distinguishes
metadata:
  type: feedback
---

Declare one mutation per check, with a find string that occurs exactly once in the file. Prefer flipping the core predicate. Removing a guard that another guard already covers is an equivalent mutant: it survives and the proof fails. The gate prints one FAIL <id> line per failing acceptance id. In the repo test files, give each acceptance outcome a top-level test() that names its kill in a // MUTATION: comment.


### honesty-doctrine.md

---
name: honesty-doctrine
description: Unknown is null with one closed reason; instrumentation never throws into its caller
metadata:
  type: feedback
---

An unmeasured value is null with a reason, never a guess and never a zero. Rates carry their denominator. Journal and session writes are guarded and must never fail the caller. A tool that cannot measure something prints that it could not, rather than reporting a clear.


### runtime-boundaries.md

---
name: runtime-boundaries
description: Zero runtime dependencies, plugin-relative paths, enforcement files are high-tier
metadata:
  type: feedback
---

Nothing under crew/ or scripts/ imports a package. Only the visualizer has build-time devDependencies, and a node suite module must never import one (CI has no node_modules). Plugin runtime code resolves its own files from import.meta.url, never from process.cwd(); a gate is the exception and reads the checkout under test through process.cwd(). Changes to crew/loop.mjs, crew/checks.mjs, crew/acp/grants.mjs, hooks/ or docs/adr/ touch enforcement: keep them minimal and cite the ADR.
