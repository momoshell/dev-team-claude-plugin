# Architecture decision register

Every ADR number this repo has ever minted, ratified or not. **Grep here before
minting a new one** — the next free number is **030**.

That instruction is the point of the file. ADR numbers are cited from shipped
code as the authority for invariants (`scripts/factory/emit.mjs`,
`crew/drive.mjs:141`, `crew/headless.mjs`), and those citations name *numbers,
not paths* — so the register has to be findable and complete or the citation
resolves to nothing. It previously lived in `.claude/dev-team/memory/`, the
tree v0.2.0 declared retired, which is what #128 was filed to fix.

A number is burned once proposed. Two decisions have collided here before
(#128, and the 2026-08-04 entry that caught it live), so the index below lists
**proposed and abandoned numbers too** — a number claimed by a parked epic is
not free.

### The 014–019 tangle, recorded so nobody re-derives it

The parked deterministic-backbone epic (#23) proposed **ADR-014…019** in its v1
package; its v2 consolidated them down to **014/015/016**, judging 015 and 019
consequences of 014/016 and 017 an implementation detail. The cmux-mode epic
then minted **017/018/019** for unrelated decisions, deliberately skipping
014–016 as claimed — see the legacy log's 2026-08-04 entry, which exists
precisely because that session first picked 014 and caught the clash.

#23 was closed 2026-08-13 as answered (crew v3 is the shipped deterministic
backbone), so 014/015/016 record decisions that were never ratified and never
built. **They stay burned.** Reusing a number whose proposal is quotable in a
design package is how a citation silently resolves to the wrong decision.

## Note on scope

ADRs 001–022 are almost entirely about the **retired** first-generation runtime
(pane dispatch, worker plugins, the QA-gate ladder), removed in v0.2.0. They are
kept because their numbers are cited and their reasoning is still quoted, not
because they describe how the crew works today — for that, read
[`crew/README.md`](../../crew/README.md).

## Entries

- **ADR-001 — Execution substrate: custom cmux adapter, not `cmux claude-teams`.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Drive cmux via its CLI/socket behind our own adapter layer. Option A (`cmux claude-teams`) rejected: tmux shim at `~/.cmuxterm/claude-teams-bin/tmux`, gated behind `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, Claude-only, partial tmux verb coverage — cannot carry a roster, a permission model, or a return contract. *Consequence:* the orchestrator composes dispatch records and invokes adapters, never hardcodes Claude Code assumptions into the dispatcher. *Why:* every architecture of the plugin before cmux was tied to the Agent-tool model; adapters un-tie it. Revisit if: claude-teams leaves experimental and grows multi-CLI support. Source: epic #15 design ledger (D1); v1 §4.1 option A rationale, v1 §6.

- **ADR-002 — Filesystem is the data plane; the cmux socket is control plane only.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Specs in as file paths on the launch line; returns as schema-validated files; `wait-for` = doorbell; `read-screen` = diagnostics only; `send` = single-line control text only. Forced by cmux's design (events redact bodies; no payload primitive; TUIs submit on every newline). *Consequence:* structured returns are the data plane's contract in both directions — the orchestrator branches on enums (status, verdict, severity), never on prose; screen-scraping is structurally impossible. *Why:* the asymmetry (agent uploads giant JSON, orchestrator reads one byte at a time from a pane) forced this shape; it turns out to be robust. Source: epic #15 design ledger (D2); v1 §4.2 rationale, v2 §4.5.

- **ADR-003 — Completion is signalled by a four-rank ladder; events trigger rescans, never endings.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. The doorbell is a hierarchy: (0) return-file watch inside `await` — stat + `return-lint` every 3–5 s, co-primary, filesystem-only; (1) `cmux events --name notification.requested` — workspace-scoped rescan trigger, native for Claude inside cmux; (2) adapter `trap … EXIT` writes `logs/<id>.exit` sentinel and signals `wait-for`; (3) Stop hook return-gate with ≤2 block cap and its own counter, writes the blocked return on exhaustion. *Consequence:* the orchestrator's join always unblocks — by a fresh valid return, by an explicit blocked return (written by the agent, the gate, or the adapter), or by a timeout naming the pane and its log; no branch ends in silence. Self-signal dropped (prompt-dependent, deny-beats-allow makes it unreliable). *Why:* (0+1) provide liveness without hooks or socket reach; (2) is the liveness backstop for crashes; (3) enforces the return contract but never owns the signal. Unbounded block loops burn sessions; an interactive TUI never exits by itself. Source: epic #15 design ledger (D3, amended in v2 after review); v2 §4.3 rank definitions, v2.1 §B-2 attribution model. *Amended by:* 2026-08-01 Am.1 (nonce + ladder re-derivation), 2026-08-02 poll-first await, 2026-08-02 '.exit never decides completion', 2026-08-05 be-11-01 errata (the rank-1 doorbell event is `agent.hook.Stop`, not `notification.requested` — live-verified against cmux 0.64.22; see docs/trd-cmux-execution-mode.md's Superseded-since-ratification table).

- **ADR-004 — Role-station panes: the return file is the doc tab.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Judgment roles return markdown, opened with `cmux markdown open` and relocated into the producer's pane with `move-surface --focus false`. One artifact serves three roles: contract return (schema-validated), live progress view (live-reloading on disk), approval surface (rendered doc in the pane). For executors the pane closes on return; for judgment roles the pane collapses to the rendered document — focus-don't-close is the Phase-2 default (collapse-on-close is polish, gated on spike S19). UUIDs only (no positional refs persisted); re-read before acting. Placeholder is lint-invalid by construction. *Consequence:* leads and reviewers see their work live while producing it; the orchestrator never drafts-in-pane; every file is written tmp+rename, never rm-then-recreate. Fallbacks: browser surface tab, then a split pane. *Why:* one artifact instead of three (return + viewer + approval) is cheap; live reload frees the lead from refresh loops. Source: epic #15 design ledger (D7, amended in v2 for UUIDs); v1 §4.4 mechanism, v2 §4.4 amendments, v2.1 §E close-step. *Amended by:* 2026-08-03 parent-render-on-validation, 2026-08-06 collapse-on-close default (S19 passed; verified-sibling precondition — this reverses "focus-don't-close is the Phase-2 default").

- **ADR-005 — Security posture: default socket mode, orchestrator-inside-cmux, allowlist-shaped worker profiles, scoped return grant.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. `cmuxOnly` stays (the only socket mode that makes sense); `allowAll` banned; `cmux identify` preflight enforces the precondition. Worker profiles are allowlist-shaped under `dontAsk` (deny beats allow; only non-prompting mode that cannot stall). One file grant: `Edit(//<abs task-dir>/returns/**)`. Workers denied `Bash(cmux *)` at the tool layer (outside the permission system). No Task tool. Never `--dangerously-skip-permissions` or `bypassPermissions`. For pane dispatches the profile's tool universe and allow/deny rules REPLACE the role's frontmatter wholesale — never merge (frontmatter expresses the Agent-tool model, profiles express the pane model). *Consequence (resolves the latent ADR-004/005 conflict):* the one file a read-only role may write is exactly the file ADR-004 renders — they're the same file. Addendum clause: `cmuxOnly` is containment, not immunity. The socket admits any descendant of the cmux app — which includes every subprocess a worker pane spawns. Third-party code executed by allowed commands (e.g. package scripts under `npm test`) is therefore inside the socket trust boundary, and the worker-level `Bash(cmux *)` deny does not mediate it. What the default mode does buy: the boundary shrinks from the entire user account to what is deliberately run inside cmux. Residual inside-risk is cross-pane typing, screen reading, and driving logged-in browser surfaces within cmux. Operational rule: do not keep high-privilege interactive sessions — SSH to production, sudo'd shells, authenticated admin browser surfaces — in the same cmux instance where worker panes execute untrusted build code. Task workspaces are ephemeral by design; privileged long-lived panes belong outside cmux or at minimum outside any cmux instance running dev-team workers. *Why:* Tier-2 and Tier-3 specs can dispatch untrusted role prompts; permission-based containment is the only available boundary (OS sandboxing deferred). Denying cmux at the tool layer assumes workers never signal — true because the gate and adapter signal instead. Source: epic #15 design ledger (D9, amended in v2 and again in v2.1); v1 §5.4 Roster, v2 §4.6 scoped grant, v2.1 §B-1 profile replacement. *Amended by:* 2026-08-01 D9 amendment (enumerated cmux allow-list, no deny wildcard) and 2026-08-01 Am.1 (uniform --tools, web-tool loss).

- **ADR-008 — cmux is an environment prerequisite, not a preference.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. `execution_mode: cmux` means preflight failure stops the task with precise remediation; no silent degradation to Agent-tool dispatch. Two values: `cmux` / `agent-tool` (default for anyone without cmux — macOS-only app). Onboard sets `execution_mode: cmux` on a working install; pre-existing projects default to `agent-tool` and must opt in. The plugin treats cmux like git (also a macOS/Linux-only prerequisite). *Consequence:* preflight failure is loud with remediation steps; users know when they are not in cmux mode. Phase 1 spike S8 audits the installed version and gates the entire phase. *Why:* silent fallback created debugging confusion (users think they got cmux when they got Agent-tool); loud failure is cleaner. Cross-file pointer: conventions.md's 2026-08-03 entry (execution_mode canonical values cmux|agent-tool, subagent a normalized legacy alias).

- **ADR-009 — Pane system prefixes are byte-stable per role.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Static role file + static per-profile addendum + static worker plugin; per-dispatch variance via env and kickoff only; wave launching (first pane of a role warms the prefix cache; same-role siblings launch after it begins). The model receives expanded absolute literals in the kickoff (spec path, return path, dispatch id) — the kickoff is per-dispatch and sits after the cached prefix. Env vars are for shell-side consumers (adapter, return-gate, gate-mode), which expand them; the model is not a shell consumer. *Consequence:* two dispatches differing only in ids/paths produce byte-identical prompt-file content; cache hit rates stay high; rejects per-dispatch generated `--settings`. *Why:* every dispatch re-computes the session prefix for the model; caching is essential under the July-2026 token budget. - **ADR-010 — Machine-readable verdicts at both ends of the pipe.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. Reviewer returns stay markdown for the human surface but carry a fenced `{verdict, findings[]}` block inside the Verdict section — present, parseable as JSON, `verdict` in the set {pass, changes-needed, inconclusive}, every `findings[].severity` in {critical, warning, suggestion}. Shape-validated only; finding quality is never linted. The gate branches on the severity enum (any critical → bounce/escalate; only suggestions → pass with notes; missing/unparseable → inconclusive → re-run scoped to the diff), never on prose interpretation. A majority-verdict rule runs over multiple reviewers' `verdict` values. *Consequence:* the orchestrator's control flow reads the block; prose remains for the human and the doc tab; reviewer quality judgments stay agent-side and are never linted. *Why:* prose is ambiguous (does "needs work" mean bounce or amend?); enums are actionable. The severity-to-ladder mapping is critical ↔ must-fix, warning ↔ should-fix, suggestion ↔ consider. Source: epic #15 design ledger (D17); v2.1 §H verdict-block definition, §R2-3 gate branching. *Amended by:* 2026-08-03 required_sections matching semantics and the still-open extractSection shadowing exposure noted 2026-08-04.

- **ADR-011 — One shared noise-glob definition applied at read points only.** accepted · ratified 2026-08-01 at slice-1a planning · recorded 2026-08-05, issue #10. `scripts/noise-globs.json` holds a single definition of paths to filter (lockfiles, vendored, minified/generated, build output); `config.md` per-project override. Applied at reviewer bundle, cmux diff view, and handover-spec.md guidance — the three places humans read. Never at the git scope-compliance check (which stays explicitly unfiltered); never to a files_in_scope path (a dependency-bump task's only meaningful diff IS the lockfile). Every filtered bundle names what it excluded in the gate report, so the omission is visible. *Consequence:* reviewers see diffs that matter; the git check validates the full truth; filtered content is named, never hidden. Spec-lint WARNs on noise-glob matches in files_in_scope (to surfaced the intention). *Why:* filtering is a read-side convenience for humans; verification paths always see the unfiltered truth. Source: epic #15 design ledger (D16); v2.1 §G noise-filter definition, §12·10 filtering rules. *Amended by:* shipped at issue #9 (PR #33) with the spec-lint WARN later absorbed into #26.

- **ADR-012 Amendment 1 — ADR-012's "no PreToolUse hook" is worker-plugin-scoped; orchestrator-side hooks are admissible where a rule cannot express the invariant.** ratified 2026-08-12, issue #78. ADR-012's closed hook inventory and its "no PreToolUse hook in the default profile" clause govern the WORKER plugin (`scripts/cmux/worker-plugin/`, a containment surface delivered per-dispatch via `--plugin-dir`). - **ADR-023 — Roster-override persistence across `/clear` is declined; the existing two-layer precedence already covers the need.** accepted 2026-08-08, issue #30. `resolve.mjs`'s `loadRoster` already has two persistent layers below the ephemeral session override: `~/.claude/dev-team/roster.json` (personal, all-projects) and `<project>/.claude/dev-team/roster.json` (project-scoped, higher-precedence, committed by default — `.git/info/exclude`-able pre-first-commit for a personal copy). The hypothesized gap — a personal, project-scoped, uncommitted override an operator wants to survive `/clear` — is already expressible as a 3-line partial fragment in the project file (only the MERGED roster is schema-validated, so a layer file needn't carry `schema_version`/`tools`/`defaults`/`profiles`). Building a THIRD, session-tagged persisted layer was rejected: ranked below the project layer it would be silently defeated by team config; ranked above it (matching the session layer's current top rank) it becomes a top-precedence override with no `/clear` event to end it — a "why has my coder been running haiku for three weeks" footgun requiring a full writer/inspector/clearer lifecycle to be safe, none of which existed. *Consequence:* `commands/team.md`'s `roster` verb doc now points operators at the two existing files instead of offering a `--persist` flag; no new roster precedence layer, no new verb. *Why:* same family as the 2026-08-04 pane-dispatch-flip revert (needs real design, not a patch) and the "documented-then-broken control path" pattern (`execution_mode`, `keep_task_artifacts`, `noise_globs` — backend-notes.md) — a fourth knob whose entire risk surface is "operators forget it exists" belongs in that family, not shipped by default. Reopen only on a repeated real operator report, not on symmetry with the session layer. Source: issue #30, be-30-01/be-30-02, backend-lead's U-4 assessment.

- **ADR-024 — `node:sqlite` admitted at a scoped floor; the factory run ledger is THE mirror, and a mirror never originates a fact.** accepted 2026-08-08, issue #40 (plan-reviewed, revised once; shipped as `scripts/factory/ledger.mjs`). *Supersedes the factual premise* of `tasks/deterministic-backbone/architecture-package-v1.md:36` and `v2.md:233` ("JSONL, not node:sqlite — Node 20 floor"): Node 20 is EOL since April 2026, and the floor conflict is resolved by SCOPING, not a repo-wide bump — `scripts/factory/*` requires Node ≥ 24 (`NODE_FLOOR`, a verified major line: 24.15.0/darwin observed; the theoretical 22.13 minimum deliberately not claimed), CI is a two-leg matrix `["20","24"]` with `fail-fast: false`, and below floor the CLI exits 2 while the LIBRARY degrades to a fully-shaped no-op (one stderr line, `degraded:true` + `degraded_reason` surfaced by the `sessions` verb) that still writes JSONL — dispatch can never die from a missing mirror. Whole-repo bump deferred with a named re-entry condition: the first load-bearing consumer that makes the mirror non-optional (likely #59) forces it as its own decision. **One-mirror rule:** #23's unbuilt `chain.jsonl`, if Phase B ever ships, is one more raw record the ledger mirrors, never a competitor; raw records enumerated in issue #40/#41. **Invariant, time-invariant form:** "the db never originates a fact" (every row traces to a file that held it when written; no raw-record lifetime owned by the ledger; no write-back) — replaces the naive "losing the db loses nothing," which reads false once a raw record is deleted by its own lifetime rule. **Write-path posture:** ledger reads no raw record (callers pass facts confirmed through `listRecords`; the error verb `recordSourceError` is fed from `listRecords(dir,{onUnreadable})`, payload `path:keyword` never `message` — `contract.mjs` interpolates offending values into messages); UPSERT/`INSERT OR IGNORE` on natural keys; `.exit`/`.gate` never reach `sessions.status`/`phases.status` (U-4 holds in the mirror); never-prune (no DELETE/DROP/VACUUM, pinned by test); heartbeats are in-place columns, never events (the ledger owns no timer — #41 drives the rate); **the finalizer sources state from an in-process registry, never from the mirror** (a mirror-sourced guard silently loses the authoritative JSONL line on exactly the degraded tier the scoped floor exists for — caught by the round-2 scoped re-review after the first fix introduced it). Source: issue #40, do-40-02/be-40-01, ADR grep verified free incl. stale worktrees.

- **ADR-025 — Test ownership is a convention read off `files_in_scope`, not a spec field; every subagent turns in exactly one contracted deliverable.** accepted 2026-08-08, issue #18 (plan-reviewed; revised in one batched fix round after the QA gate). Scope: the lead→coder contract (`handover-spec.md`, `orchestration.md` § Handover Spec) and all 14 `agents/*.md` files. **Decision:** a test file listed in `files_in_scope` means the coder authors those tests; none listed means the coder must not create or modify one, and any coverage the change needs is named in `acceptance_criteria` with a lead-named owner — the coder never picks the mechanism itself, only flags the gap via `missing_context`/`status: insufficient` and lets the orchestrator route it (a `dev-team:test-engineer` gate dispatch in conversational mode, a separate `domain: qa` spec in workflow mode, or an explicit accepted-risk call). **Rejected: a `test_ownership: coder|test-engineer|none` schema field** — deep-review class (every lead/coder handoff), invites value creep, and duplicates state already in `files_in_scope`, which would itself need a new lint to catch the two disagreeing. The convention is instead enforced today by an existing control: the QA gate's git scope-compliance check already bounces a coder that writes an unlisted file. **Companion norm:** one byte-identical bullet ("One deliverable, then return. Produce exactly what your own contract/output format defines as your artifact — even when that's a structured package with several named parts — then end your turn...") appended to the final section of all 14 `agents/*.md`, pinned as a complete-manifest invariant (`test/role-boundaries.test.mjs`, `listAgents()`-driven) so a new agent file inherits it by default. **Corrections made at the QA gate, round 1 (`code-reviewer-deep`, all 3 must-fix):** (1) the first draft claimed `dev-team:test-engineer` is unconditionally "dispatched by the orchestrator at the gate" for coverage the coder didn't get — false in workflow mode, where `team-build.workflow.mjs`'s Stage 3 gate only ever dispatches review + `build-validator`, never `test-engineer` outside its separate role as the `domain: qa` *executor* (`executorFor`); fixed by no longer asserting one guaranteed mechanism, only naming the possible routes. - **ADR-026 — Instrumentation is never load-bearing; the emitter facade swallows every ledger/lock failure.** accepted 2026-08-11, epic #39/#41 (shipped as `scripts/factory/emit.mjs`; back-filled into this file 2026-08-12 — the number was claimed in code and specs but never recorded here, caught during #78's V2 verification). Every public method on the emitter from `openRun()` is wrapped so no throw escapes: a failure bumps a drop counter and writes AT MOST ONE stderr line per process. `ledger.mjs` deliberately throws when its own JSONL append fails (losing the raw record is fatal); this facade exists to swallow that and every other ledger/lock failure without ever changing a caller's outcome, exit code, or returned value. `openRun()` itself never throws — any failure standing up the run sidecar yields a fully-formed, fully-inert DEGRADED emitter with the same method surface. *Clause 1 (the citable one):* a ledger degradation can never invert a gate's exit code — gate facts source from the sidecar read that already succeeded, never from the possibly-degraded emitter. Source: epic #41, be-41-03..06; `scripts/factory/emit.mjs:8-19`.

- **ADR-027 — Multi-process seq allocation is parent-owned, persisted-before-emission; monotone, not gapless.** accepted 2026-08-11, epic #39/#41 (`scripts/factory/emit.mjs`; back-filled 2026-08-12 with ADR-026). `ledger.mjs`'s own seq allocator seeds from `SELECT MAX(seq)` once per process per (adw_id, kind) — single-process-only, and below the Node floor `ensureDb()` returns null so every below-floor process restarts numbering at 1 (a deterministic 100% collision the instant two processes share an adw_id). `emit.mjs` is the first multi-process caller, so it never uses `ledger.mjs`'s allocator: every emission passes an EXPLICIT seq from a parent-allocated, sidecar-persisted range. The range-allocating critical section contains NO sqlite, NO JSONL, NO spawn — it reads the sidecar, bumps `next`/`reserved_through`, atomic-replaces, all before any ledger I/O. The reservation persists BEFORE any emission: a crash mid-batch leaves a GAP, never a DUPLICATE. seq is therefore monotone, not gapless. Source: epic #41, be-41-03..06; `scripts/factory/emit.mjs:21-40`.

- **ADR-028 — Substrate discipline is enforced by an orchestrator-side PreToolUse guard that denies only on positive evidence; every other outcome allows.** ratified 2026-08-12 (user-approved at the plan-approval gate), issue #78 (arch-lead package v1→v2, plan-reviewer 2 rounds; shipped as `hooks/dispatch-guard.mjs` + a `hooks/hooks.json` entry, deep-review 3-lens adversarial panel + mutation pass). `orchestration.md:42` binds the orchestrator to dispatch every `pane: true` role through `scripts/cmux/dispatch.mjs` in cmux mode, never the Agent tool — prose with no mechanical backstop, and it failed twice in five days (issue #76 ran end-to-end on Agent-tool subagents; the planning session for THIS issue then did the same, on current rules, a pure judgment failure). **The guard:** a PreToolUse hook (matcher `Agent` — the payload tool-name for a subagent dispatch, Phase-0 live-verified, NOT `Task`) that DENIES iff SIX conjuncts all hold — `tool_name==='Agent'`, no `agent_id`/`agent_type` present (main-thread only), `subagent_type` matches `/^dev-team:[A-Za-z0-9_-]{1,64}$/`, `resolveExecutionMode().mode==='cmux'`, the MERGED roster marks the role `pane===true`, AND `PANE_ROLES.includes(role)`. That last conjunction MIRRORS the dispatcher's own admission test (`dispatch.mjs`: admit iff `resolved.pane && PANE_ROLES.includes(role)`) exactly, so the two can never disagree — and it gates on the RESOLVED grant, never a hardcoded name list (the #27 gate-on-the-grant-not-the-name rule; a project roster override that flips a role is honored in both directions, and a `pane:true`-but-not-in-PANE_ROLES role stays dispatchable via agent-tool rather than being wedged behind both doors). **Fail-open on positive evidence only:** every error/uncertainty path — malformed stdin, unknown role, ambiguous/unknown `execution_mode`, invalid/unreadable roster, any throw, hook timeout — ALLOWS. This inverts the repo's usual fail-closed default deliberately: the guard is not a containment boundary (worker containment is ADR-005/012's `--allowedTools` surface, untouched); it is a doctrine backstop on the orchestrator's own session, and the costs are asymmetric — a wrong refusal-to-permit blocks EVERY subagent dispatch in the session for a cause the user cannot see, while a wrong allow is one visible, correctable agent-tool dispatch. **Never emits `permissionDecision:'allow'`** (a PreToolUse allow bypasses the user's own permission rules — a fail-open guard must say nothing, never grant; narrowed from the ratified `deny|allow` shape by the backend-lead, orchestrator-confirmed) and **never exits 2** (policy is exit-0 JSON only, so the platform's non-blocking semantics for other non-zero exits carry the fail-open guarantee for free). **ADR-008 reconciliation:** ADR-008 governs the dispatcher's PREFLIGHT, where the substrate is genuinely unavailable — loud stop, no silent degradation; ADR-028 governs a GUARD malfunction, where the substrate is fine — fail open. They compose rather than conflict because the two failures have opposite blast radii (refusal-to-act costs one clear error; refusal-to-permit costs every unrelated caller). **Carve-outs:** `Explore` scouts (no `dev-team:` prefix), `pane:false` roles (agent-tool is their correct substrate in cmux), non-`dev-team:` subagents, nested calls (carry `agent_id`/`agent_type`), worker sessions (`DEVTEAM_WORKER` early exit), and workflow mode — DOUBLY excluded per Phase 0: the Workflow tool arrives as tool-name `Workflow` (never matches) AND its inner `agent()` calls carry `agent_type: workflow-subagent` (nested carve-out). This cleared the ADR-007 stop condition — the guard ships as a real deny, not warn-only. **Kill switch is the config, not a new knob:** `/dev-team:team mode agent-tool` makes the substrate truthful; a dedicated disable key is rejected on ADR-023 grounds; `escalate` is rejected per ADR-008. **Consequences:** (a) silent inertness when `node` is unresolvable is accepted and DETECTABLE — a `node_unresolved` line in the decision log (`~/.dev-team/guard/dispatch-guard.jsonl`), plus a `systemMessage`; (b) an invalid-roster fail-open is a de facto SECOND kill switch (a schema-breaking roster edit disables the guard via `roster_error` while the dispatcher keeps working off `roster.snapshot.json`); (c) the decision log accumulates `cwd`+`session_id` for every dispatch across every repo on the machine, rotation deliberately unbuilt, 32MiB ceiling MARKED (`log_ceiling_reached`) not silent; (d) **restart discipline** — hooks load at SessionStart, so a session started before this version keeps the old guardless hook set; the guard only protects sessions started on or after the shipped version, and restart-after-plugin-update remains required. **The guard reads 3 of the roster's 4 layers** (session is a dispatcher-only `--config` sidecar the hook can't see) — a bounded residual that could diverge only via a hand-authored non-standard sidecar, not the supported `roster` verb (which writes agent/model only). Source: issue #78, arch-78 package v2, Phase-0 findings, be-78-01/02, doc-78-03.
