- **2026-08-21** — **crew/child.mjs arms no signal handler, in any window: the module is synchronous from entry to return, so every stretch of it is turn-free, a registered listener can never dispatch, and registering one still suppresses Node's default terminate-on-signal disposition.** This is the second sighting of 2026-08-11 — same repo, different module. #436's two armed windows were `arm()` after `io = seatIo(...)` through the `disarm()` before the drive (`checkoutProtectedPaths` plus four `io.log` writes) and the `finally { arm() }` wrapped around `settle()` (envelope, mirror, then `settleSeatTeardown`, which blocks in `pollGroupUntilDead`). Measured on this checkout by sending a real SIGTERM to a real forked child the instant it entered each window: armed, the child was deaf for the full 3019ms block and exited 0, and the `signalled` envelope its handler would have written was never written at all; unarmed, the same signal killed it by default disposition in 1-2ms — the same 1-2ms the two stretches that were never armed (the pre-arm preflight stretch and the drive) already measured. The residual is recorded, not papered over: a child reaped before `settle()` writes no envelope of its own, and the daemon's `settleSignalled` (`crew/daemon.mjs`) writes the run's `signalled` escalation record instead — the only mechanism that also covers SIGKILL and OOM (#423). A reap during settlement loses the teardown sweep, never the record, because `settle()` writes the envelope first. *Why:* a third attempt at cooperative child-side cleanup must now argue against two measurements rather than one. What makes a handler inert is the EVENT LOOP SHAPE around it, not the wiring, so the fix is never "arm it somewhere else" — closing the gap needs the async/worker child tracked in #419, and arming a handler in a turn-free function is not a step towards it but a regression that makes a daemon-reaped child survive its reap.

- **2026-08-01** — When composing a `claude` CLI invocation programmatically, always place a bare `--` immediately before the prompt positional. *Why:* `--tools`/`--allowedTools`/`--disallowedTools`/`--add-dir` are variadic and greedily consume the following positional; the prompt is then silently never submitted (`SessionStart` fires, `UserPromptSubmit` never does, no error, indefinite idle). Live-verified on claude 2.1.220, 4 reproductions + fix confirmation (cmux spike, `tasks/cmux-mode/spike-findings.md` S7/S9).
- **2026-08-01** — `dontAsk` permission semantics, live-verified on claude 2.1.220 (spike addendum, transcript evidence): omission from `--allowedTools` **is** denial for any command outside the built-in read-only set (`ls cat echo grep pwd head tail find wc which diff stat du cd` + read-only `git` — those always run, in every mode); a precise argument-scoped allow (`Bash(cmux notify *)`) is honored while sibling verbs stay denied; scoped denies (`Bash(cmux ping*)`) enforce. Never pair a broad deny with a narrow allow — precedence is deny→allow and a deny cannot carry exceptions; prefer allow-only rules and rely on omission-denial. *Why:* fail-closed containment with zero deny-list maintenance; the natural deny+carve-out shape silently resolves to denied.

Read the session transcript (`~/.claude/projects/<project-slug>/<session-id>.jsonl`, tool_use/tool_result pairs, `is_error` field) instead. *Why:* two spike tests were initially misread as "everything executed" when the transcript showed every call denied.
- **2026-08-01** — `--append-system-prompt-file` and `--system-prompt-file` exist on claude 2.1.220 but are absent from the main `--help` listing (referenced only inside `--bare`'s help text). - **2026-08-01** — Claude Code permission-rule syntax, **live-confirmed on 2.1.220** (S22a passed both directions with `Edit(//abs/**)`; S22b showed a `Write(...)` rule is rejected on stderr with *"is not matched by file permission checks — only Edit(path) rules are. Use Edit(…) instead"*): file-path rules must be `Edit(...)`/`Read(...)` — `Write(...)`/`NotebookEdit(...)`/`MultiEdit(...)` path rules are accepted but never consulted, and `Edit` covers all file-editing tools; absolute paths need a **double** leading slash (`//abs/...`) — a single slash anchors at cwd. Grep a child `claude`'s stderr for `is not matched by file permission checks` to fail fast on a bad rule kind. *Why:* both errors fail silently as spurious denials; they invalidated the spike's original S9 test.
- **2026-08-01** — Never site an agent-writable directory under `.claude/`, `.git/`, `.vscode/`, `.idea/`, `.husky/`, or `.devcontainer/`. Live-verified: a `dontAsk` worker with an **exact-match** `Edit(//<repo>/.claude/dev-team/tasks/x/returns/**)` allow rule is **denied** — `permissions.allow` does not override protected-path denial. The boundary is asymmetric: an interactive/`auto` orchestrator session writes `.claude/dev-team/` fine, so the trap only bites the dispatched-worker path — exactly where return files live. *Why:* silently breaks every worker return with a message the worker will narrate rather than escalate (drove the ADR-006 task-dir relocation).
- **2026-08-01** — `--allowedTools` is an allow-*rule* list, not a capability list; `--tools` is what closes the available tool set, and `--tools` does not cover MCP tools (use `--strict-mcp-config` + `--disallowedTools "mcp__*"`). A profile claiming a role "cannot run commands" is wrong unless Bash is absent from `--tools` — with Bash present, the built-in read-only set still executes in every mode. *Why:* omission from `--allowedTools` denies *execution*, but the tool stays in the model's context and the read-only set still runs.
- **2026-08-01** — Any token that authorises a state transition must be an unguessable per-run nonce delivered out of band to the process that fires it, and must never reach the supervised process's argv, environment, or any directory it can read. Prefer a mode-0600 file the consumer reads and unlinks before the supervised process exists: on macOS `ps eww` reports a process's **exec-time** environment, so unsetting an inherited env var after exec does not retract it. *Why:* discovered closing a completion-token forgery hole in cmux mode.
- **2026-08-01** — Never auto-`git reset --hard` a checkout the user owns. Automatic destructive recovery is permitted only on a path proven to be an agent-created worktree (is a worktree, shares the expected `git-common-dir`, is not the primary checkout); anything else refuses and escalates. *Why:* an over-broad cleanliness post-condition plus an automatic reset is a data-loss bug waiting on one false positive.
- **2026-08-01** — This repo has no JSON-Schema validator and will not gain one. New schemas stay inside the fixed 15-keyword budget (`$schema title description type required properties additionalProperties items enum const pattern minimum maximum minItems uniqueItems`; non-empty string = `pattern: "\S"`, bounded length = pattern quantifier — `minLength`/`maxLength` out of budget) so the hand-rolled validator in `scripts/cmux/contract.mjs` stays small and reviewable; enforcement is a **positive allow-list walk** in `test/schema.test.mjs`, and every new schema must be added to that file's **hardcoded list** (it is a list, not a glob — an unlisted schema is checked by nothing). *Why:* README advertises dependency-free; `ajv` would need node_modules, a lockfile and CI changes.
- **2026-08-01** — `//` is permission-rule syntax, not filesystem-path syntax. Inside `--allowedTools` an absolute path needs a double leading slash; a *filesystem* path field in a record/env var must be single-slash absolute (POSIX leaves `//foo` implementation-defined). Two distinct patterns, never unified. *Why:* conflating them in a schema silently blesses paths some platform may resolve differently (caught reconciling issue #2 vs the v2 design record).
- **2026-08-01** — Prefer structural impossibility to a test assertion, and a whitelist to a blacklist. Encode a rule so violating it yields an *invalid document* (closed enum, absent property, `additionalProperties: false`); keep the test only as a meta-check that the constraint hasn't been widened. Where a constraint must be enumerated, enumerate what is **allowed**. *Why:* 1a's plan review found two stale blacklists (a shell-metachar refusal list missing `(`/`)`/quotes; a conditional-keyword list missing four banned keywords) and zero stale whitelists.
- **2026-08-02** — CLI-dependent tests use a repo-local fake-binary fixture behind a `<TOOL>_BIN` env indirection: `test/fixtures/fake-cmux.mjs` logs every invocation as one JSON line to `$FAKE_CMUX_LOG`, persists mutable topology to `$FAKE_CMUX_STATE`, and varies **only by env switches** — no test-specific conditionals inside the fixture; where it answers "what does the real system say", the answer is a frozen live capture (see qa-notes 2026-08-02). *Why:* first instance of the pattern here (1b dispatcher); keeps the suite offline and <5s while every cmux interaction stays assertable.
- **2026-08-02** — Concurrency-unsafe check-then-act on files is a defect class the panel found four times in one slice: use `writeFileSync(tmp)` + `linkSync(tmp, dest)` (EEXIST = loser) for exclusive creates, a `'wx'`-created lock file `{pid, started_at}` verified-before-unlink for RMW transitions, and treat a corrupt lock as stale, never a wedge. `existsSync`-then-`rename` is always a TOCTOU (rename clobbers unconditionally). *Why:* 1b's record lifecycle (writeRecord/terminateRecord/worktrees.json) shipped all three shapes before review.
- **2026-08-02** — A worker's self-reported terminal status (`blocked`/`insufficient` in the return body) is decided at the outcome-mapping layer, **never** inferred from the process exit sentinel. The `.exit` sentinel never fails a valid return (frozen U-4), and a gate-exhausted turn writes a blocked return with `.exit=0` — so an exit-keyed check both breaks U-4 and misses that case. Key on `envelope.body.status`, in a row ahead of `completed→ok`. *Why:* a PRE-1C-VERIFY refusal / CLI-missing / gate-exhausted dispatch was laundering `{status:"blocked"}` into outcome `ok`, advancing the orchestrator on work that never ran (1c panel MF1). Adding the dedicated `blocked` outcome bumped `dispatch-record.schema.json` schema_version 1→2 per its own evolution rule (outcome-enum additions bump).
- **2026-08-02** — A snapshot/inventory verifier must assert **completeness against a closed manifest** (every expected destination was seen), not only reject bad entries found on disk — a rejection-only walk is bypassable by deletion. *Why:* a worker `rm`-ing the turn-blocking gate from its snapshot passed a rejection-only walk with the gate silently absent (1c panel MF4).
- **2026-08-02** — Cross-trust artifacts (per-worker plugin snapshots) are keyed **per dispatch** (`<stateDir>/worker-plugin/<dispatch_id>/`), never shared per task: a shared snapshot lets a long-lived writer role mutate the hooks a concurrent read-only role executes on its next hook fire. Nest under the task stateDir so wholesale teardown still sweeps it. *Why:* shared `worker-plugin/` was a cross-dispatch code-execution vector (1c panel R1 / contract #9).
- **2026-08-02** — "Never logs the secret" and "exactly-once side effect" acceptance criteria are **vacuous unless proven by mutation**: pair each with a test that fails when the guard is removed or the secret is injected (assert against `NONCE_PREFIX` on *every* failure path, not just the happy one; count the actual side-effect invocations, don't just assert a well-formed value). *Why:* three 1c must/should-fixes (MF7 nonce-log, SF3 exactly-once, SF5 realpath) were 652/652-green holes a reviewer's one-line injection/guard-removal defeated. Extends the positives-first rule to guard-removal mutation testing.
- **2026-08-02** — A raw control character (e.g. a literal `NUL`) written as a string-literal separator makes the source file "binary" to BSD grep/`rg`/diff and many editors — they silently match nothing. Always use the escape (`'\0'`, `'\x00'`) so the source stays ASCII while the runtime string is identical; at the gate, a `grep` that unexpectedly returns *nothing* for a symbol you know exists is the tell — confirm with `tr -cd '\0' | wc -c` / a Python NUL scan. *Why:* a coder shipped two literal NUL join-separators in `adapter-claude.mjs`; tests passed (node tolerates it) but every grep-based gate check came back empty and nearly masked a real inspection.
- **2026-08-03** — `execution_mode` canonical values are `cmux` | `agent-tool`; `subagent` is a legacy alias normalized to `agent-tool` on read, and an absent key means `agent-tool`. Enforced by frozen exports in `scripts/cmux/dispatch.mjs` (`EXECUTION_MODES`, `EXECUTION_MODE_ALIASES`, `DEFAULT_EXECUTION_MODE`) + a deepEqual drift guard; exactly two values can ever leave `readExecutionMode`, and no document may present `subagent` as the value to set. *Why:* the frozen 1a preflight remediation (`cmuxctl.mjs` verb_missing) already instructed operators to set `agent-tool` while the 1b reader threw on it — a documented-then-broken control path. One canonical spelling per mode; the throw quotes the raw configured spelling. Supersedes: the 1b-era `subagent | cmux` pair (dispatch.mjs + README).

Documented in `references/qa-gate.md`, #8. *Why:* verified live against the installed binary's `--help`; recording it prevents a future slice from "adding the diff verb to the allow list."
- **2026-08-04** — **A counter's unit is whatever event its hook actually fires on — design against the SHIPPED hook inventory, not a ratified-but-unbuilt one.** Issue #8 specified `max_turns` gate enforcement assuming a per-tool-call hook existed, because ADR-012 named a "PostToolUse attestation" hook in its closed inventory — but that hook was scheduled for a later slice and never built (`DEVTEAM_SIGNAL_LOG` is a frozen env key with no writer). - **2026-08-04** — **No worker-plugin hook may force-stop (`continue:false` or equivalent) while the gate mode file reads `observe`.** Observe means a human has interjected mid-dispatch (`gate-mode.sh`, sticky once set); `return-gate.sh` already honors it with an unconditional early exit — no block, no slot claim. - **2026-08-05** — **A shell command documented in `references/*.md` for the orchestrator to run must be portable to bash, zsh, and POSIX `sh` — never assume bash.** This repo's interactive shell is zsh; a documented snippet using bash-only syntax (arrays, `read -a`, process substitution `<(...)`) silently fails or hard-errors when the orchestrator actually runs it, even though the snippet reads fine and any structural test of the surrounding prose stays green (tests can't execute embedded shell). Prefer POSIX-portable pipelines (e.g. `... | tr '\n' '\0' | xargs -0 -r ...`) over array-based composition; if bash-only syntax is unavoidable, say so explicitly and wrap it in `bash -c`. *Why:* issue #9's qa-gate.md noise-filtering commands shipped a bash-only fix that broke under zsh/sh on the first deep-review pass — caught only by live-running the snippet in all three shells (qa-notes.md 2026-08-05).
- **2026-08-03** — **A structural check whose "already done" state is unobservable will be re-done.** Any idempotent mount/create loop must resolve current state from the authority (a fresh tree/listing) before acting, and its absent-vs-ambiguous outcomes must be distinguishable so consumers can fail closed; a guard that relies on "this branch is unreachable today" becomes a duplicate-side-effect bug the moment the gate that made it unreachable opens. *Why:* `statusCmd`'s doc-tab re-mount loop was a documented structural no-op under the Phase-1 `PANE_ROLES` gate; flipping six roles at #6 turned it into "mount another panel on every status call" until guarded.
- **2026-08-01** — Dispatch only via `scripts/cmux/dispatch.mjs`, never in orchestration.md prose. The dispatcher owns the verb sequence (workspace creation, pane launch, kickoff send, doc-tab mount, await logic, close), token generation, worktree lifecycle, and error recovery — mechanical and deterministic work that belongs in a tested script, not narrative. Judgment (when to re-dispatch, how long to wait for a stalled pane, whether to ask the user) stays in the orchestrator's prose and interactive decisions. *Why:* the plugin already splits mechanical concerns (spec-lint, task-cost scripts) from judgment prose; dispatch is mechanical and failure-prone, and testability against a fake cmux without the model is essential. Source: epic #15 comment 6, v2 §4.1 and §5.8; recorded 2026-08-05, issue #10.
- **2026-08-01** — Control plane and data plane are separate channels: the filesystem carries structured returns (JSON/markdown), specs as file paths, and completion signals as files; the cmux socket carries diagnostics only (read-screen output is never a decision input), and control text only (send carries single-line commands, never payloads). Structured data that drives control flow (status, verdict, severity) is validated and acted on from files; prose diagnostics inform the human operator but never the orchestrator's branch logic. Any verdict that drives control flow is structured data with a fixed enum, validated mechanically; quality judgments stay agent-side and are never linted. *Why:* cmux's socket is message-scoped with redacted bodies and no payload primitive; the filesystem is the only channel that can carry contracts. Source: epic #15 comment 3, v1 ADR-002, and comment 8, v2.1 §R6; recorded 2026-08-05, issue #10.
- **2026-08-01** — The adapter contract is two verbs and a side effect: `capabilities` (orchestrator calls it at preflight; adapter reports model/flag support), and `run <record.json>` (orchestrator sends the dispatched role's spec/model/profile; adapter execs the agent inside the pane and never returns until the agent exits). The side effect is mandatory: on any exit (success, crash, timeout) the adapter writes the return file (`tmp+rename` for atomicity) and signals `cmux wait-for -S <token>` from a `trap … EXIT`, so the orchestrator is never left without a return. The return is the truth; the signal is the event. *Why:* determinism requires one script entry point; a return-on-exit invariant means crash recovery is file-based, never token-based. Source: epic #15 comment 6, v2 §5.3; recorded 2026-08-05, issue #10.
- **2026-08-01** — CLI-dependent subsystems (cmux, claude, npm) use a `<TOOL>_BIN` environment variable as a mockability seam: `dispatch.mjs` reads `$CMUX_BIN` (default `cmux`), the adapter reads `$CLAUDE_BIN` (default `claude`), and test fixtures wire them to fake binaries (`test/fixtures/fake-cmux.mjs` logs invocations; a mock claude script checks argv). This generalizes the existing `<TOOL>_BIN` test fixture convention (see 2026-08-02 entry about fake-binary fixtures); in cmux mode every integration point between the orchestrator and a real tool must be seamed this way. *Why:* tests run offline with full visibility into every tool call, zero model cost, and no flaky timeouts. Source: epic #15 comment 6, v2 §8; recorded 2026-08-05, issue #10.
- **2026-08-01** — Single source of truth for role prompts: every role body lives in exactly one `agents/<role>.md` file, never forked or duplicated. Substrate addenda (platform-specific instructions like "write your return to `$DEVTEAM_RETURN_PATH`") live under `scripts/`, never copied into `agents/`, so they are never auto-discovered as subagent roles. A pane dispatch reads the same role file, strips the frontmatter, appends the static substrate-specific addendum via `--append-system-prompt-file`, and sends to the agent. Agent-tool dispatch reads the same file, frontmatter intact. No file is edited to fit one substrate or the other. *Why:* two copies of a prompt drift independently and invalidate both; substrate addenda under scripts/ is the clean boundary. Source: epic #15 comment 6, v2 §4.6; recorded 2026-08-05, issue #10.
- **2026-08-01** — One reference file per subsystem: `references/cmux-dispatch.md` contains all cmux-mode mechanics and verb reference, read once per dispatch cycle; no cmux protocol lives in the core orchestration.md (kept lean at ≤69 lines), no verb tables elsewhere. A future adapter (codex, opencode, pi) gets one new reference file; the plugin never accumulates a second cmux reference or a second adapter reference. Judgment code (when to escalate, when to retry) can go in prose; mechanical reference material belongs in a frozen, indexed file. *Why:* discoverable, versionable, auditable as a single unit for every phase of work. Source: epic #15 comment 6, v2 §5.1; recorded 2026-08-05, issue #10.
- **2026-08-01** — Persist UUIDs, never positional refs, and re-read before acting: dispatch records store cmux surface/pane/workspace UUIDs as hexadecimal in the record file; code never stores positional refs like `surface:9` (which renumber when surfaces reorder). Before any topology operation (send, close, move-surface, read-screen), query `cmux tree --json --id-format uuids` and resolve the UUID to its current identity, no-op loudly if the UUID is gone. On ambiguity (multiple surfaces match), abort rather than guess. *Why:* positional refs are layout-dependent and silently break when cmux reorders; UUID-first + re-read means concurrent dispatches never close each other's panes. Source: epic #15 comment 6, v2 §4.4; recorded 2026-08-05, issue #10.
- **2026-08-01** — UI-backing files (return markdown for doc tabs, placeholder files for the worker to complete, rendered artifacts) are overwritten in place via `tmp+rename` (write to a temp file, atomically link it into place) or edited in place, never deleted and recreated. `existsSync`-then-`rename` is always a TOCTOU race; deletion + recreation later than cmux's ~500ms retry window bricks the rendered panel permanently. This differs from the existing TOCTOU rule (line 28, 2026-08-02 entry) in purpose: that rule guards *shared mutable state* (worktrees.json lock); this guards *visible UI artifacts* that cmux is monitoring for live-reload. *Why:* atomic writes and visible-file stability are prerequisites for a rendered doc tab. Source: epic #15 comment 6, v2 §4.4; recorded 2026-08-05, issue #10.
- **2026-08-01** — Worker profiles are allowlist-shaped under the `dontAsk` permission mode: a profile lists exactly what tools the role can call (`--tools Read,Edit,Write,Glob,Grep,Bash`) and exactly which operations are allowed (`--allowedTools "Edit(//…/returns/**)" "Bash(git diff *)"…`); there is no blanket deny list. Deny takes precedence over allow, so an allowlist-only shape fails closed by omission — any tool call not explicitly allowed is denied at the tool layer. Read-only roles (judgment, reviewer) can write exactly one file (their return) via a scoped grant; executors can write their worktree and their return. - **2026-08-12** — **A fail-open gate proves its exception branches non-vacuously by asserting each branch's OWN distinct diagnostic reason_code — never "the fixture allows", which every branch produces identically — and the catch-all must emit a code no named branch does.** The naive "delete the branch, the decision flips" mutation criterion is UNSATISFIABLE for a fail-open control: deleting the DEVTEAM_WORKER exit, the malformed-JSON catch, or the unknown-role branch all still yield ALLOW (the default), so the fixture stays green whether or not the code exists. The mechanism that restores non-vacuity: a frozen per-branch reason_code written to a decision log, with the outer catch-all carrying a code (`internal_error`) DISTINCT from every named one — that distinctness IS the control, and mutation testing must target the code (delete a branch → code changes to `internal_error` or a sibling; swap two codes → a code-specific fixture catches it). #78's be-78-02 mutation pass found the one gap this rule exists to close: valid-JSON-but-non-object stdin (`null`, an array) had no fixture, so the `isPlainObject(input)` guard was unpinned and a `null` payload silently regressed to `internal_error`. *Why:* generalizes the #76 vacuity family (self-referential test helpers mask a vacuous pin) to fail-open controls specifically — the r2 plan review predicted this exact class, and the guard would have shipped with an unpinned crash-to-internal_error path without it.
