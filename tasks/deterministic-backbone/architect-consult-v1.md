# Architect consult — architecture-package-v1 (deterministic backbone)

**Consultant:** dev-team:architect · **Date:** 2026-08-04 · Verified against `scripts/cmux/{dispatch,contract,return-lint}.mjs`, `references/{qa-gate,cmux-dispatch}.md`, `orchestration.md`.

## Q1 — §3 Position: **agree-with-modification** (keep A/C; three supporting arguments wrong; one cheaper win unexamined)

### 1a. Turn-count decomposition changes the answer
Orchestrator turns split into **poll turns** (re-invoking `await --all`; `AWAIT_CAP_DEFAULT_S = 120` at `dispatch.mjs:927`, pane timeouts 1800–3600s ⇒ a 25-minute lead ≈ 12 poll turns; three roles/slice ⇒ polls dominate) and **decision turns** (~5–6/slice). **A does not reduce poll turns at all** — `chain step` returns `still-running` and the orchestrator re-invokes. A's entire win is in the decision class, and **C already captures most of it** (one `gates.mjs check` call collapses spec-lint + validation + scope + aggregation). A's increment over C ≈ 1 turn per phase boundary (~3/slice). Meanwhile §8.7's `resolve` protocol is a Write + a Bash per halt, then a further `step` — 8–12 tool calls where prose spends ~4. **As specified, A is plausibly turn-negative.**

Modifications:
- **Merge `resolve` into `step`:** `chain step --answer <halt-id> --decision '<inline-json>' [--override "<reason>"]`, `@file` escape hatch. Keep the refutation logic exactly (best idea in the package); don't charge two tool calls per question. As sliced (B4→B5) the two-verb shape gets frozen into schema+fixture before anyone measures.
- **Cap halts per segment, not just kinds:** acceptance criterion — a clean Tier-2 slice with no amend cycle emits **≤3 halts** (spec_approval, gate_route, acceptance).

**The unexamined cheaper win:** `AWAIT_CAP_MAX_S = 600` (`dispatch.mjs:929`); `references/cmux-dispatch.md:20-23` documents `--max-block-s` but recommends no value, so the orchestrator gets the 120s default. **`--max-block-s 600` cuts poll turns 5× for one line of doc** — larger than the chain's entire projected win, zero architectural cost, gated on the same unknown (U2). **Recommendation: make Scout 1/U2 a hard gate on the whole initiative; land the `--max-block-s` change as an A0 slice first.** Sequencing: **A0 → C (gates as standalone CLI) → measure → A (step machine) only if the measurement still shows a win.** Building B3 (frozen segment-table DSL) before U2 is measured is building on sand.

### 1b. Spawn vs import — right call, wrong reason, four missed failure modes + one severe
The invariant argument self-refutes: §3.3 invokes `dispatch.mjs:3-5` ("the ONLY file that spawns/git/wall-clock") while §9.1's `evidence.mjs` does git, spawns, and measures wall-clock. Restate honestly: *within the cmux subsystem* dispatch.mjs is the sole spawner; the chain is a separate subsystem with its own single impure module. Real reasons for spawn: process isolation, the `DISPATCH_BIN` fake seam, version-skew tolerance.

Missed failure modes:
1. **Exit 2 does not always print JSON** (`dispatch.mjs:1495-1506`, `:1528-1531` — no `printResult` on argv/usage errors; lock contention *does* print `{error:'lock_held', holder}`). Chain must treat exit 2 + empty stdout as its own argv bug (halt `blocked`) vs `lock_held`. `fake-dispatch.mjs` must reproduce this asymmetry.
2. **`spawnSync` maxBuffer** (default 1 MB; overflow truncates stdout, `res.error.code === 'ENOBUFS'`). Set explicitly; check `res.error`/`res.signal`/`res.status === null` before parsing.
3. **Orphaned await child wedging `await.lock`:** SIGKILL of `chain step` while blocked in `spawnSync('dispatch await')` leaves the child alive holding await.lock; next step refuses naming the chain's own orphan. Record the spawned dispatcher PID in `chain.json.head`; explicit `timeout` + `killSignal` on spawnSync.
4. **Lock-staleness ordering can invert:** asserted invariant needed — `chain_lock_stale > await_lock_stale`, with a test.

**Severe — the crash window between spawning `dispatch` and persisting the dispatch id:** killed between spawnSync return and the chain.json rename ⇒ pane exists, chain has no record ⇒ next step re-dispatches the slice ⇒ **duplicate pane + second dispatch_id**. Rule: **`listRecords(paths.dispatchDir)` is the sole authority on what was dispatched; `chain.json.phases[].dispatch_ids` is a cache that must never contain an id listRecords does not confirm; reconcile adopts unknown records rather than dispatching again.** (Invariant-8's "phase record before dispatching" is phase-granularity; per-dispatch is needed.)

Minor: `assertExecutionModeCmux` (`dispatch.mjs:1517`) re-reads config.md on every spawn — a mid-run edit flips chain-driven dispatches to refusal mid-chain. Snapshot `execution_mode` at `chain plan`; fail closed on change.

### 1c. The convergence trigger — **comforting fiction, internally contradictory**
§8.1 states the chain cannot invoke the Agent tool — a substrate fact (only a model turn can). An "Agent-tool backend for chain.mjs" is **unbuildable by construction**; the trigger can never fire. The only surviving reading (chain halts per Agent-tool dispatch) is strictly worse than prose and still doesn't make the workflow a thin caller (its value is zero-orchestrator-turn unattended batches). **Delete the trigger; state the steady state honestly: three substrates, permanently, serving three different things.** Concrete harm of keeping it: a future implementer designs `segments.mjs` backend-agnostic with a transport indirection for a backend that cannot exist.

## Q2 — §5.2 Gate layer: **agree on the cut; disagree on the `inconclusive` mapping**

### 2a. completed-vs-accepted — right cut; a real downstream misread exists
The decisive argument belongs in §5.2: `return-lint.mjs:4-6` is "a THIN CLI over the parent's own evidence layer" and runs **inside the worker-writable snapshot** — widening ladder step-2 ships content gates into the worker's tree (the trust-M1 shape §5.4 rejects).

**The misread destroys evidence.** `dispatch.mjs:1398`: `const archive = Boolean(args['keep-artifacts']) || shouldArchive({ outcome: 'ok' }, records)` — the `task` argument is **hardcoded `{outcome:'ok'}`**. A run where every dispatch completed ok but the chain refused acceptance (hard-fail gate, protected breach, unresolved halt) has its task dir **and state dir deleted, not archived** — taking chain.json, chain.jsonl, every GateReport with it. The audit trail is garbage-collected precisely when it matters. Fix in B8, named dependency on #7: `teardownCmd` reads `chain.json.accepted` and passes `{outcome: accepted === true ? 'ok' : 'refused'}`; absent chain.json ⇒ today's behavior. Also decide the **ledger's lifetime** (chain.jsonl lives in STATE_DIR which teardown deletes) — either it outlives teardown (copied to archive unconditionally) or say plainly it does not.

The permanence of `outcome: ok` in dispatch records while the chain refused the run is **correct** — a dispatch record is a fact about a process; acceptance is a judgment about work. The only consumer treating "all dispatches ok" as "run good" is teardown. One line of doctrine for `references/chain.md`: *status.json answers "did the dispatches finish"; chain.json answers "was the work accepted"; never read one for the other.*

### 2b. `inconclusive` mapping — **disagree**
(i) **It is a brain change, and it's not in §13.** Both existing definitions of `inconclusive` are about *absence* (`qa-gate.md:33` "no verdict"; D17 "missing/unparseable"); a third producer exists in code (`return-lint.mjs:99` `VERDICT_STUB_OBJECT`). Adding self-contradiction is a fourth producer widening a defined term in a brain file. Add as ratification item 8 or drop the "zero brain change" claim.
(ii) **Route converges, record shouldn't.** In cmux, "re-run" = new dispatch of the same role, and §4.3 already carries the GateReport in the kickoff — so the bounce and the re-run are the same action. Keep the route; reject the naming: `verdict_consistent` produces `{item, ok:false, note:'verdict=pass with 2 critical findings — F1, F2'}`; the routing coincides with D17's inconclusive branch as a *convenience, not an identity*; **the chain never rewrites the reviewer's `verdict` field** (the package's own "deterministic results never wear an agent's envelope" demands this — "maps onto inconclusive" is one sloppy sentence from an implementer overwriting a worker-authored envelope).
(iii) **The real defect: the loop has no bound and no owner.** ADR-015 says the chain only counts *existing* bounds; there is no existing bound on re-running an inconclusive review (≤2 is coder-insufficient; re-dispatch has only attempt ≤99). Mechanized "refuted → re-run" can loop a reviewer indefinitely with ADR-015 forbidding the chain from stopping it. Two ways out; **recommend (b): a refuted verdict halts on first occurrence; never auto-re-runs.** Strictly cheaper, ADR-015 intact, zero new counters, no brain change; the orchestrator re-dispatches, escalates the ladder, or overrides with a recorded reason. (a) — a new ≤1 bound — is honest but is a brain change plus the fourth counter §4.3 avoided.

**Calibration:** ship `pass ∧ ∃critical` as the hard refutation; ship `changes-needed ∧ findings.length === 0` as **evidence-only, non-routing** initially — reviewers legitimately put blocking reasoning in `Must-fix` (only Must-fix blocks, `qa-gate.md:35`), so this variant will false-positive against real returns.

**Factual error in §5.3:** "Panel majority … already mechanical, already owned by the existing ladder" — **no majority aggregation exists anywhere in `scripts/`** (grep: zero matches). `ladder.mjs` validates one envelope; panel majority today is orchestrator prose plus a copy in `team-build.workflow.mjs`. It's listed in **#8**, which B4 depends on — state it as a dependency being *acquired*, not a mechanism being *read*. If #8 ships D17 without an aggregator, the chain would have to write one — and then the chain **is** deciding a verdict, violating its own charter.

## Other material issues
1. **§6's protected-path set is self-defeating in this repo.** `scripts/chain/**`, `scripts/cmux/**`, `hooks/**` ARE the product here — #7/#8/#9/A2 all dispatch coders against `scripts/cmux/*.mjs`; B6 as written escalates on the plugin's own development. **Fix:** protected set = `.claude/dev-team/memory/**` + `.claude/dev-team/config.md` only; everything else is the ordinary scope check. A protected path in `files_in_scope` is a **spec** error caught at spec_gate, not a runtime breach.
2. **A2 carries the most Phase-A risk for the least marginal value.** Heuristic path-parsing linter in the hard path of every executor dispatch, contract-freeze-set file, no override; repo direction on spec-lint is *softening* (#9). **Recommendation:** narrow A2's refusal to schema-derived checks that structurally cannot false-positive (missing required field, empty files_in_scope), pass heuristic checks through as warnings in the dispatch JSON; or ship behind `--require-spec-lint` (default off), flip after observed runs.
3. **§13.1 is load-bearing and under-argued** — the turn-count thesis depends on a brain-file amendment that is 1 of 7 pending ratifications. Surface at the top of §0.
4. **The 4096-byte JSONL cap's rationale is wrong.** PIPE_BUF governs pipes, not `appendFileSync` to a regular file; O_APPEND offset atomicity holds regardless; single-writer-under-lock already mandated. Keep truncation for readability; delete the PIPE_BUF justification (as written it teaches 4096 as a correctness boundary).
5. **U2 is named highest-impact, then ignored by the plan.** Make Scout 1 a **blocking gate on B3**, not an input to B4's spec.

## Over-engineered for a two-person plugin
- `segments.mjs` as a separate module + frozen DSL + `validateSegmentTable()` + construction-time description lint — for two tables authored by one repo. Fold the tier-2 table into `chain.mjs` as a plain exported array; extract when tier-3 forces a second shape. B3 freezes a data format before its only consumer exists.
- Six ADRs before a line of code — 015 and 019 are consequences of 014/016; 017 is an implementation detail. Three would carry the same durable content: position+state, envelope/gate authority, write boundaries.
- `chain abort` — nothing a halt or deleting chain.json doesn't cover. Drop until needed.
- Nine Phase-B slices with a full dependency lattice for an unmeasured thesis. B1+B2 are standalone-useful; **re-plan B3–B9 after the measurement gate.**

**Worth keeping despite the ceremony:** the `{item, ok, note}` evidence-on-pass shape (§5.2), the `resolve` contradiction refutation (§8.7), the mutation tests for load-bearing prohibitions (§9.3), the frozen-live-capture rule for `fake-dispatch.mjs` (§9.2). Those four are the package's real content.
