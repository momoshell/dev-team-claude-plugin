## 1. Locked decisions

### D4 / ADR-002 — file data plane, socket control plane
Socket = control + signaling only; filesystem = data plane. Spec goes in as a file path on the launch line; agent writes structured return to a file; `read-screen` is diagnostics only, NEVER the result channel; `send` is kickoff/interjection only, never multi-line payloads. "Structured returns are the contract in both directions — the orchestrator branches on enums, never prose." Ratified deviation: `await --all` is FOREGROUND, chunked; orchestrator loops (background Bash ends the turn, nothing resumes the model). No cmux deny rules anywhere; exactly two cmux allows byte-identical: `Bash(cmux notify *)`, `Bash(cmux wait-for -S *)`.

### D5/D6 — workspaces & paths (D6 location SUPERSEDED)
Workspace = one task engagement; panes hired per dispatch, closed when return lands; workspace destroyed at ship; Tier 1 = no workspace (delegated T1 coder = single pane in orchestrator's workspace, `tier1-<slug>` task dir). Live layout (comment 10 §6.3 + issue #2 comment):
```
~/.dev-team/tasks/<repo-slug>/<task-slug>/   # TASK_DIR, --add-dir'd
  task.json plan.md context.md spec/ returns/<stem>.json returns/<stem>.md(parent-written) signals/<stem>.jsonl
~/.dev-team/state/<task-slug>/               # parent-side, NEVER --add-dir'd
  dispatch/<stem>.json  worker-plugin/  <id>.nonce(0600)  <id>.exit  <id>.signal-log
~/.dev-team/archive/<task-slug>-<utc>/
```
Reason: dontAsk worker with exact-match allow under `.claude/` is DENIED (G9, live-verified U2/S25c). Dispatch records parent-side because under TASK_DIR "they leaked sibling attention tokens to every worker" (rider C). Identity: dispatch_id UUID; slice_id human (SLICE pattern); attempt 1–99; stem `<slice>.<attempt>`; worktrees **keyed to task_id** with `attempts: [dispatch_ids]`; branch `^dt/[a-z0-9-]+/[a-z0-9-]+$`. `//` is permission-rule syntax only; filesystem fields single-slash absolute.

### D2 + tables A/B — roster/profiles
Precedence: agents/*.md frontmatter → plugin roster.default.json → ~ → project → session. Live shape: top-level `tools` hoisted identical for all roles `[Read,Edit,Write,Glob,Grep,Bash]`; no per-profile tools/deny/disable_slash_commands; `profile.allow` = agent-neutral grant tokens (returns_write, signals_append, worktree_write, validation_commands) expanded by `expandGrants`; 3 profiles by "one per distinct grant-token set" (executor=all4/changes_expected; validator=no-worktree_write/clean; judgment=returns+signals/clean); permission_mode enum-closed dontAsk; roles carry pane/profile/isolation/model/doc_tab/return (+agent/effort/timeout_s/max_turns); schema_version 1 const; architect + trd-reviewer SUBAGENT_ONLY; profile description must NOT match `/cannot run commands/i` (read-only Bash set executes in every mode, G5). Additive optional fields with documented default don't bump version.
**NEW-1 (v2.1 §B-1): profile replaces frontmatter tool policy WHOLESALE for pane dispatches — never merge.** From frontmatter a pane takes model + effort only. Convention #13: "Enforcement models don't merge."

### D15 / ADR-009 + NEW-3 — byte-stable prefixes, kickoff literals
System prefix byte-stable per role: static role file (passed via `--append-system-prompt-file`, exists on claude 2.1.220/G14), static worker plugin, no per-dispatch content in system prompt. All per-dispatch variance via env vars AND the kickoff (first user message). **Two audiences, two forms: env.DEVTEAM_* for shell-side consumers; the MODEL receives expanded absolute literals in the kickoff** (nothing resolves $VARS for the agent — planner has no Bash, Write doesn't expand env). Kickoff: single line ≤4000 chars, no newlines; carries dispatch_id, task_dir, spec_path, return_path, signals_path, attn_parent, attn_upstream as literals; must not contain NONCE_PREFIX. Waves: same-role siblings launch after first pane's first turn (~5s settle) for cache reads; cap 4–6. Argv hard rules (9, comment 10 §5.1): bare `--` before kickoff positional always (else dispatch idles forever, no error); argv = string array to spawn without shell, no $() or concatenation, the array builder is the contract; one element per permission rule; // -prefixed absolute paths in rules; rule kinds whitelist (path: Edit/Read only; command: Bash only); nonce substring-scan before spawn.

### B-2 — events trigger rescans, never resolutions
Rescan triggers (in-process, never end the call): notification.requested event · rank-0 poll tick · EXIT sentinel appearing → re-stat + re-lint every outstanding return, refresh quiet timers. Resolution reasons (end await --all, per-dispatch attributable): completed (fresh valid return; includes blocked) · crashed (exit sentinel ∧ no fresh valid return) · attention (turn-end event + no return quiet_s=45 later + top shows idle; latched once per attempt) · timeout (wall from created_at). Non-resolution exit: still-running at --max-block-s. "A doorbell that cannot name the sleeper only wakes; it never decides" (convention #14). Why: events are workspace-scoped, surface_id usually null — 6 panes would fire false attention at every turn boundary.

### ADR-003 — four-rank completion ladder
0: return-file watch (stat + return-lint every 3–5s, freshness) — co-primary. 1: `cmux events --reconnect` workspace-scoped ⇒ rescan — primary push. 2: adapter EXIT trap → `.exit` sentinel + `wait-for -S` token — crash backstop, permanent. 3: bounded Stop-hook gate — contract enforcement only, ≤2 blocks, never the signal of record. Agent self-signal dropped. **Parent invariant: on EVERY wake, indistinguishably, completion is re-derived exclusively from the ladder — return exists, mtime fresh (shipped: strict integer-ms >), parses, validates, dispatch_id matches. A wake is never itself evidence.** S20: wait-for tokens are durable across cmux restart (global namespace) — stale tokens can fire spurious wakes, reinforcing re-derivation; events cursors are boot-scoped.

### Cursor/lock ownership (v2.1 §D)
`await.lock` (PID + started_at, stale = 2× max-block-s); second concurrent await REFUSES exit 2 naming holder PID. Events child writes to spool; `events.cursor` advances only on clean exit; trap-kill events child on every exit path; replay-safe because rescans are idempotent. timeout_s = wall-clock from record.created_at evaluated on every rescan.

### D17 / ADR-010 — structured verdicts (§R governs, §H superseded)
Shape: `{"verdict": "pass|changes-needed|inconclusive", "findings": [{"severity": "critical|warning|suggestion", "file", "line" (nullable), "summary"}]}` — one fenced json block in the section matching `Verdict`; unknown keys ignored; validation = presence/parseability/enum only, never quality. Scope: verdict_block true on gate-participating roles only (code-reviewer, code-reviewer-deep, build-validator); plan-reviewer/trd-reviewer keep prose (feed human approval). Branching: any critical → bounce/escalate per existing ladder; warnings → task summary; suggestions only → pass with notes; missing/unparseable → inconclusive → re-run scoped to diff. Panel: pass = majority over members' verdict values. Severity ↔ Must-fix/Should-fix/Consider. NOTE: §H's `approve|revise|block` is superseded — do not use.

### D9/ADR-005 — no bypass, ever
Socket default mode; orchestrator inside a cmux pane; allowAll banned; never `--dangerously-skip-permissions`/`bypassPermissions` (negative tests); dontAsk = omission-is-denial. Trust addendum (comment 9): cmuxOnly is containment, not immunity — don't keep high-privilege interactive sessions in the same cmux instance as worker panes.

### D14/ADR-008 — preflight hard stop
cmux is a hard prerequisite; no Agent-tool fallback; five byte-exact remediation messages (tested); mutating verbs refuse without cached preflight.json; carve-outs: Tier-1 direct, Explore scouts, workflow mode (ADR-007). Postcondition (comment 10 §9.2): primary checkout must be clean modulo postcondition_ignore; violated clean ⇒ refused_postcondition; dirty primary ⇒ refused + escalate, "no automatic destructive action on a checkout the user owns."

## 4. Collision/composition analysis for a phase-chain runner

**4.1 Who sequences panes: the orchestrator, as judgment, in a foreground loop — explicitly not a script.** dispatch.mjs "never talks to a model"; v2 §4.1 "mechanical work in a script, judgment in prose"; orchestration.md:42 owns the loop; await --all = "the Agent tool's blocking rhythm rebuilt out of bounded tool calls, each chunk boundary an interjection point." Deterministic sequencing already exists and is carved out: **ADR-007 "Workflow mode stays on the Workflow tool's agent() dispatch"** + shipped carve-out "neither [Explore nor workflow] goes through dispatch.mjs". team-build.workflow.mjs already IS a deterministic chain (waves, depends_on-must-PASS, one amend-retry, cap, unroutable rejected). **Sharpest design question: is the runner (a) a third substrate beside dispatch.mjs and the workflow, (b) a replacement for team-build.workflow.mjs that drives dispatch.mjs (contradicts ADR-007 + carve-out line — needs a ratified §13-style deviation), or (c) a layer above the orchestrator's await loop?**

**4.2 Retry ownership is split three ways, each named:** orchestrator owns amend→rebuild on insufficient (≤2 then escalate; brain, unchanged by epic) · return-gate.sh owns Stop-hook blocks (≤2, hard ceiling 3, then writes blocked return itself) · orchestrator-via-triage owns re-dispatch on timeout/attention (new dispatch_id always, worktree reused; never automatic for orphans). Convention: "hooks own their loop bounds (never rely on stop_hook_active)" — backed by claude-code #54360 and #55754 ("an unbounded block loop in an unattended pane is a FINANCIAL failure mode"). attempt capped 99. **Runner-owned retry counters = HIGH collision; must delegate to the orchestrator's amend loop or be filed as a brain change.**

**4.3 QA ladder: owned by qa-lead; "brain unchanged" is a binding constraint + epic non-goal** ("the substrate changes, the brain does not"), with exactly three narrow exceptions (lead sections, D17 block, D16 WARN). D17's own limit: "The ladder is unchanged — this replaces prose-reading with enum-reading." Only sanctioned mechanical ladder input on the roadmap: #13 item 5 (tier floors from diff LOC/file-count), post-initiative. **A runner that decides review depth = HIGH collision; the composable move is feeding objective signals into the existing ladder choice.**

**4.4 Envelope validation is owned and deliberately layered:** return-envelope schema (step 1) + record.return body validation (step 2) in ladder.mjs — "the single authority on whether a dispatch completed"; return-lint owns lint shape incl. D17; return-gate owns worker-side enforcement; adapter owns record/sha/inventory/nonce; parent writes the .md render (no grant covers it). **Two envelope validators over the same returns/ tree would break the single-authority property; adopt return-envelope.schema.json + ladder.mjs as-is or declare a ratified second envelope type. MEDIUM collision.**

**4.5 Inherited constraints table:** await.lock refuses concurrent awaits (runner shelling await in parallel with orchestrator loop deadlocks by design) · events.cursor single-writer clean-exit advance · record lifecycle monotone create→bind→terminate, no third state · outcome enum frozen 7+null (null ⇒ archive fail-closed; archive := task.outcome≠ok ∨ ∃dispatch outcome≠ok) · phase pill: gate NEVER fired from code · orchestration.md ≤8 added lines total (4 used), exactly one references/cmux-*.md (tested) · kickoff/nudge composition rules (charset allowlist; never copy from read-screen) · config parsing: exactly one execution_mode line · spec ingress: spec-lint mechanical + orchestrator semantic, "run it, don't eyeball it," unchanged by epic.

**4.6 Clean composition points:** cross-PHASE sequencing has NO owner — dispatch.mjs sequences within a dispatch, orchestrator sequences dispatches, workflow sequences waves; a chain runner joining segments by task id sits above dispatch.mjs and beside the orchestrator — an unclaimed slot · worktrees.json already keyed to task_id with attempts[] (natural join key) · adapter contract is multi-consumer-shaped ("no dispatcher change" for new agents) · D18 context.md is exactly the shared-state primitive between segments · status.json + status verb = read-only reconciliation costing no orchestrator turn · #19 turn budgets point at #8's max_turns — land per-phase caps there, don't invent a parallel budget.

## 5. Issue-filing house style
One PR per implementation issue; opening bolded line carries depends-on (issue numbers + spike ids), parallelism + why, commit convention (`feat: <summary — detail>; bump 0.1.NN`; docs use `docs:`), review lane when non-default (justified against qa-gate triggers). Milestones = phases (six, prose descriptions); epic carries `epic` label + rollup, no milestone. Labels flat: epic/enhancement/documentation. Section skeleton: `## Files` (explicit paths, new vs modified, one-line roles) → `## Scope`/per-deliverable subsections → `## Design` (brain-adjacent) → `## Tests` (named file + ·-separated exact assertions) → `## Acceptance` (behavioral, negative-test-bearing; standing line: node --test green with no cmux/model/network). **Invariant-carrying sections: every issue restates in full the invariants it must not violate** (the epic enumerates nine), as bolded inline sentences each with its why; no bare prohibition — every "never X" gets an em-dashed consequence clause. Fallback ladders pre-designed in the issue ("Gates: … On-no: …", terminal rung = STOP AND ESCALATE). Superseding by comment, never body edits. Cross-refs: bare issue numbers + spike ids + "Referenced by:" lines. Repo-side: version bump every commit; memory reconcile as separate chore commit; every new script gets a zero-dep test with CMUX_BIN/CLAUDE_BIN seams.
